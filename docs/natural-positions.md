# 天然细分位置与存档兼容（v0.4.18）

## 原因

旧随机生成只有 GK/CB/W/CM/ST。所有随机 W 都使用 `w_*` 风格，旧推算把 DL/DR/WBL/WBR 扣到 80 以下，ML/MR 则不到 90。保留旧推算用于历史兼容，新增独立天然位置层，避免修改比赛快照。

## 新生成

- `Player.positionProfile` 保存稳定的主位置与熟练度底线，独立于 `detailedPositionsVersion: 1`（后者仍是数据格式标记）。
- `createRandomPlayer` 支持 `detailedPosition` 和 `modernPositions`；新生成默认按具体位置选风格，主位置 90–99、副位置 80–89，无关位置不超过 75。门将/外场不互换。
- 位置、风格使用独立随机流，不额外消费旧名字/身体/年龄等随机流。
- 25 人模板保留原粗位置槽位顺序；只有 7 个 W 球员，无法为 8 个边路细分位置各发一名独立主力。通过相邻副位置覆盖全部 14 个位置，翼卫主位置左右交替生成。
- 新球队先安放球星的真实主位置，再按剩余位置缺口安排随机球员；实际阵型覆盖使用二分匹配验证，不将同一人算作两个同时上场的人。
- 青训把入营目标位置传给生成器；补位青年/11 人制补人按现有位置缺口选具体位置。
- 常见球星使用 `data/natural-star-positions.ts` 的明确主副位置资料；未列出的球星保留风格推断，不声称完全还原现实位置。

## 为什么世界有生成版本

AI 球队会在预览、缓存和赛季流程中按种子重建。直接改变风格会使同一旧球员的属性发生变化。

- 缺少 `WorldState.positionGenerationVersion`：保持旧风格、球星粗位置入槽和身份生成过程，只追加位置底线。
- 值为 1：使用新分配/风格。新世界和正常赛季切换启用；读取旧档不默认启用。
- 现有管理球队、签入球员和重生球员不会因为切换世界版本而重新生成。
- 生成缓存包含此版本，防止同种子的新旧世界混用。

## 迁移边界与规则

`position-profile-migration.ts` 只遍历实时名册、自由/预备球员、挂牌、培养候选人、培养结果、AI 签入、实时转会球队、青训营与候选人，以及对应球员卡。

不遍历活动引擎、已锁定任务、战报回放、PvE 对手快照、旧杯赛快照。替换位置表对象，不就地修改共享的表引用。

- 稳定身份/原始生成槽位决定旧随机球员的新增底线，不能按当前数组下标计算；未知 ID 不冒充生成槽位。
- 青训旧档使用最早的培养记录/入营方案恢复天然位置，不用当前改练方向重新赋予天赋。
- 所有兼容补齐均为 `max(原有效熟练度, 新底线)`。缺失键之前回落到粗位置的有效值也要保留。
- 不改属性、CA/PA、粗位置、名称、身份、合同、体能、精力或财务。
- 各张卡独立补底线，不把另一张卡的训练成果复制到基础或其他卡。可信旧存档中冲突的装备副本取最大值后同步；来自客户端的装备副本则以已恢复的服务端卡为准。
- 不能无条件保证所有已有转会后的球队都覆盖全部位置。旧球队的少数球星替换槽位/缺员可能残留缺口，报告缺口，不强行给不相关球员加位置。

## 联机权威

启动迁移有变化时同时推进 `revision` 和 `lastUserRevision`，拒绝旧页面回写。普通 PUT 恢复服务端 profile 元数据，但保留合法位置训练的增量；恢复权威卡后再补位置。世界生成标记由服务端世界覆盖，不信任客户端标记。自由市场版本推进一次，令客户端刷新池。

## 验证

- `tests/natural-positions.test.ts`：旧随机生成/球星非位置字段的 SHA256 金标准；新角色/风格/副位置；整队与阵型覆盖；缓存隔离。
- `tests/position-profile-migration.test.ts`：所有实时副本、缺失键、卡间隔离、培养完成、快照隔离、幂等与篡改防护。
- `tests/position-profile-online.test.ts`：启动迁移、旧页面冲突、服务器元数据、合法训练增量、生成版本与重启幂等。
- `npm run audit:positions -- data`：只读打开 SQLite 和世界文件，只在内存中试迁移；逐个检查实时球员和球员卡的非位置字段/熟练度，并校验冻结数据与第二次迁移。不会写生产数据。

上线前备份完整 data/，确认无直播及运行中的比赛计算，再进行构建/重启；已就绪的锁阵任务保留，不重算。
