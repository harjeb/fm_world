## 0. 当前路径、范围与共同契约

### 0.1 本轮核查得到的事实

| 当前代码 | 实际行为与限制 |
| --- | --- |
| `src/game/pes/sim.ts:step → updateShape` | 每个物理步重置 `marks/presser/cover`，但**没有重置 `presser2`**；球冻结、本方持球或无人可选时可能保留旧值。 |
| `sim.ts:updateShape → marks` | `used` 只包含 `presser/cover`，没排除 `presser2`。第二上抢者可以被分配一个盯人槽位；`decideOffBall` 因上抢判断优先，实际不执行盯人，却占用了盯人分配名额。 |
| `sim.ts:assignPressers` | 第二人现在和第一人一样追球，不等于现实中的封传球线；每帧按全队熟练度抽一次低 / 高反向，可能抖动。现有 `emergency` 在 `allowed` 为假时不会运行。 |
| `sim.ts:decideOffBall / passValue / execPass` | 已有 `spaceBehindLine` 和前插，但跑动目标通常被限在越位参考线之前；评分按接球人当前位置，执行时又加速度提前量，两者并非同一个目标。 |
| `sim.ts:execPass → PesSettlement.pass → resolvePossession` | 带结算的普通传球在**出脚时预先抽定** `ok/icpt/miss/out`。`ok` 或 `icpt` 在最多约 3 模拟秒内保护指定接球 / 拦截人；模型不会让任意防守者在飞行中重新裁决一次。`onEvent` 还会在出脚事件时就累计完成传球。 |
| `sim.ts:formationTarget / decideOffBall` | 基础阵形只是部分球员的目标；`press/cover/mark` 等分支会覆盖它。`move` 中有动态分离力，但**没有目标之间硬性最小间距求解器**。 |
| `sim.ts:serialize / game.ts / engine.ts` | 物理快照仍是 `version:1`，比赛 `rulesVersion=4`；P1 使用新指令但还没有完整可路由的独立版本。`lastPoss`、实验参数及部分结算状态缺少恢复语义。不能只靠改版本标签承诺旧回放兼容。 |

### 0.2 共同边界

1. **风格只是模板。**三项只读取球队已展开的指令、实际球员、位置、体能与对手，不做 `if styleId`。
   以下所说「高压」「防反」「低位」是指令组合的例子，不是隐藏增益。
2. **旧 v4 冻结。**上线前必须保留可执行的 v4 实现和版本路由；已有 P1 原型也须单独冻结 / 可重现。
   在新规则中，**没有 `instructions` 的球队**保留旧五滑杆的分支、数值和 RNG 调用；只要对手改变行为，
   两队比赛的轨迹自然可能变化，不能保证混合对阵比分不变。
3. **实验隔离。**可以先在离线测试中显式启用受控实验实现；未完成规则路由、快照和兼容测试前，不接线上、
   UI 或后台 AI。每次运行记录源码 / 配置 / 夹具哈希、实际能力开关、种子及代码 dirty 状态，绝不依赖默认缓存猜版本。
4. 所有阈值默认 11 人制 `L=105, W=68, K=1, D=900`。**战术距离**按给定 `K` 缩放，物理接触半径和
   物理速度用米 / 米每秒；调度时间使用模拟秒。7 人制单独测试，不默认宣称已调平。
5. 当轮结果分为「固定局面正确」「比赛行为有效 / 不确定」「赛果探索」「恢复兼容」；前者通过不等于后者通过。
   埋点只读已有候选和决策，**不得调用会抽随机数或标记技能的评分 / 结算函数**。

## A. 第二上抢者任务冲突

### A1. 先修任务不变量，不顺手改压迫强度

目标：只修复过期 / 重复任务。其他选人半径、人数、原上抢目标公式、排序和随机调用先保持当前 P1 语义；
但立即刷新过期 `target` 会改变移动时机，因此也可能影响整场结果。为便于归因，将 A1 拆成**A1a 任务表修复**
和 **A1b 在 A1a 上立即刷新失效目标**，保留两个独立实验开关，最终交付同时满足两者。两者均在新规则 /
隔离实验实现，不能回写旧回放。

**在每个物理步的 `updateShape` 开头、任何提前返回之前，对带新指令的队伍：**

```text
marks.fill(-1); presser = -1; presser2 = -1; cover = -1
if ball.frozen or 本队持球 or 没有可用外场球员: 结束该队分配
按原 P1 规则分配 presser / presser2 / cover
used = 非负且当前在场的 {presser, presser2, cover}
在其余外场球员中按既有威胁顺序分配 marks；分配后立即加入 used
```

- 一名球员最多一个**主动防守任务**；`presser/presser2/cover` 两两不同，也不能出现在 `marks` 的分配者中。
  `marks[slot]` 的值是**对手 pid**，不是本方标记人的 pid；检查时应按 `team.players` 的 `slot` 找分配者。
- 门将、离场、眩晕者不可作为外场任务分配者；没有合格人时留 `-1`，不能复用旧 pid。
  允许对手持球者及门将是否成为目标继续遵循 A1 原有逻辑，**不在这一补丁扩展 P2 逼抢门将**。
- `updateShape` 发生在队员决策之前；球员决策期间可能出脚、失球或死球。消费任务前若球已冻结、
  目标已离场 / 不再有效或本队已持球，跳过该旧任务；下一物理步重建。换人 / 红牌立即清除引用离场 pid 的任务，
  不允许旧球员被追抢或盯人；不改历史事件。
- 球在传球飞行或无主时，A1 保持原有 `possessionTeam/decideLoose` 行为；**不要把 `presser2` 清零误称
  已实现精确的无主球调度**。A2 才限制目标类型。持球 / 死球 / 空球的模式切换要分别测。
- 不通过 `Set` 的 `-1` 占位算留人；`outfield` 的实际在场数与眩晕条件需分别报告。测试必须同时检查
  任务表**和该球员实际执行的 `mode/target`**，避免表面没有重叠但仍追旧目标。

**处理决策延迟：**清空任务表本身不改 `p.target`，而当前球员可能要等到下一次 `decideT≤0` 才更新目标。
A1 在重分配前保存每名相关球员的任务 key（类型和盯人目标 pid），分配完成后与新 key 比较；只有 key 改变者
需要刷新运动目标。抽出一个**不抽随机数、不改 `decideT`**的任务目标函数，按现有 `press/cover/mark` 公式
刷新有效新任务；没有防守任务时，按当前球权 / 死球选择原有阵形、争球或定位球目标。持球人、有效拦截接球人和
死球主罚人按原有更高优先级处理，不覆盖其目标。新增用于比较的 `lastAppliedTask` 作为新规则纯数据随快照保存；
老版本不新增字段。

`step()` 中其他球员可在同一帧出脚或犯规：每次实际消费任务前校验当前球权 / 阶段与目标；在 `updateBall` 后、
`move` 前再统一验证，若此前有效任务已失效则用同一纯函数刷新。球权变化、死球、离场等事件应立即清理无效
任务引用；发生在本帧移动之后时，目标可在下次移动前刷新，但快照必须保存待刷新状态。禁止调用 `decide()`
后再调用 `reactionTime()` 来强制刷新，因为那会额外消费 RNG。以上改变只进入新规则的带新指令一方。

**A1 固定局面验收**：两名上抢者 + 三个潜在盯人对象时第二人不能抢占盯人槽；从防守→持球、死球、
传球飞行→无主、换人、第二人红牌、全部眩晕逐帧断言不存在残留；有 / 无 `instructions` 两队分别测试。
同输入同 seed 和无埋点 / 有埋点事件、RNG 相同；旧 v4 golden 与冻结 P1 对照按其原版本执行。

### A2. 再让第二人承担不同职责（单独实验能力）

**设计意图：**第一人接近持球人，第二人优先封住最近危险接应线；这是任务与位置，而非自动封锁传球或提高抢断概率。
A2 相对 A1 是额外行为变化，须保留 A1 开关作为直接对照，不把改善 / 恶化全部归因于 A1 修复。

1. **有效目标：**只对活球、`ball.owner` 是当前在场对手外场球员时分配常规上抢；P2 `pressKeeper` 未开放时门将
   不在常规目标内。传球飞行 / 无主球遵循原拦截和争抢，不把预测落点冒充「持球者」。
2. **合格人员：**在场外场、未眩晕、体力 `≥0.20`；满熟练时常规 / 反抢按已有 `engagement` 和半径
   `12 / 15 / 18` **物理米**及人数上限 `1 / 1 / 2`，反抢窗口半径可 `+3m`、上限 `18m`；
   低熟练沿当前 P1 的插值和档位，见第 6 条。以实际持球者到队员的距离升序、同距 `pid` 升序；
   不把二次 `maxSpeed` 加成写入排序。
3. **人数与留人：**设在场外场数 `N`，可分配主动上抢 `cap=min(指令上限, max(0,N−2))`。
   两名留人只保证不承担**主动上抢**，仍可协防 / 盯人，并不保证一定在球后。`N≤2` 时 `cap=0`，
   不为了紧急例外绕过人数限制。
4. **紧急例外：**若常规 / 反抢未选到人且 `cap≥1`，距实际持球者 `≤3m` 的未眩晕在场外场球员最多选 1 人，
   即使回撤或不在逼抢线内也允许；体力低于 0.20 允许作为紧急候选，先按距离、再 `pid`。
   选中者计入 `cap`，紧急例外首轮在全场适用；不是无限追球，也不改变近身 `tryTackles`。
5. **二人分工：**`cap≥2` 且有两个合格候选时，第一人按上述顺序追球；第二人从剩余候选中按距持球人、`pid` 升序选择。
   在持球人的在场外场队友中，找 `0<距离持球者≤12K` 的最近接应对象，同距按对象 `pid`；
   第二人从持球人到该接应对象的线段中点，向本方球门方向偏 `1.0K` 作为封线目标，再裁到场内 `0.6m`。
   若没有接应对象，第二人从持球人朝本方球门方向 `3K` 处协防，不再追到和第一人同一点。
   目标只改变跑位：对方仍可传球，实际线路、压力和结算决定结果。
6. **更新时序：**A2 的主动任务每约 `0.25` 模拟秒重评一次，以新规则可序列化的物理步计数为准：
   `nextEvalStep=currentStep+ceil(0.25/DT)`，到步重评，量化误差小于一个 `DT`。死球、球权变化、主目标或任务人失效、
   新出现 / 消失的紧急 `≤3m` 条件在**下一物理步**立即使其失效并重评。期间仍每步验证目标在场与合法，
   防止 0.25 秒追着已离场 / 已出球的人。`cover/marks` 只在同一有效任务表上分配，执行优先级见 C2。
   A1 / A2 第一轮主比较先固定双方 `familiarity=1`；当前 P1 低熟练时每帧会为防线反向抽签，A2 不借机
   修改这条既有 `lineBias` 路径。低熟练任务采用该次重评时当前 P1 的档位 / 人数结果并保持到下次重评，
   其抽签频率及效果应另报，不能混入 A1 与 A2 的满熟练差异。任务、重评截止时刻和稳定的 `pid` 平分规则
   进新规则快照；A2 不新增每帧随机抽签。

**条件算例：**11 人制、10 名外场、指令高压，距离持球人分别为 `2/5/8m` 的三名合格队员，
存在 `8m` 处的接应对象，则第一名追球、第二名向对应线路中点的球门侧移动，第三名可按原分配协防 / 盯人；
不是三人一起追。只剩两名外场时 `cap=0`。若回撤且只有一人距球 `2.5m`，该人可成为唯一紧急上抢者。

**A2 验收：**
- 精确断言 `0.25` 秒与下一物理步失效、边界 `3m/12m/18m/0.20`、并列 `pid`、双方换边和小于 3 名外场。
- 比较 A1 vs A2：记录合格压迫暴露秒、`0/1/2` 人任务秒数、实际靠近距离、被切断的候选线路、
  已分配但未执行秒数、任务切换次数；另报受压出球、夺回、跑动与体能。不能以高位夺回变化证明抢断能力提高。
- 低熟练度阶段只作为 A2 现有模型的对照，不引入新的 `F_A−F_B` 概率；连续熟练度模型属于独立后续版本。

## B. 可达身后空当与越位

### B1. 数据与指令契约

P2 `advanced.possession.receiving = feet | mixed | space`。本项只在**有新指令且显式选择 `space` 的球队**
启用新候选，不改变无指令球队和 `mixed` 既有基线；`feet` 是另一项独立能力，按高级指令文档实现和验收，
不在 B 首补丁中借机改变。

候选应以纯数据传递：

```ts
type SpacePassCandidate = {
  receiverPid: number
  target: Vec2              // 本次决策的计划目标，不是球员当前位置
  flightTime: number        // 确定性规划估计，模拟秒
  kind: 'through'           // 仅选择该候选后用于一次真实结算
  score: number             // 使用既有评分 + 受限 P2 偏好
}
```

候选为**当前一次 `decideOnBall` 的临时数据**；选中后同一对象 / 目标交给执行，不能再次按最新速度生成另一个目标。
真正飞行中的球权威状态仍在 `ball/meta`：B 新规则的身后传球**必须**增加 `plannedTarget` 和 `flightKind`
并序列化，以支持恢复与评估，而不是只存在局部变量。`PesEvent.meta` 目前只支持标量，出脚事件如需记录目标，
使用 `plannedX/plannedY` 数值字段，不直接塞嵌套对象。接球人 `runTarget/runUntil` 已进 `PesPlayer` 快照；
新增状态要按换人 / 红牌明确处理，见 B4。字段缺失的旧快照只由旧规则读取。

### B2. 合法、可达的计划落点（不保证一定成功）

首个 B 版本只做**开放比赛的地面普通传球**，不改开球、角球、任意球、传中及球门球；高球身后、
门将特定出球和跑向空当的复杂路线后续独立设计。开 / 关越位规则都可生成空当候选，但判罚走 B4。

**开放比赛不能只检查 `phase==='play'`：**`updateRestart` 在发球人持球后就清空 `restart` 并切入 play，
所以本版须先新增新规则的 `restartContext / openState`，并进入快照。每次死球设 `restartPending`；发球人
首次主动传 / 传中 / 解围 / 射门后切到 `unconfirmed`，该第一脚始终不属于开放比赛。之后某队球员取得实际
控制并累计 `0.20` 模拟秒，或取得控制后主动出脚，则确认 `open`；触发确认的动作仍不计入开放比赛，
从其后动作开始允许 B。若发球人首次主动出脚前被对手实际控制，取消其待首脚状态并转为 `unconfirmed`，
从对手的实际控制开始累计；未确认又死球、中场或终场时重置，无主球暂停累计，对手实际取得控制时重建候选。
此状态仅供**识别开放比赛**，不替代现有转换窗口；角球 / 点球的直接出脚路径也要显式完成首次动作状态。
`restartContext` 包含类型、发球方、发球人 pid、是否已首脚、候选球队与累计控制时间；换人继承有效发球人，
取消、失效和恢复的顺序必须固定。若这一前置状态未实现，B 的开放比赛范围无法可靠实现，不得开放。

一次持球决策中，对每个在场、非门将、非持球人、未眩晕的队友，按固定 `pid` 顺序最多生成**一个**额外空当候选：

1. 使用进攻方向 `lx=x×dir`、`ly=y×dir`。记 `receiverLx` 为**当前接球人位置**，`ballLx` 和
   `secondLastLx` 取现有规则，含门将实际位置；`reference=max(0, ballLx, secondLastLx)`。
   该值用于描述当前防线，不替代已有 `isOffside` 的对方半场与容差判断。
2. 必须已有有效 `runTarget` 且 `mode=run`、`runUntil>time`，并向进攻方向有正向速度 `vForward≥0.5m/s`。
   尚未起跑、无人可用或接球人不在场，**不新造**跑动或传球。B3 再让可用跑动有机会跨线。
3. 从持球人到接球人当前位置的距离 `d` 取 `leadTime=clamp(d/15, 0.3, 1.2)`（模拟秒），
   目标 `T = receiver.pos + receiver.vel × leadTime`；将位移总长度限为 `6K`，再将 `T` 限在球场线内 `1m`。
   裁剪后若 `(T.x−receiver.pos.x)×dir < 1K`、`T.x×dir ≤ reference+0.5K`、
   `dist(passer,T)<3m` 或 `>62K`，则丢弃该空当候选，保留常规候选。
   前 `0.5K` 是待标定安全余量，不是越位容差；这种候选只代表目标在参考线更前方。
4. **可达性检查只是预测，不是瞬移或成功承诺：**令 `dT=dist(passer,T)`、`laneT` 为出脚点到 T 的
   现有 `laneClearance`。只在 `dT≤32K` 且不满足 `(laneT<1.6m && dT>17K)` 时保留地面候选，
   这与现有 `loft` 判定一致但对新目标 T 检查。其他情况回退普通候选。
   对保留者，用 `speed=clamp(8+dT×0.45,9,27)`、朝 T 的方向、出脚点沿方向前移 `0.55m`、
   `z=0.05, vz=0, spin=0`，按 `updateBall` 的每步 `DT` 重力 / 空中阻力 / 地面阻力公式规划；
   找首次距 `T≤1m` 的 `tBall≤2.5s`，未到达则丢弃。此规划不修改比赛状态、不抽 RNG；高度降到地面
   前可能经过多个空中物理步，不能把它简化成一帧后立即地面滚动。
5. 令 `tau=max(0,tBall−clamp(receiver.decideT,0,0.45))`；接球方向单位向量 `e=norm(T−receiver.pos)`，
   `v0=clamp(dot(receiver.vel,e),0, vmax)`，`vmax=0.88×maxSpeed(receiver)`，`a=maxAccel(receiver)`，
   `tCap=(vmax−v0)/a`。若 `tau≤tCap`，`R=v0×tau+0.5×a×tau²`；否则
   `R=v0×tCap+0.5×a×tCap²+vmax×(tau−tCap)`。当 `dist(receiver.pos,T) > R+1m` 时丢弃候选。
   这忽略对手阻挡、转身、分离力与实际减速，且当前物理分轴限加速度，因此只是**启发式近似，并非严格数学上限**；
   仍需在固定场景和比赛里记录预测 / 实际偏差。
6. 普通候选既有单刀保护、距离、路线、危险回传和越位软扣分继续生效；`space` 不复活已拒绝的候选。
   在本规则将与目标相关的距离、向前位移、线路净空、开放度都按 `T` 计算，其他依赖球员真实站位的
   判断（技能、越位、位置 / 射门候选）继续使用实际球员。对合格空当候选，先算接球人当前 P1 熟练度
   `qReceiver=0.35+0.65×clamp(receiver.familiarity ?? 1,0,1)`，给 `+0.04×qReceiver` 的高级倾向分，
   并入既有 P2 传球预算 `±0.06`；与 P1 预算合计最多 `±0.16`，不再将该 P2 分乘第二次熟练度，
   不另加风格分。

**候选排序与 RNG：**常规和空当候选的确定性基础评分分别算一次；同一接球人两个候选共用该球员原有的一个
评分噪声样本，不能每多一个候选就多消耗一份主 RNG。候选并列按 `pid`、再按常规优先排序。只选中空当候选时
调用一次 `contact.pass`；候选生成、可达预测和埋点不得调用 `contact.pass / beatsOffside` 或产生技能计数。

**数值例：**向 +x 进攻，球员在 `x=5`，接球人在 `x=18`、速度 `3m/s`，防线参考 `x=20`，
`leadTime=13/15≈0.867s`，计划落点 `x=20.6`。落点越过参考线，接球人出脚时仍位于线前；
满足其余净空、地面球和 ETA 条件时才进入候选。不能据此推断传球必然完成。

### B3. 跑动目标与释放时机

当前 `runTarget` 总被设在线前，若只在 B2 依赖已有速度，身后机会可能不足。新规则对选择 `space` 的一方：

- 在现有前插申请条件、人数上限和 `runnerProb` 下，先选与 B2 同口径的前场球员；沿进攻方向设跑动目标为
  `min(reference+4K×qReceiver, HL−6K)`，其中 `qReceiver` 为 B2 中接球人个人熟练度系数，横向沿用现有
  受边界约束的通道。**目标可以在线后**，但移动仍受加速度 / 速度限制；该位置偏移只缩放一次。
- 未出脚时不保证一直在合法位置：球员、球和对手都可能运动；`passValue` 按当前接球人位置维持越位软扣分，
  最终以出脚实际位置判罚。`onGain=counter` 仍使用既有 `runnerProb` / 转换偏好；B 不再给反击概率重复加成。
- 选中空当传球并出脚后，接球者执行既有的飞行球 `interceptPoint` 接球任务，原任务合法时不被一般阵形强制
  限回越位线前；出脚后越过防线并不自动越位。被对手实际控球、死球、中场、超时或本人离场时清除该跑动状态。
- 新跑动与 P2 `supportRuns` 等未来能力使用同一活动 `runTarget` 人数上限；B 先不增人数、不无条件造第三前插者。
  无真实跑动 / 可达目标时正常回退，不能让 `space` 强迫低位阵地战不断直塞。

### B4. 出脚、结算、越位和恢复

- `passValue` 与 `contact.pass` 对**同一个计划落点 T**计算路线和距离；出脚时 `passKind='through'`，
  沿用 `SettlementKernel.passModel` 的类型、实际球员属性 / 压力和一次随机裁决，不额外叠加成功率。
  传球路线 / 接球点的评估只能按当前局面近似；后卫跑动不会在 B 版本里重新决定已经抽出的裁决。
- 「同一个计划目标」不等于所有结果球都会精确落到 T：`stagePassAim` 对 `icpt/miss/out` 会生成拦截 / 失误
  演出点，真实发射还含原有角度误差、spin 和阻力。分别记录 `plannedTarget` 与 `actualAim/result`；
  不把偏离目标的失败错记为成功。`ok` 的真实接球仍受当前最多约 3 秒的结果保护。
- **重要限制：**当前 `PesSettlement.pass` 把接球者视为目标点来调用 `passOdds(to,to)`，不会另扣接球人追不到球的
  结算惩罚；B2 的 ETA 是候选筛选，不是完整接球模型。若 `ok` 但接球者因实际轨迹 / 干扰未追上，
  记录 `plannedOkNoClaim` 和到球时间，不能报告为实际成功。要让途中真实回追 / 拦截推翻 `ok`，必须另设计
  **延迟结算、事件与助攻 / 传球完成统计原子提交**，不在 B 里暗改 `resolvePossession` 的保护窗口。
- 出脚前记录 `offsideCandidate = rules.offside && isOffside(team, receiver)`，按既有时序处理
  `beatsOffside` 特性，只在原本应执行特性时调用一次；不在候选阶段预抽。最终只有规则开启、特性未消除、
  并且**该目标接球人实际参与接球**时按现有路径吹罚；规则关闭不吹。自己半场、球比接球人靠前、
  倒数第二名对手等边界沿用既有规则，包括 `0.3` 容差，不能用目标是否在线后代替。当前无 `contact` 的
  原生 `execPass` 分支未在写 `offside` 时检查开关；B 的新规则若支持原生分支，须也显式处理开关并单独测试，
  不回写旧 v4。
- 测无门将 / 门将出击、双方半场换边、球比接球人更靠前、少于两名对手、特性成功 / 失败及开关。
  现有传中候选对越位开关有独立限制，B 不改它，也不称本次覆盖所有定位球越位例外。
- 中途快照必须保存实际选中的 `ball.meta`、已抽裁决 / 越位结果、跑动目标、RNG 和规则 / 参数；
  决策尚未选中时不持久化临时候选。若换人发生在飞行中，沿用现有换人将 `intended/icpt` 指向替补、
  历史 `from` 不变的兼容语义；新增计划字段的继承 / 清理需明确且测试。红牌 / 死球取消及出球瞬间保存均要测试。

### B5. B 的测试和输出

固定局面以控制随机抽样 / 脚本化结算检验：

1. 接球人在线前，落点在线后可生成；出脚后跑过线可合法接球；出脚时人已越位则按现有软评分和规则处理。
2. 同样目标，慢前锋 / 无法在 `tBall` 前接近、球不能到、目标出界、路线触发高球或无前插，均回退；
   快速 / 正确方向跑动可生成。固定其他输入比较 `familiarity=0/0.4/1` 时，跑动目标偏移与 P2 倾向
   分别只随 `qReceiver` 缩放一次。**不必因为能力 / 熟练度高就必然选中或成功。**
3. 断言评分、调用 `contact.pass` 的 `aim`、序列化的计划目标一致；不同 `ok/icpt/miss/out` 的演出终点可不同。
   每个普通出脚只调用一次真实结算，非选中候选零次；打开埋点不得改变 RNG / 事件 / 比分。
4. 所有重开球类型下，第一脚和确认控球的动作不产生空当候选；确认后下一次开放比赛动作可用。涵盖同队一脚
   连续出球、对手抢先控制、待确认时死球，以及 `restart` 清空后尚未首脚的保存恢复。
5. 接球、越位、红牌 / 换人、死球、半场、传球飞行保存恢复；完成传球的**预结算统计与实际接球**分别报告，
   不把两者强行合并。

开放比赛埋点需存每个可行机会的分子 / 分母：额外空当候选数、被选择数、真实出脚数、越位候选 / 判罚数、
`plannedOkNoClaim`、实际到位接球、接球耗时、下次射门和失球；分别按对手实际防线高度和对手是否留下保护分层。
新旧规则都不按高防线直接加 xG。正式平衡前至少测严格镜像基线、统一属性 `--squad 67 --exact-mirror`，
以及待实现的双方同画像的速度 / 技术组合。

## C. 低位无球紧凑：中路覆盖与边路代价

### C1. 指令含义

P2 `advanced.defense.width = narrow | normal | wide` 与 `possession.width`、`defense.line`、
`engagement/intensity` 相互独立。11 人制试验缩放 `s=0.85 / 1.00 / 1.15`，先测实际形成的宽度和机会，
不能宣称低位自动降低射门成功率。`line=low` 只控制纵深，不隐式开启 `narrow`；链式 / 摆大巴需通过新的
风格 revision **显式**复制窄防守，而不是用风格 ID。

### C2. 一次变换覆盖实际会用的队形 / 盯人目标

**触发：**仅当该队有新指令且对手拥有稳定球权（沿本规则定义的对手实际持球或有效同队传球飞行）时，
在 `decideOffBall` 防守阶段应用；死球、己方持球、无稳定球权的争球及门将不应用。
本项不扩展转换确认规则；传球飞行 / 暂定球权语义沿冻结规则统一确定并在测试中固定。

**先确定任务，再处理目标；不要每个球员独立计算一个不同中心：**

1. 以当前步**球员位置快照**和有效任务表，为所有在场未眩晕的防守外场人员计算其原始目标 `raw[p]`：
   `mark` 用原盯人目标，未分配任务的 `idle` 用原 `formationTarget`。`press/presser2/cover`、被裁决的主动拦截、
   无主球抢点、门将和定位球专项目标不参加缩放，也不参加中心计算。无有效目标者跳过。
2. `eligible` 至少两人时，先将每个原目标的横坐标裁到 `[-HW+2.5, HW−2.5]`，记为 `raw0Y`，
   再算 `cy = mean(raw0Y)`；否则不改。沿用当前 P1 的全队外场平均 `F=teamFamiliarity(team)`，
   `q=0.35+0.65×clamp(F,0,1)`，计算 `sEff=1+(s−1)×q`，按 `pid` 升序计算
   `proposedY = cy + (raw0Y−cy) × sEff`。熟练度只在这里缩放一次；`F=1` 时使用完整 0.85 / 1.15，
   `F=0` 时分别为 0.9475 / 1.0525，而不是反向或完全归中。
   这些都使用变换前的 **world y**，只算一次；不在 `formationTarget` 和 `mark` 上各缩放一次。
   `raw.x` 原样保留，避免把防守宽度偷换成防线高低。
3. 窄 / 宽档首轮把每人相对 `raw0Y` 的横移幅度限为 `±3K`。对于 `mark`，再限制缩放导致的该球员目标到
   被盯对象横向距离最多比 `raw0Y` 增加 `1.5K`：`|newY−opponent.y| ≤ |raw0Y−opponent.y|+1.5K`。
   将上述区间与场内 `[-HW+2.5, HW−2.5]` 求交，把 `proposedY` 裁入交集；`raw0Y` 总在交集中，
   所以退化时回退它。有限数检查失败时回退原路径并记录。只约束离人更远的额外偏移，不强行贴住对手。
4. **间距不作虚假硬保证：**首轮保留 `move` 既有分离力，不新增强制位置投影；记录目标 / 实际距离，
   测试越界与扎堆。若需要硬最小间距，必须另定公平、可终止的求解器及相同中心 / 排序语义，不能把现有
   动态分离力写成已经满足所有目标间距约束。
5. `normal` 必须直接走本规则的原始目标分支（不做均值、缩放或额外随机抽签），保证 schema 2 中性适配与
   schema 3 `normal` 在该共同规则下事件 / RNG 逐位一致。窄 / 宽下目标变化不保证球员瞬时到位：仍由
   `decideT`、`move`、加速度和分离力决定实际轨迹。

**任务优先级（高到低）：**球员不能行动 / 死球专项 → 既有实际拦截 / 无主争球 → 有效主动上抢 → 协防 →
盯人 → 防守阵形目标。C 只处理后两项，A 分配的两名上抢者不会因 C 被拖回队形；这里描述的是本次规划的
明确优先级，当前实现的飞行球预结算拦截仍是特殊路径，必须按版本验证。

**固定算例：**满熟练、某防守帧只有两名符合条件的阵形球员，原目标 `y=−20m / +20m`，中心 `0`；`narrow` 后为
`−17m / +17m`，每人横移 `3m`，`wide` 后为 `−23m / +23m`。若还存在一个负责主动上抢的人，
其目标不参与中心和缩放。实际球员并不会立刻移动 3m；盯人限制、边界或人数不足时结果可能更小。

### C3. 同步、快照与回退

- 同一物理步中每名球员可能不同时间到 `decideT`；必须从**该物理步移动前的同一份位置快照**计算 raw 与中心，
  之后由到期球员读取目标，不能先更新一名球员的目标再拿它去算其他人的中心。若前一个人的决策让球权 / 阶段
  改变，后续读取前重新验证触发条件；不能把旧防守目标用在本方持球上。
- 若实现为每步从当前快照纯函数重算且没有跨步缓存，则无需把仅供当步计算的数组写入快照；若缓存跨越
  `step()`，缓存内容、基于哪一帧、失效条件必须保存并恢复，否则不能宣称中途读档相同。
- 参数先固定为规则 / 能力版本的一部分，或作为快照的有限数值明确保存；不能像当前 `tacticsParams` 一样
  仅由开赛参数覆盖、恢复时静默回到默认。对新 / 旧 schema 的 `normal` 和混合对阵均须固定。
- C 首版继续使用现有每队输入一个 `familiarity`、按在场外场 `PesPlayer.familiarity` 平均的模式；缺失按 1。
  当前替补没有独立传入熟练度，替补缺字段也会按 1 处理，这是需要报告的已知限制；不要宣称已经有四族
  个人熟练度。未来四族模型及替补输入上线时另发布版本，不能静默改变本实验口径。
- 后卫卡住边线、`eligible<2`、人数不足、盯人目标已离场、多个队员目标重叠均有确定性回退。
  `showWide`、拼抢尺度和独立纵向紧凑度不在本项暗中开启。

### C4. C 的验证

| 固定局面 | 必须断言 |
| --- | --- |
| 满熟练、两人 `y=−20/+20`，无其他目标 | `narrow=−17/+17`、`normal` 精确保留、`wide=−23/+23`；交换阵营、半场、左右镜像对称 |
| 同时有上抢、协防和盯人 | 上抢 / 协防不被缩放；盯人满足 `1.5K` 额外距离约束，且同一球员只变换一次 |
| 强侧边线 / 禁区 / 自定义位置 | 场内有限、横移不超 `3K`，不篡改 `x` 或外场上抢任务 |
| 红牌 / 换人 / 无稳定球权 | 无效 pid 不参与中心，少于两人回退；死球 / 己方球权 / 争球走相应高优先级 |
| 熟练度 0 / 0.4 / 1 | 固定目标逐项检查 `sEff` 连续接近正常、不得反向；换人后按在场均值重算，缺失按 1 |
| `normal` 两种 schema | 事件、RNG、物理快照逐位相同；无旧无指令球队新逻辑 |
| 每步中途改变球权 | 后续决策重新校验，恢复后 target / 任务 / RNG 不分叉 |

整场只改防守宽度，分别对 `line=low/mid/high` 与不同进攻方向做配对对照；记录无球外场 `P90−P10`、
同一帧角色目标 / 实际宽度、缩放覆盖率、中路传球净空、边路接球 / 传中、禁区射门和对手 xG。
**窄低位可能改善中路，也可能增加边路损失；不预设总 xG 一定降低。**

## D. 分阶段实验、护栏和交付

### D1. 三个变更分别对照

| 阶段 | 试验 vs 对照 | 基础输出 | 首次复测结果（探索） |
| --- | --- | --- | --- |
| A1 | 原冻结 P1 vs A1a（任务表）；A1b（目标立即刷新）vs A1a | 任务冲突 / 过期数、盯人覆盖、完成任务时长；跑动、体力及 xGD 作为探索 | **已达成**：5 组对位、所有采样帧冲突数为 0；355 项测试全过 |
| A2 | A1 + 二人分工 vs A1 | 单人 / 双人任务暴露、封线距离、失球 / 夺回及体力 | 尚未实现 |
| B | A2 基线下 `space` vs `mixed` | 合格候选、选择、可达性误差、真实接球、越位 / 失球 | **已触发但不足**：1.3–2.9% 传球为空当球；快反 vs 高压 −2.70 → −2.91（反向） |
| C | 固定 A2 / B 基线，窄 / 宽分别 vs 正常 | 实际无球宽度、盯人 / 弱侧覆盖、中路 / 边路机会 | **已触发但幅度小**：链式仅 −0.5～−0.9 m，且对控球反而多丢 0.48 |

每个阶段先跑固定场景单元测试，再用 **30 个训练种子块**做方向和耗时冒烟；不把 30 块当正式结果。
设计样本：相同人员和对手，试验 / 对照各做主、客一场，四场为一个种子块；先每场算指标、再主客平均，
与对照做差，固定种子对完整块 bootstrap。计数 / 暴露速率在每个重采样块中汇总计数和暴露后再计算；
分母为 0 或数据缺失明确记缺失，不记作 0。至少报告 95% 区间、每组分母和完整块数。

**建议冻结的正式行为检验（同一画像的 3 项族）：**

1. B「身后计划出球选择率」：分母为开放比赛中，球员有非强制出球决策且按 B2 纯规划器存在合格空当目标的次数；
   对 `space` 和 `mixed` **都以只读方式运行同一个规划器**判分母，只认当时真实存在的 `runTarget/mode`，
   不得虚构跑动、抽 RNG 或影响选择。分子为该机会集中最终实际出脚的普通传球，其出脚前计划目标
   `lx>reference+0.5K` 的次数；`mixed` 用其原提前量作为计划目标，所以不是天然为 0。
   由于两组的真实跑动机会本身可能受指令改变，另报全部非强制决策的数量及合格机会占比，
   不把条件选择率直接解释成无条件机制因果。`space−mixed` 预期增加，最小有意义差异先设 **1 pp**。
2. C 窄 / 正常：对手稳定控球期间，每模拟秒采集在场外场 `y` 的 `P90−P10`，每场先求均值；少于 8 名外场
   或无采样记缺失。预期 `normal−narrow > 0.5K` 米。
3. C 宽 / 正常：同样口径，预期 `wide−normal > 0.5K` 米。

A1/A2 的无重叠和目标时序是**固定局面硬不变量**；A2 的整场职责分离率、夺回和结果先作为探索，避免把按设计
必然不同的任务标签当作真实防守收益。上述 B / C 三项先针对严格镜像基线的 `mirror` 场景预注册，统一属性及
其他画像作为事先列出的独立分层复验，不把不同画像硬平均后掩盖反例。

冻结实现后每项用 `10001–10200` 的 **200 个完整种子块**、20,000 次同步配对 bootstrap；对 3 项分别方向正向化，
用双侧 **98.333%** Bonferroni 区间（分位数约 0.833% / 99.167%），下界严格超过各自门槛才记行为有效；
包含门槛为不确定。任一比较完整块不足 190 个、B 任一组的合格机会少于 200 次、C 任一组的有效一秒采样少于
1,200 次，均标记不确定。另报告未校正 95% 区间、失败和分母；实际不同设计和阈值要在看验收数据前冻结。

额外 2×2 条件实验：进攻方 `space/mixed` × 对手 `line=high/low`，以及对手 `width=narrow/normal` ×
进攻 `focus=middle/wing`；每组条件四格、每格同种子主客各一场，**8 场组成一个种子块**（基线可复用）。
先比较行为和机会，再探索 xGD 的差中之差。
不能从单组 `p<0.05` 而另一组 `p≥0.05` 推断它们互相不同；不能预先要求某风格净胜为正。

### D2. 回归、性能和发布门槛

- **确定性：**同输入同 seed 两次逐位；埋点开 / 关事件、比分、最终 RNG 一致；测试球权转换、上抢任务生效期间、
  空当出脚 / 飞行及宽度缩放中途 JSON 保存恢复。外加换人、红牌、死球、半场和技能触发前后恢复。
- **兼容：**冻结 v4 golden 与 P1 行为；有 / 无新指令及两个不同 schema 混合对阵；旧队自己的分支不能被新功能
  偷换，跨版本老比赛按旧规则真实实现恢复。新规则转换状态、调度时钟、球路元数据、参数和 `secondWindUsed`
  要么全部保存，要么标记不支持中途恢复，不能静默丢弃。
- **赛果护栏：**记录 `xGF/xGA/xGD`、比分、控球、传球完成 / 实际接球、射门与体力；总进球 / 总 xG 按
  原设计 `max(0.35球,15%) / max(0.30 xG,15%)` 标记调查，不因单一指标达到某值就宣布通过。
- **资源：**分别比较开关前后的 900 秒全场耗时、内存、每次决策候选数量；先记录机器 / Node / 样本及基线分布，
  在验收种子前设置允许退化上限。可达性逐步模拟仅对合格 `space` 候选执行并设每决策候选上限；不能为了埋点
  重跑结算或产生第二次随机抽样。
- **上线状态：**只有实现 + 单项 / 交互实验 + 路由 / 服务端校验 + UI + 旧版本保存恢复通过，才可开放相应指令。
  任何指标未实现、机会不足或结果与假设相反时保留原始数据，标记不确定或重新设计，不用隐藏加成补胜率。
