# 挑战玩法重设计：传奇挑战 / 杯赛挑战 / 巅峰之路

> 状态：**设计稿，未实施**。本文档是「挑战」页面的 PvE 玩法扩展方案，先于代码评审定稿。
> 定位：**纯 PvE**。不引入任何联机时间、全服同步或跨玩家竞争；所有状态存在各自存档里，服务器不需要任何改动（联机模式下也只落在玩家自己的存档命名空间内）。

## 一、现状与目标

### 1.1 现状

- 挑战页（`src/ui/screens/challenge.ts`）目前只有**友谊赛**：按联赛分区列出世界球队，单场约战，平局进点球（`knockout` 语义），战报进 `challengeHistory`，无收入、不涨球迷。
- 比赛管线已经支持「对任意一支 `AITeam` 开一场淘汰赛语义的比赛」（`startChallengeAgainstTeam(game, ai, seed)`），引擎、战报、复盘、点球全部现成。
- 球员数据是 0–1500 的主属性制，CA 上限 1500；球星有 `era`（年代）、`tier`（强度档）、风格画像（`profiles-curated.ts` 手工画像 + FM 导入画像）决定「强在哪」。
- 俱乐部页已有「历史成绩」标签（历年联赛），没有奖杯/荣誉陈列。

### 1.2 目标

在挑战页增加三个新模式，与现有友谊赛并列：

| 模式 | 一句话 | 对手 | 反复性 |
|---|---|---|---|
| 友谊赛（现有） | 和世界球队单场约战 | 当前世界的 AI 球队 | 无限 |
| **传奇挑战** | 挑战历史最强俱乐部赛季的复刻阵容 | 固定静态数据（50 支起步） | 无限，记录战绩 |
| **杯赛挑战** | 单败淘汰杯赛，夺冠进荣誉橱窗 | 世界球队 / 纯随机生成（按杯赛定义） | 同一杯一赛季一次，输球淘汰 |
| **巅峰之路** | 100 关由弱到难闯关 | 前 20 关国家队，其余生成 AI + 少数固定配置 | 过关推进，输可重试 |

### 1.3 全部模式共用的比赛口径（不改引擎）

| 事项 | 口径 |
|---|---|
| 引擎 | 复用现有比赛创建管线（新物理引擎 + 结算内核），`knockout = true`，平局进点球 |
| 收入/球迷 | 与友谊赛一致：**不产生轮收入、不涨球迷**（杯赛/闯关奖励走显式发放，不混入比分驱动的经济） |
| 体能/伤病 | 与友谊赛一致：赛后扣 condition、伤病照记（沿用 `applyMatchConditions` / `recordMatchInjuries` 现行为） |
| 种子 | 固定种子：`splitSeed(game.seed, '<mode>-<key>-<attempt>')`，读档不能刷新射门 |
| 进行中互斥 | 与现在一致：同一时刻只有一场进行中的比赛（`activeMatch`），PvE 比赛与联赛不并行 |
| 战报 | 进 `challengeHistory`；`MatchRecord` 增加 `mode` 字段区分（见 §5.2），复盘页按 mode 显示标签 |

## 二、传奇挑战

### 2.1 规则

- 50 支（首批）**历史最强俱乐部赛季**的复刻队伍：真实俱乐部名 + 具体赛季 + 当年教练 + 当年真实阵容（每队 16 人：11 首发 + 5 替补）。
- **同一俱乐部允许出现多个不同年份**（如 AC 米兰 1988-89 / 1993-94 / 2006-07 三支并存）。
- 阵容、属性**固定**：静态数据文件，不随存档、不随赛季变化；每个玩家看到的都是同一支（不像世界 AI 会成长）。
- 自由约战，无解锁门槛；每支队伍记录**战绩**（胜/平/负、进球数），挑战页直接展示。
- 全开放、可无限重打；「击败全部 50 支 / 某俱乐部全部年份」的成就式里程碑留作后续扩展（只加展示，不加数值奖励）。

### 2.2 属性怎么「根据现实设计」

数值是玩法数据、不是能力鉴定，但尊重历史共识。设计口径（已实装）：

- 每名球员的目标是 **7 项主属性**（外场：传球、射门、盘带、抢断、力量、速度、爆发力；门将：反应、手控球、出击、一对一、传球、镇定）的**平均评分 80–100**，不是要求每一项都 ≥88。
- 主属性按位置/风格/手工画像展开：强项推到 100，弱项可以落到 45–75，再统一平移，使 7 项平均落在目标值。因此会明确出现强弱形状，例如范巴斯滕射门 100 / 抢断 53，皮克传球 100 / 射门 58。
- **隐藏属性**（视野、决断、无球跑动、防守站位、预判、镇定、团队合作、停球、头球、灵活、耐力）优先参考 FM 画像 `fmProfileFor`（FM24 + 2013-14 导出表）；没有 FM 数据的球员回退到 `profiles-curated.ts` 手工画像或风格画像。隐藏属性不参与「主属性平均 80–100」这个目标，单独按较平的分布生成。
- CA 不再作为硬约束，由全部 18 项（门将 22 项）自然推导；当前 50 队首发平均 CA 约 1100–1200。
- 上限 = 当前值（`ceilings = attrs`，`PA = CA`）：复刻阵容不存在成长，所见即所得。
- 每队整体强度按当年实际战绩分档，档位只影响队内主属性平均目标的分布（全部在 80–100 内）：
  - **S+**：公认历史最强梯队（08-09/10-11 巴萨、12-13 拜仁、14-15 巴萨）→ 首发主属性平均约 88–92
  - **S**：欧洲冠军级（88-89 米兰、16-17 皇马、99 曼联等）→ 约 86–90
  - **A**：联赛冠军/欧冠决赛级（95-96 尤文、90-91 桑普等）→ 约 84–88
  - **B**：有历史意义但整体稍弱（森林、凯尔特人、摩纳哥等）→ 约 80–84
- 首发位置、阵型、战术都按当年真实配置；替补按当年轮换写。
- 数据来源声明沿用现有口径：真实姓名与俱乐部名仅用于原型玩法测试，属性为玩法数据；50s–70s 球员不依赖 FM 导入，隐藏属性由手工画像/风格画像补齐。

### 2.3 数据格式

新文件 `src/game/data/legend-teams.ts`（静态数据，方便人工核对与增补）：

```ts
export type LegendPlayerTuple = [
  name: string,          // 中文名
  enName: string,        // 英文名（确定性生成、画像匹配的键）
  country: string,
  pos: Position,         // GK/CB/W/CM/ST 五位置制，贴合现有引擎
  style: StyleId,        // 踢法风格 → 主属性基准
  avg: number,           // 7 项主属性（门将 6 项）的平均目标，80–100
  foot?: Foot,           // 可选，默认右脚
]

export type LegendTeamDef = {
  id: string              // 'milan-1988-89'
  club: string            // 'AC米兰'
  clubEn: string
  season: string          // '1988-89'
  coach: string           // '阿里戈·萨基'
  tier: 'S+' | 'S' | 'A' | 'B'
  formationId: ElevenFormationId
  tactics: Tactics
  color: string
  accent: string
  note: string            // 一句历史注解（欧冠夺冠、三冠王…）
  players: LegendPlayerTuple[]  // 16 人，前 11 按阵型槽位顺序排列
}
```

构建器 `src/game/legend.ts`：

1. 7 项主属性：`LEGEND_MAIN_STYLE`（按打法的基准）→ `profiles-curated.ts` 覆盖 → 统一平移，使 7 项平均等于 `avg`。
2. 隐藏属性：`fmProfileFor`（FM 画像）→ `profiles-curated.ts` → 风格画像，按较平分布生成。
3. 阵容：按数据顺序把前 11 人填进阵型槽位，后 5 人替补，`validateLineup` 校验。
4. 结果按队缓存；比赛直接走 `startChallengeAgainstTeam`，**引擎零改动**。

## 三、杯赛挑战

### 3.1 规则

- 三个固定杯赛（见 §3.4）。**同一个杯赛在一个赛季内只能参加一次**：报名后本季锁定；小组出局或淘汰赛输球即结束，只能等下一赛季重新报名。
- **两个 16 队杯赛**：4 组 × 4 队，小组单循环（每队 3 场）；每组前 2 进 8 强；1/4 决赛、半决赛、决赛都是**单场**，平局点球决胜。
- **一个 32 队杯赛**：8 组 × 4 队，小组单循环；每组前 2 进 16 强；16 强单场；**1/4 决赛、半决赛主客场两回合**；决赛单场。两回合总比分打平直接点球，不设客场进球。
- 玩家只踢自己球队的比赛；同组/同轮其他比赛由 AI 对 AI 自动模拟（`simulateAIvsAIState`，v2 快速结算）。
- **夺冠 → 获得奖杯**，永久记录在存档里，俱乐部页可查看奖杯与夺冠记录；同一杯赛多赛季多次夺冠会累计。
- 未完成的杯赛在换季时作废（不补赛、不发奖），下一赛季可重新报名。

### 3.2 流程

```text
报名（本季未参加过）→ 抽签（世界球队 + 随机队混合，本季固定）
  → 小组赛 3 场（逐场踢；其他场次 AI 结算）
      ├─ 小组前 2：进入淘汰赛
      └─ 小组出局：本季该杯结束
  → 16 队杯：1/4 决赛 → 半决赛 → 决赛（均单场）
  → 32 队杯：16 强单场 → 1/4 决赛两回合 → 半决赛两回合 → 决赛单场
夺冠：写入 TrophyRecord，发放夺冠奖励，荣誉橱窗 +1
换季：进行中的杯赛作废（status = 'void'），全部杯赛解锁可重新报名
```

### 3.3 赛制与状态

- **小组赛**：4 队单循环 3 轮；胜 3 分、平 1 分、负 0 分；排序依次看积分、净胜球、进球数、相互战绩、抽签种子。
- **淘汰赛对阵**：小组第一对另一组第二，按固定签表交叉；同组球队不在 1/4 决赛相遇。
- **两回合**：1/4 决赛、半决赛（仅 32 队杯）打主客场；种子高的一方先客后主；总比分平局直接点球。
- **单场淘汰**：16 强（32 队杯）、1/4 决赛/半决赛（16 队杯）、决赛；平局点球。
- 玩家最多场次：16 队杯 6 场（3 小组 + 3 淘汰）；32 队杯 9 场（3 小组 + 1 十六强 + 2 八强 + 2 半决赛 + 1 决赛）。

```ts
type CupRun = {
  cupId: string
  seasonIndex: number
  status: 'active' | 'eliminated' | 'champion' | 'void'
  stage: 'group' | 'r16' | 'qf' | 'sf' | 'final' | 'done'
  group?: {
    index: number
    table: { teamId: string; played: number; won: number; drawn: number; lost: number; gf: number; ga: number; points: number }[]
    fixtures: CupFixture[]
  }
  knockout?: {
    round: 'r16' | 'qf' | 'sf' | 'final'
    ties: CupTie[]
  }
  currentMatchId?: string
}
type CupFixture = {
  id: string
  round: number
  homeId: string
  awayId: string
  played: boolean
  score?: { home: number; away: number }
  matchId?: string
}
type CupTie = {
  id: string
  round: 'r16' | 'qf' | 'sf' | 'final'
  legs: CupFixture[]          // 单场 1 条；两回合 2 条
  aggregate?: { home: number; away: number }
  shootout?: { home: number; away: number }
}
type TrophyRecord = {
  cupId: string
  cupName: string
  seasonIndex: number
  wonAt: number
  finalOpponent: string
  finalScore: { home: number; away: number }
  finalShootout?: { home: number; away: number }
  matchId?: string
}
```

- 判定「本季已参加」用 `cupRun.seasonIndex === game.season.index && status !== 'void'`。
- 奖杯列表只增不减；跨赛季持久。
- 小组赛/淘汰赛的每个 `CupFixture` 都对应一场 `MatchRecord`（`mode: 'cup'`），可复盘。

### 3.4 首版杯赛定义（3 个）

| 杯赛 | 规模 | 赛制 | 参赛池（世界 + 随机） | 定位 | 夺冠奖励（占位） |
|---|---|---|---|---|---|
| 社区杯 | 16 队 | 4 组 × 4；小组前 2 → 8 强单场 | 12 世界（含你，11 AI）+ 4 随机 | 入门，练阵容 | 100 万 |
| 联盟杯 | 16 队 | 4 组 × 4；小组前 2 → 8 强单场 | 7 世界 + 你 + 8 随机 | 中期主力杯 | 300 万 |
| 冠军杯 | 32 队 | 8 组 × 4；前 2 → 16 强单场；8 强/半决赛两回合；决赛单场 | 11 世界 + 你 + 20 随机 | 高难度，毕业杯 | 800 万 |

- **随机队池**：全局常量 `CUP_SEED` + `CUP_VERSION`，按杯赛生成固定池：社区杯 8 队、联盟杯 12 队、冠军杯 24 队；冻结在 `src/game/data/cup-teams.generated.ts`。所有玩家共享同一批随机队；每个赛季按 `splitSeed(CUP_SEED, 'cup-field-<cupId>-<season>')` 抽取/轮换。
- **世界队**：社区杯从本分区取，联盟杯从全世界的非冠军联赛取，冠军杯从冠军联赛/高 RANK 球队取；世界队强度跟随存档世界成长。
- **混合与抽签**：世界队 + 随机队合在一起后按赛季种子洗牌、分组；同一赛季同一杯赛的对阵固定，换季作废后重新抽。
- **随机队强度**：社区杯约 600–750、联盟杯约 780–920、冠军杯约 950–1100（首发平均 CA）；随机队不随世界成长，保证杯赛始终有“外部强队”。
- **杯赛定义是配置，不是存档**：增删杯赛不影响旧存档（新杯自动可报名，删掉的杯只是不再出现在报名列表，奖杯记录仍显示）。
- **传奇杯**（8 队、全部传奇队抽签、特殊奖杯样式）作为后续扩展预留，本版不开放。
- 换季作废的理由：世界球队名单换季后重建，签表里的队伍引用会失效；随机队池虽然固定，但小组/对阵是按赛季抽的，跨季没有意义。

## 四、巅峰之路

### 4.1 规则

- **100 关**由弱到难推进：只能挑战「当前关卡」，过了解锁下一关，没过不推进（可无限重试）。
- 每关一场淘汰赛，平局点球决胜（闯关不能靠平局混）。
- **1–80 关为生成 AI 球队**：名字、球衣、阵型、战术、球员都按全局种子和关卡号生成，首发平均 CA 沿 §4.2 曲线爬升。
- **81–100 关为 20 支固定世界杯国家队**：静态复刻，属性按现实设计；从 81 关的 1000 一路打到 100 关的 1300，构成最后的“世界杯墙”。
- 固定国家队是静态定义，所有玩家一致；生成段用全局种子，保证所有玩家打到的第 N 关也是同一支球队（§4.2.1）。
- **奖励**：每关一个奖励槽 `RewardDef`，默认 `{ type: 'none' }`；里程碑关发金钱；技能卡奖励预留（§4.4）。**每关奖励只发一次**（记录已领取的最高关卡）。

### 4.2 难度曲线：350 → 1300

关卡 s 的目标是**首发 11 人的平均 CA**。曲线单调不降，段内线性、取整到 5：

| 关卡 | 目标首发平均 CA | 队伍来源 |
|---|---:|---|
| 1–10 | 350 → 450 | 生成 |
| 11–20 | 450 → 550 | 生成 |
| 21–30 | 550 → 630 | 生成 |
| 31–40 | 630 → 710 | 生成 |
| 41–50 | 710 → 780 | 生成 |
| 51–60 | 780 → 850 | 生成 |
| 61–70 | 850 → 920 | 生成 |
| 71–80 | 920 → 1000 | 生成 |
| 81–90 | 1000 → 1135 | 固定国家队 |
| 91–99 | 1150 → 1270 | 固定国家队 |
| 100 | **1300** | 巴西 1970 / 最终 Boss |

- **1–80 关**：每关 11 名首发围绕目标均值分布：核心 +80～120，主力 ±30，替补 −80～120；单队实际平均允许 ±20 偏差。
- **81–100 关**：按每支国家队的真实档位给 CA（见 §4.3），不是机械插值；整体从 1000 拉到 1300。
- **第 100 关 1300** 已经高于现有传奇队 S+ 的首发平均（约 1150–1200），定位为整个 PvE 的最终 Boss；如果觉得太难，优先把 100 关降到 1250，而不是改前 99 关。
- 生成段的战术倾向随关卡加深：1–40 均衡/混合，41–70 开始高压/直传，71–80 高位防线 + 高压 + 快速。
- 需要 `scripts/balance.ts` 用「对应阶段的培养阵容」抽样验证：目标为适龄阵容胜率 55–70%，跨 20 关后掉到 30–45%。

#### 4.2.1 怎么保证所有玩家打的是同一支 AI

**核心原则：生成段用全局种子，固定段用静态定义，二者都不能来自玩家存档或账号。**

- 定义全局常量 `PEAK_ROAD_SEED`（例如 `0x5EED2026`）和 `PEAK_ROAD_VERSION`（例如 `1`）。
- 第 N 关（1–80）的随机队种子固定为：
  ```ts
  splitSeed(PEAK_ROAD_SEED, `peak-v${PEAK_ROAD_VERSION}-${N}`)
  ```
  **不要**用 `game.seed`、账号 id、`Date.now()`、服务器启动时间或注册时间。
- 81–100 关的世界杯国家队是静态定义，天然对所有玩家一致。
- 生成段只要「同一个种子 + 同一版生成器 + 同一份数据」，所有玩家（单机、联机、不同设备）得到的就是同一支球队。
- **推荐再保险：把 100 关的对手冻结成 `src/game/data/peak-stages.generated.ts`**。用 `npm run peak:generate` 按全局种子生成一次并提交，运行时直接读表；这样即使以后改了球员生成器，旧关卡也不会变。100 关 × 16 人 ≈ 1600 名球员，文件约 100–200KB，可接受。
- 如果不想冻结整张表，至少保留 `PEAK_ROAD_VERSION`：改生成器就升版本，旧版本逻辑保留或只对新玩家生效；否则同一关在不同版本会生成不同球队。
- 联机时由服务器下发/校验对手（或直接下发整张表）；单机用同一份表/种子。不要出现“服务器按 v2 生成、客户端按 v1 生成”的漂移。
- **只落盘进度**：`pve.peak.cleared`、`rewardClaimed`。当前关的对手可以存一份快照，防止中途更新把对手换掉；已通关的关卡不需要存。
- 杯赛同理：如果要让同一赛季所有玩家面对同一批 AI，种子用 `sharedWorld.seed + cupId + seasonIndex`，不要带账号 id；只有「每人不同签表」时才把账号 id 加进抽签种子。

> 「按需生成」和「所有人相同」不矛盾：按需生成只是延迟计算，确定性来自**全局种子 + 版本化生成器**，不是来自服务器启动时预生成。

## 八、已定决策与开放问题

### 已定（本方案内）

1. **D1** 三种新模式全部复用友谊赛比赛管线，不改引擎与结算。
2. **D2** 传奇队/国家队为静态数据文件，构建成标准 `AITeam`；确定性属性生成，不随存档漂移。
3. **D3** 杯赛：每季一次、单败淘汰、输了淘汰、换季作废、奖杯永久记录。
4. **D4** 巅峰之路：输可无限重试、平局点球、奖励按关卡只发一次；前 20 关固定国家队。
5. **D5** 全部状态进 `GameState.pve` 可选命名空间，读档补默认值；不碰服务器。
6. **D6** `MatchRecord.mode` 区分模式，`isLeague` 语义不动。
7. **D7** **首版 3 个杯赛**：社区杯、联盟杯、冠军杯；传奇杯（全传奇抽签）预留后续扩展，本版不开放。
