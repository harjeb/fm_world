# 战术风格与球队指令：引擎验证报告（首轮）

> 本文是 [战术风格与球队指令](./fm-tactical-styles-and-instructions.md) 第三、四节和
> [球队指令系统](./team-instructions-system-design.md) 4.1 的**实测验证**：实现了首版九项指令的实验分支、
> 比赛埋点和批量实验脚本，按文档 4.2 / 4.5 的口径测量方向与幅度，并给出校准后的参数建议。
>
> 状态：
> - **已实现**：P1 九项指令（方向 / 传球 / 节奏 / 持球宽度 / 得球 / 失球 / 防线 / 逼抢线 / 频率）、
>   熟练度执行模型、比赛埋点、实验脚本；旧 v4 路径未改（`src/game/pes` 全部测试通过）。
> - **未实现**：P2 高级指令、P3 比赛钟 / 拖延、跨场体能、后台 `MatchEngine` v2 投影、服务端校验与 UI。
> - **结论等级**：机制方向「已验证」；整套风格「行为有效 9/10」；结果影响「仅探索，且当前不满足平衡护栏」。
>   本文所有数字都只代表本夹具、本引擎版本、本参数集。

## 1. 结论摘要

1. **机制方向全部正确**：10 类单项指令在固定夹具上都能产生文档预期的方向，且没有把「方向 = 宽度」
   或「逼抢线 = 频率」混成一个滑杆（见 3.1）。
2. **9/10 风格达到行为目标**：只有「摆大巴」的 EF 目标与模板自相矛盾（模板同时用 `direct` 传球，
   而直传本身就会抬高 EF）；「链式防守」的 DL 刚好压在下界（−2.97 米，目标 −3 米）。
3. **最重要的校准不是系数，而是中性基线**：文档 4.1 的逼抢线 `mid = 0.60`、搜索半径 `mid = 12` 让
   「中性」B0 比当前 v4 的逼抢**弱 −0.62 xGD**。这意味着任何「风格 vs B0」的对照都会把风格高估约
   半个净胜球。校准后 `mid` 必须复现 v4 的逼抢覆盖（0.90 / 15 米），`low` 才是真的收缩。
4. **平衡护栏未通过**：校准后各风格相对 B0 的 `ΔxGD` 仍在 **−1.6 ～ +1.9**，是文档 4.3 探索区间
   （±0.1～0.2）的 5～10 倍；控球 / 高压系一律占优，低位防守系一律吃亏。原因不是指令方向错了，
   而是缺少两类代价：**高位防线身后的空间**和**逼抢强度的体能反馈**；低位防守还缺 P2 的**无球宽度**
   （见 6）。
5. **熟练度模型可用**：进攻端效应随熟练度按 `eff = 0.35 + 0.65 × fam` 线性衰减（`fam = 0.4` 时保留约
   35%，`fam = 0` 时回到中性）；防线端在补上「执行反了」抽签后才出现退化（见 7.3）。
6. **目前几乎没有克制**（新增第 8 节）：45 组对位里只有 5 条交互项显著，全部是「同级风格互相克制」；
   任何低位 / 反击风格对控球 / 高压的交互项都在 ±0.5 以内且不显著。**「防反克制高压」不成立**，
   因为引擎里既没有「身后空间」的收益，也没有「低位紧凑」的防守收益。熟练度目前只缩放强度，
   不能翻转对位（8.6），要绑定克制必须让「熟练度差」进入对位机制（8.7）。

## 2. 口径与可复现性

- **夹具**：`src/game/pes/baseline.ts:baselineTeams(1)`，体力 100、删除 `autoSubs` / `chemistry`、
  对象键排序、非有限数记 0、UTF-8 无换行 → **60,950 字节，SHA-256 `f03f8ef0…c801b`**，
  与设计文档 4.5 第 2 条给出的哈希**逐位一致**（脚本启动时打印并校验）。
- **比赛**：11 人制 105×68（`makeGamePitch(900)`）、`D = 900`、越位开、`noInjuries: true`、`now = 0`、
  常规时间、无点球大战、双方 `autoSubs = undefined`。
- **三种场景**（文档 4.5 第 3 条）：`mirror`（镜像均衡，对手 B0）、`technical`（本方传球 / 一脚球 /
  视野 / 决策 +8，抢断 / 力量 / 头球 / 防守站位 −8，对手 B0）、`speed`（对手速度 / 加速 / 无球跑动 /
  灵活 +8，传球 / 视野 / 团队 / 耐力 −8，并使用「快速防反」模板）。
- **配对**：每个种子 4 场（试验主 / 试验客 / 对照主 / 对照客），同一比赛种子、同一批球员换边。
  主指标先按场求值，再按种子块求 `S − C`；区间用固定种子的 2,000 次配对 bootstrap（95%，未做多重校正）。
- **样本**：风格 12 个种子块 × 3 场景（792 场）；单项 8 个种子块 × 3 场景（912 场）；
  熟练度 6 个种子块 × 2 场景。
- **脚本**：`npm run tactics:experiment`（`--individual` / `--familiarity` / `--n` / `--only`）。
  结果写入 `docs/tactics-experiment-*.json`；同参数的结果有缓存，重跑只补缺失场次。

### 2.1 埋点口径与文档的差异

`src/game/pes/metrics.ts` 实现了 `PL / CF / W / DL / HLR / EF / Stam`，另外加了
`pressU`（上抢时的球位置）、`pressN`（每帧上抢人数）、`pressRate`（有上抢任务的防守帧比例）、
`lossPressRate`（失球窗口内有上抢任务的帧比例）、`decideInterval`（决策间隔，tempo 用）。

简化（不宣称兼容性验收通过）：

- 夺回确认用 `possessionTeam()` 连续累计 0.20 模拟秒，候选期间主动出脚立即确认；原控球队重获球权或
  死球取消候选。文档里「新候选暂时挂起旧窗口 / 恢复」的多窗口细节没有实现，只保留一个活动窗口。
- 稳定控球暴露时间直接取自 `possessionTeam()`（含同队传球飞行），未单独处理 `looseT ≤ 4` 的细分。
- 埋点默认关闭；关闭时一行不执行，v4 的比分 / 事件 / 随机数流不受影响。

## 3. 机制验证（单项指令）

参数为**文档 4.1 的首轮值**（`wPass 0.08 / wFocus 0.08 / wWidth 0.15 / wTransition 0.06`、
`engagement 0.35/0.60/0.90`、`radius 9/12/15`、`count 1/1/2`），只改 A 队一项，其余中性；
**唯一例外是防线**：文档的 `line 0.2/0.5/0.8` 实测 `DL` 几乎不动（−1.5～+2.2 米），
所以这一行用 5.2 校准后的映射（`lineValue 0.1/0.5/0.9` + `lineDepth 8` 米）测方向。
数值为相对 B0 的差（8 个种子块，主客平均）。

补充观察：

- **节奏只改决策间隔，不改成功率**：`slow / fast` 的 `passAcc` 变化在 −0.4 ～ +1.7pp 之间、区间都跨 0，
  与「节奏不是凭空加能力」一致。实测决策间隔差 ±0.02～0.03 秒，和 `0.26 − 0.1 × tempo` 的公式一致；
  节奏的杠杆本身很小（满档只有约 0.055 秒）。
- **频率的高档靠人数而不是发生率**：搜索半径 12 → 15 米几乎不改变「有没有人上抢」，只增加第二上抢者
  （`pressN` +0.89）。所以文档里「频率 → 上抢任务发生率」的预期只对低档成立，高档要用**人数**判定。
- **防线是最弱的机制**：文档的 `line 0.2 / 0.5 / 0.8` 在现有 `formationTarget` 里几乎不生效
  （`lineX` 限幅从不 binding），实测 `DL` 只有 −1.5 ～ +2.2 米。校准后（`lineValue 0.1/0.5/0.9` +
  `lineDepth 8` 米 + 熟练度系数）单项变成 −1.9 ～ +2.5 米，整套「链式防守」到 −3.0 米，
  才勉强进入文档 −3～−10 的下界。要真正做出「低位 / 高位」，还需要 6.2 的平衡机制配合。
- **失球转换的幅度远大于文档预期**（±33 ～ ±60pp），因为「有没有上抢任务」是二值行为；
  作为方向验证足够，但不适合当验收门槛，建议改成「窗口内平均上抢距离 / 人数」这类连续量。

### 4.2 「摆大巴」的目标需要改写

文档把「摆大巴 / B0 的 `EF` −12～−3pp」当作主指标，但 3.5 的摆大巴模板同时带 `passing = direct`，
而 `direct` 本身就把 `EF` 抬高约 +8～+14pp（3.1 的 `onGain: counter` 与直传叠加），两者相互抵消。
实测只有 −0.7pp。真正可检验的因果比较是**摆大巴 vs 链式防守**（两套模板只差 `onGain`），
实测差约 −5～−10pp，方向正确。建议把这一行的主指标改成「相对链式防守的 `EF`」，或者把摆大巴的
`passing` 改成 `mixed`（但那就不再是 3.5 的模板了）。

## 5. 参数校准

### 5.1 先修中性基线：「mid」必须等于当前 v4 的逼抢覆盖

用同一夹具跑「B0（新模型中性） vs v4 旧五字段全中」12 个种子块：

| B0 的逼抢设置 | B0 − v4 `xGD` |
| --- | --- |
| `engagement mid 0.60` / `radius 12`（文档值） | **−0.62** ± 0.21 |
| `engagement mid 0.75` | −0.43 ± 0.16 |
| `engagement mid 0.90` | +0.07 ± 0.19 |
| `engagement mid 1.00` | −0.36 ± 0.22 |
| `radius mid 15`（逼抢线不变） | −0.06 ± 0.16 |
| `pressCount mid 2`（人数 +1） | −0.79 ± 0.21 |

结论：

- 文档的 `mid = 0.60` 把「中性」定义成了比当前游戏**更保守**的球队；用它当对照，所有风格都会
  凭空多出约 +0.6 xGD。「风格 vs B0」的对照因此不能直接当作「风格是否过强」的证据。
- 把 `mid` 拉到 0.90（或半径拉到 15）后 B0 与 v4 基本打平（+0.07 / −0.06）。
- **第二上抢者不是白送的**：在逼抢线不变时把人数加到 2，B0 反而比 v4 差 −0.79 xGD
  （拉走两个人、身后空当变大）。这条数据支持「高强度压迫必须付代价」，也说明 `pressCount high = 2`
  不能单独当作增益使用。

### 5.3 重新锚定带来的副作用

- `highPress` 的 `HLR` 从 +0.77（旧 `mid`）降到 **+0.32**，低于文档 +0.5 的下界。这不是机制失效，
  而是对照变强了：`HRR` 的分母（对手控球暴露）和分子（高位夺回）同时变化。建议把该行的目标改成
  **+0.25～+1.5 次 / 对手控球 10 分钟**，或给高频率档再加一个「反抢成功后 3 秒内的射门」指标。
- 低 / 中 / 高逼抢线的**绝对含义变了**：`mid` 现在是「像今天这样全场都能上抢」，`low` 才是收缩。
  文档 3.5 的模板本身不用改（模板写的是档位，不是数值），但 4.1 的数值表和 UI 文案要同步更新。

### 6.2 读法

1. **风格优势主要来自防守端**：控球 / 高压 / 密集短传的 `ΔxG 防守` 是 −0.5 ～ −1.1，而进攻端只有
   +0.3 ～ +0.8。也就是说「压上去让对手踢不出来」在当前引擎里的收益，远大于「自己创造机会」。
2. **高位防线没有付代价**：即便对手是「快速防反 + 速度型」（`speed` 场景），高压系仍然净赚。
   当前引擎里能利用身后空间的机制（`spaceBehindLine`、直传身后）权重太低。**这是最该先补的**：
   在 `speed` 场景里，高位压迫应当出现 `ΔxG 防守 > 0` 的迹象，否则「高压 + 高防线」就是无风险按钮。
3. **体能代价存在但太弱**：高压系多跑 570 ～ 740 米、期末体力低 3 ～ 5 个点，但 `maxSpeed` 的体力项是
   `0.78 + 0.22 × stamina`，5 个点只相当于 1% 速度。**方向建议**：把体力对速度的敏感度从 0.22 提到
   0.35，或在 `tryTackles` / 传球误差里加体力项，再复测「高压下半场失球 / 被反击」。
4. **低位防守目前是纯亏**：链式防守 / 摆大巴 / 长传冲吊的 `ΔxG 防守` 都是 +0.4 ～ +1.1（越守越差），
   `ΔxG 进攻` 也变差。原因是 P1 只有「防线更深」，没有 P2 的**无球宽度**和**紧凑度**：队形只是整体
   后撤，横向空间没压缩，对手照样能从中路推进。**方向建议**：低位防守不要单独开放；必须先做
   `advanced.defense.width`（文档 4.4 的 0.85 / 1.00 / 1.15 缩放）与拼抢尺度，否则「防守型风格」就是
   严格劣势选项。
5. **传球型风格有真实代价**：双翼齐飞 / 长传冲吊的传球成功率 −1.3 ～ −2.7pp、射门 −0.9 ～ −3.1，
   双翼齐飞还要多跑 640 ～ 1130 米、期末体力低 4 ～ 5 个点。这是唯一「有收益也有代价」的一组，
   符合设计原则 3；但它们的 `ΔxGD` 是 0 到 −0.6，收益不足以抵消代价。

### 6.3 平衡护栏判定

按文档 4.5 的护栏（`ΔxGD` 落在 ±0.1～0.2 的探索区间、「没有在多场景都无代价的万能风格」）：

- **不通过**。校准后仍有 4 个风格（控制球权、高位压迫、密集短传、垂直密集短传）在三种场景下都净赚
  约 +1 xGD，且代价只有 3～5 点体力。
- 这不是「指令写错了」，而是**收益/代价不对称**：防守端收益已经实现，进攻端空间与体能代价还没实现。
  在这两类代价补上之前，P1 建议只以「行为有效」对外，不进入 PvE 平衡与线上联赛默认模板。

## 7. 战术难度与球员熟练度

### 7.1 数据与取值

- 每名球员一份熟练度 `fam ∈ [0, 1]`（UI 显示 0–100）。建议按**指令族**存，而不是按风格 ID：
  `possession`（传球 / 方向 / 节奏 / 宽度）、`transition`（得球 / 失球）、`block`（防线 / 逼抢线）、
  `press`（频率）。风格熟练度 = 这四族的加权平均（权重默认 0.3 / 0.25 / 0.2 / 0.25）。
- 风格复杂度（文档 1. 的标签，已写进 `STYLES[id].complexity`）：
  - `0.7` 低：双翼齐飞、长传冲吊、快速防反
  - `1.0` 平均：控制球权、灵活防反、链式防守、摆大巴
  - `1.3` 高：高位压迫、密集短传、垂直密集短传
- 单项难度（`INSTRUCTION_DIFFICULTY`）：传球 0.8、方向 0.9、节奏 0.9、宽度 1.0、防线 1.0、
  得球 1.2、逼抢线 1.2、失球 1.3、频率 1.3。
- 建议的「无惩罚所需熟练度」：复杂度 0.7 → **0.45**，1.0 → **0.60**，1.3 → **0.75**。
  低于该值 UI 显示「战术生疏」，低于 `所需 − 0.15` 显示红色警告。这些门槛来自 7.3 的衰减曲线，
  不是官方数据。

### 7.2 执行模型（已实现并验证）

```text
eff  = 0.35 + 0.65 × fam                              // 执行强度：缩放偏好幅度 / 逼抢线 / 半径 / 人数 / 前插概率
slip = 0.35 × (1 − fam) × difficulty                  // 每次决策「执行反了」的概率（上限 1）
bias = +1（未 slip） / −1（slip）                       // 进攻端反转偏好方向；防线端低/高互换
```

实现位置：`src/game/pes/sim.ts` 的 `assignPressers`（防线端）与 `passValue` / `decideOffBall`
（进攻端）、`src/game/pes/tactics.ts` 的 `execution` / `slipChance`。

设计取舍：

- `eff` 用**全队平均**熟练度，因为它作用于整体队形与逼抢覆盖；`slip` 用**个体**熟练度，
  因为「这一脚是否按战术处理」是个人决策。
- 满熟练度（`fam = 1`）时 `slip = 0` 且不抽额外随机数，所以校准实验（全部 `fam = 1`）的行为
  与实装完全一致，也让「老球员 / AI 默认熟练度」可以走同一条路径。
- 防线端「执行反了」定义为**档位互换**（低 ↔ 高，中不变），而不是随便乱跑；否则低位防守会退化成
  随机站位，反而更难平衡。
- 熟练度只影响**选择与站位**，不改能力、不改传球 / 射门成功率、不改跑速。这与文档「不重复加成」一致。

### 7.3 实测衰减曲线

同风格相对 B0 的主指标（mirror + speed 平均，6 个种子块；`fam` 为全队熟练度）：

| 风格 | 主指标 | fam 1.0 | fam 0.7 | fam 0.4 | fam 0.0 | 0.4 档保留比例 |
| --- | --- | --- | --- | --- | --- | --- |
| 控制球权 | `PL%` | −7.9 | −2.8 | +1.0 | +0.6 | ≈ 0（已回到中性） |
| 高位压迫 | `HLR` | +0.75 | +0.49 | +0.53 | +0.27 | 71% |
| 密集短传 | `EF` pp | −8.8 | −5.6 | −3.8 | −3.8 | 44% |
| 垂直密集短传 | `CF` pp | +13.1 | +9.0 | +6.5 | +7.4 | 49% |
| 双翼齐飞 | `W` 米 | +4.6 | +4.7 | +5.8 | +5.8 | 125%（反向，见下） |
| 快速防反 | `EF` pp | +11.6 | +7.7 | +4.4 | +1.6 | 38% |
| 链式防守 | `DL` 米 | −3.1 | −2.2 | −1.8 | −1.0 | 59% |

读法：

- **进攻选择类**（`PL / EF / CF`）随熟练度单调衰减：`fam 0.7` 保留约 45～70%，`fam 0.4` 保留约
  20～50%，`fam 0` 剩下 10～45%（`eff` 的下限 0.35 加上「执行反了」的抵消）。
  `控制球权` 的 `PL` 在 0.4 档已经翻正，说明它最先失效——`passing` 是难度最低的指令（0.8），
  但它的效应也最小，低熟练度下很容易被随机选择淹没。
- **防守覆盖类**（`HLR / DL`）在补上「执行反了」之后也出现了退化（71% → 31%），但比进攻慢：
  因为防线 / 逼抢线是**整队连续生效**的，不像单次传球那样一次 slip 就完全相反。
- **宽度类仍然是反例**：`W` 随熟练度下降反而增大。原因是宽度只缩放队形目标，`eff` 小时回到中性，
  而 slip 会把「窄」变成「宽」，两侧平均后反而更宽。正式版应把宽度指令的 slip 处理成
  **不使用该指令**（回到中性）而不是反向使用。
- 结论：`eff = 0.35 + 0.65 × fam` + `slip = 0.35 × (1 − fam) × difficulty` 这组数在 0.4～1.0 区间
  表现符合「熟练度越高执行越准」的设计意图；0.4 以下更多是随机行为，建议 UI 直接把
  `fam < 0.4` 标成「战术执行不可控」，不要只显示「略有影响」。

### 7.4 成长与衰减（建议值，未在引擎中验证）

- 首发并踢满 60 分钟：该指令族 `+0.035`；替补登场 ≥ 30 分钟：`+0.015`。
- 每场季前 / 训练营专项：`+0.08`（赛季上限 `+0.25`）。
- 连续 3 场未使用该族：每场 `−0.02`；赛季结束未使用：`−0.10`。
- 换帅 / 换风格不重置，但新风格所属族从当前值起步；这样「练过的球队」才有优势。
- 单场上限：`fam` 变化不超过 `±0.05`，避免一场比赛就刷满。

### 7.5 与存档、校验、AI 的关系

- `fam` 存在球员档案里，随阵容快照进入比赛输入；比赛存档只需要保存**本场使用的 `fam`**（已在
  `PesPlayer.familiarity`），因为比赛内不成长。
- 服务端校验：`fam` 必须是 `[0, 1]` 的有限数；缺失按 `1`（老存档、AI）处理，不能按 0 处理。
- AI 球队建议按联赛级别给固定 `fam`（如 0.55 / 0.65 / 0.75），避免 AI 因为「不熟练」而被玩家白嫖。
- UI 提示要区分「指令已设置」和「球员执行不了」：前者是战术问题，后者是熟练度问题。

## 8. 风格对位、克制与熟练度绑定

方法：`mirror` 场景（同一批基线球员，双方都没有属性增减；阵容画像的敏感性见 8.8），
无序对 45 组 × 6 个种子块 × 主客两场

| 摆大巴 | 长传冲吊 −0.09（不显著，连这个都不占优） | 垂直密集短传 −2.56 |

结论：只有**灵活防反**是一个真的能打的「防反」；快速防反 / 长传冲吊 / 链式防守 / 摆大巴对同级别风格
基本没有优势位，对控球组全线落后。

### 8.5 为什么没有克制

三条机制缺口，和前文的平衡问题同源：

1. **控球方不给转换机会**：`EF` / `HLR` 的数据显示，控球 / 高压风格的对手全场只有很少的高位失球窗口；
   反击风格拿到球时，对手的防线往往已经落位。
2. **低位防守不降低对手 xG**：链式 / 摆大巴的 `ΔxG 防守` 是 +0.4 ～ +1.1（越守越差），因为 P1 只有
   「防线更深」，没有 P2 的无球宽度 / 紧凑度，对手照样能从肋部推进。
3. **高位防线不付身后代价**：控球 / 高压的 `ΔxG 防守` 是 −0.5 ～ −1.1；即便对手是速度型快反
   （`speed` 场景），也照样净赚。

所以现在的「克制」只发生在**同类之间**（灵活防反 vs 其他反击 / 长传 / 双翼），因为它们的比赛会真正
进入攻防转换；一旦对上控球组，比赛根本不进入转换。

### 8.6 熟练度绑定：目前只是强度缩放，不是克制开关

`快反 vs 高压`（A = 快速防反，B = 高位压迫），每格是 A − B 的 xGD，5 个种子块：

| A \ B | B fam 1.0 | B fam 0.7 | B fam 0.4 |
| --- | --- | --- | --- |
| A fam 1.0 | −2.92 | −2.29 | −1.57 |
| A fam 0.7 | −2.33 | −1.54 | −1.44 |
| A fam 0.4 | −1.55 | −1.21 | −1.14 |

- 对手熟练度从 1.0 掉到 0.4，快反能少输 1.35 个 xGD；自己熟练度掉下去反而「少输」，是因为低熟练度
  把风格拉回中性，而中性比这套风格强。
- **但没有任何一格翻正**。同样的形状出现在 `快反 vs 控制`（−2.24 → −0.45）、`链式 vs 控制`
  （−3.07 → −1.06）、`摆巴 vs 控制`（−2.93 → −1.43）：熟练度越低，双方都越接近中性，
  差距按比例缩小，但强弱次序不变。
- 也就是说：**熟练度目前只缩放「风格强度」，不能产生或取消克制**。要让它成为克制开关，必须让
  「熟练度差」进入具体的对位机制，而不是只乘在本方偏好上。

`密短 vs 快反` 是唯一出现反向的一格：A fam 0.4 / B fam 1.0 时 +2.48（高于熟练的 +1.37）。
5 个种子块的噪声很大，这一格只能记为「异常，需要更多样本」，不能当成规律。

### 8.7 要让克制成立，需要补什么（建议实现顺序）

| 机制 | 作用对象 | 建议参数 / 形式 | 预期能造出的克制 |
| --- | --- | --- | --- |
| 身后空间权重 | `passValue` 对「越过对手防线」的候选 | 对手 `DL` 每高于中性 5 米，直传 / 反击的向前候选 `+0.03`，上限 `+0.10`；同时把 `runProb` 从 0.16 提到 0.22 | 快速防反 / 长传 → 高压、垂直密短 |
| 低位紧凑度（P2 无球宽度） | `formationTarget` 无球分支 | 窄 / 正常 / 宽的横向缩放 0.85 / 1.00 / 1.15，并对禁区内射门减成 | 链式 / 摆巴 → 控球、密短 |
| 转换效率 | 转换窗口内的射门 / 纵深 | 窗口内 `shootValue` 对「对手防线未落位」加 `+0.05`，上限 `+0.12` | 灵反 / 快反 → 控球组 |
| 熟练度进入对位 | 交互项而不是单方强度 | `edge = k1 × (本方 transition fam − 对手 block fam) + k2 × (对手 DL − 中性 DL)`，`k1 ≈ 0.25 xGD`，`k2 ≈ 0.04 xGD/米` | 让「练过的防反」才克制「压得高的对手」 |

最后一条是用户要的「克制和熟练度绑定」的关键：**克制应该由「本方转换熟练度 − 对手防守熟练度」决定，
而不是各自乘一个执行系数**。按本文 7.3 的实测幅度（熟练度 0.4 → 0.0 大约损失 50～80% 的风格效应），
`k1 = 0.25` 意味着 0.6 的熟练度差对应 0.15 xGD 的对位优势——这个量级刚好能让「练过的快反」在
「不熟练的高压」面前从 −1.5 走到 −0.3，而不是翻盘；要让克制真正可感知，`k1` 需要 0.5 左右，
并且必须和 8.7 前三条机制一起上。

### 8.8 阵容画像的敏感性：统一属性（`--squad 67` ≈ 主属性存档 1000）

8.2–8.6 的双方是**同一批基线球员**：同一 11 人、同一 4-4-2、同一角色、体力 100，A / B 完全相同；
但**不是全 1000**——基线阵容主属性评分 33–51（存档值约 495–765，均值 37–42），门将 46–50。
（`technical` / `speed` 场景是唯一例外：给一方 ±8 个评分点。）

为了检验结论是否依赖这套「中等、略参差」的阵容，用 `--squad 67` 把双方所有属性拉到同一值
（主属性存档 1005，隐藏属性 13/0–20），位置 / 角色 / 阵型不变，重跑同一张矩阵（660 场）。

**强度变化（vs B0，mirror）：**

| 风格 | 基线阵容 | 统一属性 | 变化 |
| --- | --- | --- | --- |
| 高位压迫 | +1.42 | **+2.29** | +0.87 |
| 垂直密集短传 | +1.24 | **+2.20** | +0.96 |
| 控制球权 | +1.08 | **+1.63** | +0.55 |
| 密集短传 | +1.24 | +1.03 | −0.21 |
| 双翼齐飞 | −0.36 | −0.37 | 0.00 |
| 长传冲吊 | −0.92 | −0.61 | +0.31 |
| **灵活防反** | **−0.92** | **+0.36** | **+1.28** |
| 快速防反 | −0.78 | −0.73 | +0.05 |
| 摆大巴 | −1.15 | −0.91 | +0.24 |
| 链式防守 | −1.42 | −1.31 | +0.11 |

**克制关系也变了**（统一属性下的交互项，`*` = 区间不含 0）：

| 对位 | 基线阵容 | 统一属性 |
| --- | --- | --- |
| 控制球权 vs 高位压迫 | +0.57* | +0.84（不显著） |
| 灵活防反 vs 快速防反 | +1.10* | +0.34（不显著） |
| 灵活防反 vs 长传冲吊 | +1.16* | +0.14（不显著） |
| 双翼齐飞 vs 快速防反 | +0.75* | +0.06（不显著） |
| 密集短传 vs 高位压迫 | −0.14 | **−1.21*** |
| 密集短传 vs 长传冲吊 | +0.13 | **+1.11*** |
| 密集短传 vs 链式防守 | +0.48 | **+1.02*** |
| 摆大巴 vs 双翼齐飞 | −0.09 | **−1.05*** |
| 摆大巴 vs 控制球权 | +0.38 | **−0.78*** |

结论：

1. **对位结论依赖阵容画像**，不能只报一套。基线阵容（属性中等、传控偏低）会低估高压 / 垂密，
   并高估灵活防反的克制。用统一高水平球员后，压迫系的强度进一步放大（+2.2～+2.3），
   灵活防反从 −0.9 变成 +0.4（区间仍跨 0）。
2. 基线阵容下那几条「防反克制」在统一属性下全部消失：说明它们更像「基线阵容的传球 / 对抗短板
   被特定风格利用」，而不是稳定的战术克制。
3. 正式验证至少要报 **三套阵容**：基线、统一中高属性（本节的 67）、以及「技术型 / 速度型」
   两种偏置阵容（文档 4.5 的 `technical` / `speed`）。三套结论一致才算通过；目前只有前两套。
4. 实现上要加一个实验维度：`--squad <rating>`（0 = 基线）。子进程必须随 job 收到这个参数，
   否则会静默跑回基线（本轮就踩过这个坑，已在脚本里修好）。

## 9. 未实现、无法测量与已知缺口

1. **P2 / P3 全部未实现**：传中类型 / 时机、门将出球、无球宽度、拼抢尺度、逼门将、逼边、造定位球、
   拖延时间。本文不对它们做任何效果声明。
2. **v2 比赛读档确定性未达成**：`presser2 / gainAt / lossAt / lineBias` 随 `teams` 序列化，但
   `lastPoss`、夺回候选（起始时刻、球队、已累计确认时长）和 `metrics` 不在快照里。正式发布前必须
   把转换窗口与上抢调度写入 `PesMatchSnapshot`，并按文档 4.5 做「中途存档 = 连续运行」的逐位测试。
3. **越位候选仍是软扣分**，传中候选则无条件排除越位（`crossOption`），两者语义不一致；本轮未改，
   按文档 4.1 的特别限制保留原样。
4. **节奏的可调范围很小**：`0.26 − 0.1 × tempo` 只有 0.055 秒，且被 `clamp(…, 0.1, 0.45)` 与
   个人技能项稀释。若要把节奏做成可感知的指令，需要重新设计反应时间公式（例如把技能项与节奏项解耦），
   并同步更新规则版本。
5. **`pressCount high = 2` 的收益依赖局面**：5.1 里单独加第二上抢者会让中性队变差 −0.79 xGD。
   建议正式版给「第二上抢者」加条件（例如只允许不同线位各一人，或只在球进入前场 1/3 时启用），
   再复测，而不是无条件 +1 人。
6. **后台 `MatchEngine` v2 未接入**：所有结论只适用于玩家可见的 PES 比赛。纯 AI 对 AI 仍是旧引擎，
   不能宣称「全服 AI 都会打新战术」。
7. **样本量**：风格 12 个种子块、单项 8 个，未做多重比较校正；本文的区间只能用于方向判断，
   不能当作正式验收。正式验收需要文档 4.5 的独立种子集（10,001–10,200）和 Bonferroni 校正。
