# 比赛机会与进球模型修改方案 v0.1

状态：**已实施。** 本文保留原设计依据；实施参数、验证结果与兼容处理见文末“实施记录”。

本文明确下一轮修改方向。与旧设计稿的比赛时长、射门模型冲突时，实施本轮修改以本文为准；当前已运行规则仍以代码和 README 为准。所有新概率、距离和统计区间都是待验证的原型参数，不代表现实足球统计定律。

## 1. 目标与非目标

### 1.1 核心目标

1. **一场游戏代表完整的 90 分钟比赛**，现实观看仍可约 10 分钟。比赛时钟、逻辑动作时间与现实播放时间必须明确区分，不能用“现实只播 10 分钟”解释全场只有三脚射门。
2. 弱队对弱队时，既有传丢、停球失误和射偏，也有漏人、被突破和解围失败。低水平不能系统性地只削弱进攻、不释放防守漏洞。
3. **机会质量先决定射门难度，射术决定在该机会内的完成质量。** 射术不高的前锋面对近距离空位、单刀，也应有较高射正概率，不能因绝对属性低而长期无效进攻。
4. 降低“射术低 → 不愿射门 → 射门又不准”的双重压制；增加合理起脚，而不是制造中圈乱射。
5. 射正不等于进球。好机会给射正保底，门将仍能扑救；不强制进球、不按比分补偿、不承诺某一场必有进球。
6. 同种子、同规则版本、同输入与指令仍可复现，表现层不能改变结果。

### 1.2 不做什么

- 不先给所有球员加射术，不用拉大球队实力差掩盖问题。
- 不根据球队总评分、CA、PA 或“弱队”标签直接加命中率。
- 不为了目标比分强制抽进球、失败若干次后必进，或在赛后改写比分。
- 不实现完整物理碰撞、完整裁判、全新战术系统或通用 AI 框架。
- 不要求弱弱对局一定比强强对局进球多；要求它有合理机会，不被系统性锁成低比分。

## 2. 当前证据与判断边界

### 2.1 已有对照

世界种子 `20260418`，19 支 AI 球队两两主客场，共 342 场；各对照使用同一组比赛种子和固定阵容、战术。当前每场逻辑时长 600 秒。下列 +20 均为比赛内部 0～100 评分，主属性存档值对应 +300；不是界面值 +20。

| 条件 | 场均总射门 | 场均总进球 | 平局 |
| --- | ---: | ---: | ---: |
| 当前数值 | 3.01 | 0.41 | 67.8% |
| 双方仅射门 +20 | 5.14 | 0.94 | 44.7% |
| 双方仅射门 +40 | 7.93 | 1.67 | 31.9% |
| 双方全部属性 +20 | 5.63 | 0.94 | 50.0% |
| 仅一方全部属性 +20 | 8.93 | 1.94 | 12.9% |
| 双方组织、推进相关属性 +20 | 3.73 | 0.66 | 59.1% |
| 属性不变，逻辑时长 1200 秒 | 6.08 | 0.86 | 50.6% |

组织、推进组提升：传球、停球、视野、决策、无球、团队合作、盘带、速度、加速度。单方增强组增强侧交替主客场；增强侧场均 1.93 球，另一侧约 0.015 球，说明制造实力差主要产生碾压局。

基准组射门转化率 13.5%，场均引擎 xG 0.44，实际进球 0.41；66.4% 为 0:0。这里的 xG 是引擎自身概率之和，不是独立外部模型，不能据此证明公式合理，只能检查结果是否明显偏离自己的概率。

首发前锋平均射门评分约 46.8、镇定约 42.0。球员生成时压低初始 CA 会整体缩放属性，而现有射门公式仍以 55 为基准。

**这些结果证明射术会同时改变出手数量与转化率，不证明正确修复就是提高属性。** 600 秒与默认 1200 秒的镜像报告也不能直接比较，应先统一整场口径。

### 2.2 需要处理的机制

- `src/game/match/engine.ts` 的 `chooseAction` 直接用预计进球率竞争其他动作，绝对射术低会明显压低射门选择。
- `shotModel` 的射正与射正后进球均受绝对终结能力影响；门将下降不能在射正阶段提供机会质量补偿。
- 视野识别偏向安全横回传；`passValue` 按接球者绝对区域打分，重复互传可能反复获得正价值。
- `openPlay` 先决策，再让全员移动完整动作时间，最后执行。带球者先不动、防守者先追；射门者也可能先按职责回撤。需要改正时序，而非单纯加命中。
- 直塞预想落点与实际接球位置不一致，前方落点没有真正约束接应跑位。
- `findBlockers` 未排除门将，门将可能既封堵又扑救。

不能夸大次要机制：基准射门快照中，排除门将封堵后模型平均进球概率仅从约 13.77% 升至 14.34%；不能把它当作低比分的主要解释。决策后移动也不是每次都降低质量，快照平均预计进球概率略有上升；修复依据是动作语义与公平时序，而非已证明它解释了全部低比分。

## 3. 比赛时间：90 分钟比赛，约 10 分钟观看

### 3.1 三种时间分开

- **比赛显示时间**：0:00～90:00，上半场结束 45:00；正常比赛结束仍为完整一场。
- **逻辑动作时间**：传球、跑动、抢断、射门用来计算位置、可达性与消耗的秒数。
- **现实时间**：联赛约 600 秒完成；关闭页面或服务器重启后仍按同一规则补算。友谊赛的加速、暂停、跳过只影响现实推进。

首版采用最少改动：继续用 `MatchState.clock` 和 `durationSeconds` 表示逻辑秒，比赛显示按归一化进度映射至 5400 秒；联赛现实完成时间独立固定为约 600 秒。逻辑总时长与动作密度通过模拟校准，不能自动与现实观看时间绑定。

这不是只改表盘：必须同时让整场产生足够的有效推进、危险区触球和起脚。先修动作与选择，再用逻辑总时长调节整场机会预算；**不先机械乘九倍动作数**。

### 3.2 必须同步的语义

- UI、文字直播、战报、射门详情统一显示比赛分钟；换人时间、球员出场分钟按 90 分钟语义展示。
- 定时换人的输入和 Agent/MCP 文档明确使用比赛分钟，并在边界转换为逻辑时刻。
- 现实截止时间、离线补算、SSE 推进与赛季调度不得误用 5400 秒延长等待。
- 体力、伤病按新动作密度重新验证；不能因为增加动作就耗尽所有人体力或成倍增加伤病。
- 同时记录逻辑时间和规则版本，避免把旧日志或进行中的比赛按新尺度解释。

## 4. 先修机会生成：防守差必须真实送机会

### 4.1 动作时序

保留现有准备/执行两段时长，不新增物理引擎：

1. 从同一初始状态选择动作并冻结时长与目标。
2. 准备段允许合理调整；持球者保留动作意图，不因普通阵型锚点自动撤销已选射门或传球。
3. 执行段双方依据同一初始快照计算移动与到达时间，一次提交；不能先让防守者追静止持球者六秒，再允许持球者开始突破。
4. 射门质量取出脚时的位置与压力；不能让防守者利用球飞行的全部时间先贴到射手，再倒算出脚干扰。
5. 封堵按出脚后到达射门通道的能力判定，不与出脚前的贴身压力混用。

### 4.2 进攻与防守必须对称地进入空间计算

- 防守站位、预判影响选位和反应延迟；速度与加速度影响实际到达，不能仅在最后抢断概率里扣分。
- 盯防者只能覆盖可达空间，不能仅因成为“最近防守者”就获得满额干扰。
- 直塞接球者确实朝预想落点移动；传球与接应共同决定能否到位，失败落点生成明确的争夺球状态。
- 低能力防守通过现有属性与到达误差产生漏人，不额外引入“弱队必漏人”的独立随机开关。
- 先利用现有断球、松散球、争顶和定位球链条；脱手补射若本轮未实现，单独列为后续项，不把已抱住的球重新分配给进攻方。

### 4.3 反复倒脚

先把传球评分改成“该动作相对当前局面的改善”，保留控球安全的价值，同时计入耗时和失球风险。不要把同一前场区域价值在每次横回传时重复当作新的收益。

如果批量日志仍存在长期不推进，再加一个最小的连续不推进成本；不提前加入复杂记忆、套路树或强制射门回合数。

## 5. 射门选择：机会驱动，不是只有高射术才愿意出脚

- 保留合法距离、角度和控球条件检查；56 米内不是都应当有明显起脚欲望。
- 用局面判断是否值得起脚：近门、角度开放、无有效封堵、机会即将关闭、没有明显更好的传球目标。
- 预计进球概率仍可参与评分，但以机会质量为主，球员终结能力只做有限修正，不能把低射术在好位置的射门选项压没。
- `st_finisher` 等已有职责体现起脚倾向；不必先新增一套人格属性。
- 决策低意味着对机会判断更不稳定，可能仓促射门或漏掉传球，而不是一律更保守。
- 坏角度远射不能靠全局“多射门奖励”胜过明显更好的近距离接应。

记录“具备近距离空位/单刀机会但未起脚”的次数和所选替代动作，用日志验证漏掉好机会，而不是只盯最终射门数量。

## 6. 射正：按机会给基础概率与保底

### 6.1 保底的含义

**保底是每脚合法射门的概率下限，不是射几脚就必定射正。** 它表示低射术在容易的场景里仍能把球送向球门。

- 保底绑定实际距离、角度、控制状态和防守压力，不绑定对手总实力。
- 同样的空位，射术低仍有较高射正概率；射术高则更稳定、终结质量更好。
- 机会已被追回、停球失败、射门角度很差，就不享受干净单刀的保底。
- 无法形成合法射门时，不能用保底生成一次射正。

### 6.2 场景初始标尺

下表为**未被外场球员封堵条件下**的射正概率。距离暂以当前场地坐标米为单位；不是对所有射门统一取下限。

| 场景 | 判定要点 | 基础射正率 | 场景保底 | 上限 |
| --- | --- | ---: | ---: | ---: |
| 近距离开放球门 | 约 8 米内、角度开放、稳定控球、无有效外场干扰，门将无法及时覆盖主要射门角 | 94% | 90% | 99% |
| 干净近距离单刀 | 约 16 米内、面对门将、角度开放、稳定控球，外场球员无法及时施压或封堵 | 85% | **78%** | 97% |
| 禁区内清晰空位 | 约 18 米内、角度合理、稳定控球、低干扰，不满足更高等级 | 77% | **65%** | 95% |
| 普通禁区射门 | 角度尚可，有普通干扰或处理难度 | 60% | 35% | 90% |
| 禁区外及困难射门 | 远距离、小角度、强干扰等 | 先随距离/角度计算，约 20%～45% | 5% | 75% |

不能把禁区坐标标签当作全部依据，必须核对实际距门距离和可见门幅。分类按从高到低互斥处理，不叠加“单刀＋空位＋近距离”三份奖励。边界使用窄区间插值，避免前进几厘米就突增几十个百分点。

头球、凌空、点球与直接任意球单独校准，不直接套用“稳定脚下控球”的 78% 单刀保底。首版保留独立定位球模型并补回归测试。

### 6.3 单刀必须是真单刀

首版可在现有 `shotModel` 周围增加一个小型机会评估函数，复用于决策估值和实际出脚判定。满足以下条件才有干净单刀加成：

1. 球员已控球，不是尚未接到直塞；能在准备段后正常出脚。
2. 实际出脚点距门约 16 米内，开放角度可先用相对球门中轴不超过约 35° 判定，再通过可见门幅细化。
3. 外场防守者当前不在有效贴身范围，且按实际速度、反应和出脚时间不能及时形成干扰。
4. 射门通道中没有可及时到达的外场封堵者，不能只检查射手身边有没有人。
5. 门将是最后主要防守者；若门将也无法覆盖，则评为开放球门而不是叠加单刀奖励。

门将靠近、出击会影响射手可用时间、有效射门角与后续扑救。门将若先合法控制球，则没有射门，不能绕过抢球结果硬给单刀保底。

### 6.4 射正公式起点

比赛输入全部使用已处理体力、位置等因素的 0～100 有效评分：

```text
precision = 0.75 × shooting + 0.25 × composure
attributeAdjust = clamp((precision - 50) × 0.002, -0.10, +0.10)

pOnTarget = clamp(
  sceneBase + attributeAdjust + residualAdjust,
  sceneFloor,
  sceneCeiling
)
```

`residualAdjust` 只包含尚未被场景分类覆盖的因素。距离、角度、干扰若已决定场景基础值，就不能再完整扣一次；逆足等可保留小修正。使场景不再成立的因素必须重新分类，而不是在“干净单刀”标签下施加巨大扣分。

例：相同干净单刀、无额外修正时，终结评分 35 的射正率约 82%，评分 75 约 90%。低射术不是必偏，高射术仍更可靠。相同终结评分 35，在基础 35% 的困难远射中仅约 32%，因此不能把单刀加成扩展成全局保底。

这是原型公式，不承诺终值。参数可以调整，但“高质量机会有明显保底、低射术不抹掉好机会”的原则不能被调参撤销。

## 7. 射正后进球：门将弱也必须有实际影响

继续使用四种互斥结果，一次抽样：

```text
封堵 = b
偏出 = (1-b) × (1-t)
扑救 = (1-b) × t × (1-g)
进球 = (1-b) × t × g
```

`t` 为上一节射正率，`g` 为未封堵且已射正时的进球率；四项相加为 1。`shotsOnTarget` 统计扑救＋进球，不把封堵一律计为射正。

修改约束：

- `b` 只包含有资格参与的外场封堵者；门将统一在抢先控制球或扑救阶段处理，不重复当作 blocker。
- `g` 以场景基础值、终结质量与门将能力的相对差、门将实际站位为主，避免继续用以 55 为中心的绝对进攻惩罚叠乘。
- 普通扑救使用反应与站位；**只有实际单刀才引入门将一对一能力**，不能所有射门都用。
- 干净单刀的条件进球基础值可先试 60%，普通禁区射门约 35%～45%，困难远射约 15%～30%；以实际场景、遮挡和门将覆盖修正。
- 原型可用 `g = clamp(sceneGoalBase + 0.003 × (finishQuality - keeperQuality) + coverageAdjust, 0.05, 0.95)`；可正常扑救的普通射门与单刀共用此形式，场景基础值不同。
- 门将无法覆盖的近距离开放球门另设高基础值，不允许一个已经失位的高属性门将隔空扑救；也不把“没有门将”回退成固定 45 分门将。
- `finishQuality` 与射正精度区分含义：前者决定已射正球的威胁，后者决定是否射向门框。复用射术时必须联合校准，不能复制同一成功率再乘一次。

示例：干净单刀、终结质量 35、门将质量 30、无覆盖修正，`g≈61.5%`。若 `t≈82%` 且无外场封堵，该脚进球率约 50%。门将质量改成 75 时，`g≈48%`，进球率约 39%。这是“低射术遇到弱门将仍有实质威胁”，不是必进。

## 8. 实施范围与顺序

### 第一步：固定基线与诊断字段

- `scripts/balance.ts`、`scripts/simulate.ts`：统一整场口径；加入弱弱、强强、强弱对照。
- `src/game/match/types.ts`、`src/game/types.ts`：按需给射门日志添加机会类型、实际距离/角度/压力、单刀判定原因、射正基础值/保底/最终值及扑救概率。
- 数据来源必须是出脚时实际状态，不能根据进没进反推“好机会”或失败原因。
- 第一阶段先复现基准，不与引擎修改混在一起；诊断脚本增加种子一致性、结果概率及输入不变的自检。

### 第二步：修动作与机会生成

- `src/game/match/engine.ts`：`openPlay`、`moveAll`、`desiredTarget`、带球对抗、直塞落点。
- 持球者与防守者同步计算，排除门将重复封堵。
- 对照输出危险区触球、单刀次数、推进成功率和射门次数；暂不同时上调射正，方便归因。

### 第三步：修选择与射门模型

- `chooseAction`、`passValue`：机会驱动射门与相对局面价值。
- `shotModel`、`resolveShot`：场景保底、正确单刀识别、相对扑救模型。
- `src/game/match/shooting.ts`：检查用脚、落点、力量/推射修正不会在保底后再次把最终射正率扣破下限；所有修正归一到一次最终 clamp。
- 决策估值与执行复用同一机会评估规则；允许因实际移动变更场景，必须记录变化。

### 兼容要求

- 新规则只用于新开比赛；已有进行中比赛不能静默切换算法或时间尺度。
- 为比赛规则标记版本。最小兼容方案是上线时先让活动比赛用旧引擎完成，再启动新规则；如果不能排空活动比赛，就必须保留旧规则恢复路径，不能只加版本字段却不处理它。
- 不重算历史比分、不修改球员永久属性、不重置培养进度。
- 历史日志缺少机会字段时展示“旧版未记录”，不能补造单刀数据。

## 9. 验证与验收

### 9.1 小场景测试：先证明机制正确

- 固定干净单刀：终结评分 25/35/50/75/95 的射正率都不低于有效场景保底，且随终结能力非递减。
- 相同低射术：单刀、空位近射显著优于困难远射；低射术不抹掉单刀优势。
- 防守人可到达射门通道时撤销干净单刀标签；来不及时不能远程干扰。
- 门将先得球不产生射门；门将失位时不能隔空覆盖。
- 仅降低门将能力，在固定射门状态下不能降低进球概率；不能改变射手的纯射正精度。
- 仅降低外场防守预判/速度，应在专用可达性场景中不更容易完成干扰或封堵。
- 先核验场景资格，再应用保底；极端逆足、强压、坏角度不能借用干净单刀标签。
- 检查场景边界连续性，以及技能、落点、脚法修正后的最终概率，不能只测试中间模型。
- 射术增强不降低固定场景射正率；四结果合法且总和为 1，只抽样一次。
- 同种子同版本日志一致；读档、离线补算不重抽本次射门；球权唯一、比赛必结束、进球不重复。

### 9.2 批量矩阵

至少三组，使用相同阵容骨架、技能、战术与一组固定种子，先每组 1000 场筛查，再对候选参数每组 10000 场确认：

1. 弱弱：主要有效能力约 30～45。
2. 强强：主要有效能力约 70～85。
3. 强弱：强队与弱队互换主客场。

另跑当前真实初始联赛和培养后的球队，不能只在所有人属性相同的人工球队上通过。保持属性形状与位置差异，明确有无体力、伤病、技能影响。

统计：整场射门、射正、进球、射正率、射门转化率、0:0/平局比例、危险区触球、单刀/空位次数、好机会放弃起脚次数、远射占比、传球方向与成功率、球权转换、终场体力、伤病率。对场均值和率报告置信区间，参数比较优先报告同种子的配对差异；不把单场胜负当作结论。

### 9.3 暂定整场体验目标

- 按完整 90 分钟语义，两队合计射门先以 **18～30 次**、场均总进球 **2～5 球**作为调试目标。
- 这些是分布均值目标，不是单场保底，也不是所有水平与战术组合必须一致达标。
- 弱弱组不得再次出现类似当前“场均三脚射门、约三分之二为 0:0”的系统性失活；若仍发生，必须用机会链统计定位，不能直接增大进球抽签概率。
- 干净单刀的最终条件射正率达到场景下限；有足够样本时实际频率应在统计误差内吻合，而不是要求每场单刀都射正。
- 强弱组强队应有明显优势，但不得通过让弱队几乎永远没有射门来凑强队胜率。
- 不允许为凑射门数出现大量无意义远射，也不允许为凑进球率把三次射门变成三次必进。

## 10. 交付与最终原则

本轮实施完成应交付：对应测试、可复现批量命令与参数、修改前后同口径报告、90 分钟时间语义说明、旧比赛处理方案，以及可从战报解释的射门概率拆分。

**先有真实空间与机会，再决定是否起脚，最后结算射正与扑救。弱防守通过送出好机会体现，低射术在好机会中有射正保底；强门将仍能救球，任何一方都不由总评分直接决定进球。**


## 11. 实施记录

### 11.1 已落地

- 比赛显示固定映射到 90:00（5400 秒）；新比赛逻辑时长为 900 秒，联赛现实推进固定约 600 秒。三者分别由 `displayClock`、`MatchState.clock` / `durationSeconds`、`leagueElapsed` 处理。
- 新比赛写入 `rulesVersion = 2`；没有版本字段的活动比赛恢复为旧射门模型与旧动作时序，历史记录不重算。
- 射门日志增加 `shotChance`：机会类型、基础射正、保底、上限、射正后进球基础值、实际距离/角度/压力、封堵人数和判定原因；`ratings` 保留最终射正、射正后进球、终结与门将评分。
- 干净单刀、近距空门、禁区空位、普通、困难、头球、任意球、点球分级；单刀/空门/空位保底分别为 78% / 90% / 65%。门将不进入外场封堵者列表，只有真实单刀使用门将一对一。
- 射门选择使用机会质量奖励，低射术不会因为预计进球率低而完全放弃单刀；传球价值改为相对推进价值；直塞接应者跑向预想落点；带球者与防守者同时移动；射门只给防守方准备段时间。
- 定时换人新输入为 `atMinute`（0–90），旧 `atSeconds` 按旧 10 分钟尺度兼容；UI、Agent/MCP、战报、文字直播和球员分钟统一按 90 分钟显示。
- 批量脚本 `npm run balance` 增加弱弱 / 强强 / 强弱矩阵，`MATRIX_MATCHES` 控制每组场次；`npm run sim` 增加机会类型、射正率、好机会放弃起脚统计。

### 11.2 验证结果

命令：

```bash
npm test
npm run build
npm run sim -- --matches=300 --seed=1
MATRIX_MATCHES=1000 npm run balance
```

- `npm test`：25 个测试文件、212 个测试全部通过（其中新增 10 个射门/时间/兼容机制测试）；`npm run build` 通过。
- 初始 AI 联赛 342 场：场均总射门 **22.25**、总进球 **2.92**、平局 **19.9%**、主胜 **40.1%**。
- 1000 场矩阵：弱弱 **24.90 射门 / 3.37 球**；强强 **26.55 / 3.78**；强弱 **30.37 / 4.98**。强弱组是 45 对 70 的极端压力组，强队仍有明显优势，弱队不是被锁死为零；该组射门略高于 30 的上沿，但总进球已回到 2–5。
- 300 场同阵容镜像：场均总射门 **22.22**、射正 **8.28**、总进球 **2.83**、射正率 **37.2%**、平局 **23.7%**；机会类型中 `clear_chance` 452 次进 244 球，`box_open` 139 次进 54 球，困难射门 3326 次进 136 球。该样本没有出现门将失位的开放球门；开放球门由专门小场景测试覆盖。

### 11.3 已知边界

- 场景边界采用窄区间参数插值，但不做完整物理碰撞；封堵只判断外场球员是否能到达射门通道。
- 旧活动比赛走旧射门模型与旧动作时序，不按新尺度重算已记录历史。
- 强弱压力组的射门数可能略高于 30；这是 45 对 70 极端属性差下的压力结果，总进球已控制在 2–5。
