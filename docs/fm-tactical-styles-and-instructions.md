## 一、战术风格

### 1. 控制球权

- **强度 / 复杂度：**高强度 / 平均复杂度。
- **风格：**掌控比赛主动，在进攻时保持耐心。重点是维持球权，丢球后尽快高位反抢，通过防守区域耐心地短传出球制造机会。
- **职员反馈：**优点是保持球权、主动积极进攻；缺点是防守区域短传出球存在风险、放缓进攻节奏。
- **持球阶段：**短传出球、破压推进、门将出球找中后卫、短传开门球、放慢节奏。
- **无球阶段：**后防线压上、高位逼抢、增加触发压迫、逼抢门将、转换阶段立即反抢。

### 2. 高位压迫

### 6. 长传冲吊

- **强度 / 复杂度：**高强度 / 低复杂度。

- **持球阶段：**很多直传、绕过压迫、尽早传中、造定位球、更加坚守纪律、大脚开门球、加快节奏、转换阶段立即反击。

## 三、融入当前足球引擎：设计建议

> 以下是针对本项目的**设计提案，不是现有功能或截图原始数据**。目标是让风格真正改变场上行为，同时保留球员能力、阵型和对手应对的影响；不把风格做成直接增加胜率的标签。

### 3.1 先看当前项目有什么

| 位置 | 当前情况 | 设计含义 |
| --- | --- | --- |
| `src/game/types.ts` | `Tactics` 只有进攻方向 `attack`、传球 `passing`、节奏 `tempo`、防线 `line`、压迫 `press` 五项，保存在 `Lineup.tactics`。 | 可以复用已有战术入口，但还没有独立的进攻宽度、逼抢线和攻防转换设置。 |
| `src/game/pes/game.ts:tacticsOf` | 将五项离散设置转换为 PES 的 `width / direct / tempo / line / press / aggression`。`attack` 目前被映射为宽度，`aggression` 由 `press` 推导。 | 「走边路」与「站得宽」目前是同一条近似映射；压迫频率与拼抢凶狠程度也没有独立控制。 |
| `src/game/pes/sim.ts` | 宽度、防线和压迫参与阵形目标；直传影响传球及接应；节奏影响决策反应时间；`updateShape` 每次分配一名上抢者和一名协防者。 | 应在站位、压迫分配和动作选择中实现新指令，而不只是改界面。当前压迫等级并不直接改变上抢人数。 |
| `src/game/pes/settle.ts`、`src/game/match/resolution.ts` | PES 的传球、对抗、射门等接触点由结算模型结合能力、位置、压力等裁决。 | 优先让战术改变球员选择和场上局面，不在动作选择和结算两处重复叠加同一战术加成。 |
| `src/game/condition.ts` | 比赛内体力受跑动等影响；联赛赛后跨场 `condition` 目前按出场分钟扣除，踢满 90 分钟固定扣 70。 | 高压可以先通过更多跑动消耗**比赛内体力**，不能宣称目前会按压迫强度额外扣跨场体能。 |
| `src/game/match/management.ts` | 当前临场「进攻 / 均衡 / 防守」会整体替换五项战术，而不是仅改变心态。 | 新模式应避免一键心态把用户设置的宽度、传球等全部冲掉；旧比赛仍保留旧语义。 |
| `src/game/match/setup.ts`、`server/match-job.ts` | 可展示比赛走 PES；纯 AI 对 AI 的后台比赛仍走 `MatchEngine` 的 v2 整步模拟。 | 不能只改 PES 就宣称所有比赛都已经支持新指令。 |
| `server/match-job.ts`、`src/ui/replay-2d.ts` | 联赛在锁阵后预计算；直播和赛后 2D 回放从开球快照重新模拟。 | 必须冻结规则和输入，并处理引擎升级后旧回放可能分叉的问题。 |

### 3.2 总体原则

1. **风格是可编辑的指令模板，不是额外属性。**选择风格时复制一组默认指令；之后用户可以逐项修改。风格本身不再暗中附加成功率。
2. **阵型、角色、风格、心态分开。**阵型决定基础站位和人数；角色决定球员职责；指令表达球队意图；心态只做受限的临场倾向调整。链式防守可以推荐三中卫，但不强制更换阵型和球员。
3. **有收益也有代价。**高压更可能就地夺回球，但需要跑动、可能暴露身后；短传可能更安全，但会受压迫、距离和球员能力制约；长传推进快，也更容易失去球权。不要保证某风格必胜。
4. **不做无效按钮。**截图里某些选项目前没有对应机制，应标为「规划中」或暂不展示，不能保存后假装生效。
5. **先做可观察、可回归的小版本。**先复用五项战术并补足关键缺口，再逐步扩展门将、传中、犯规倾向等，不一次照搬所有 FM 指令。

### 3.3 数据模型和优先级

建议把新的球队战术作为 `Lineup.tactics` 的**版本化新分支**，保留现在的五字段旧结构。下面是第一阶段的示意，不代表现有代码已经提供这些类型：

```ts
type TacticalInstructionsV2 = {
  possession: {
    focus: 'middle' | 'balanced' | 'wing'       // 进攻方向
    passing: 'short' | 'mixed' | 'direct'        // 传球倾向
    tempo: 'slow' | 'normal' | 'fast'            // 节奏
    width: 'narrow' | 'normal' | 'wide'          // 进攻阵形宽度
  }
  transition: {
    onGain: 'counter' | 'balanced' | 'hold'     // 得球后
    onLoss: 'counterpress' | 'balanced' | 'regroup' // 丢球后
  }
  defense: {
    line: 'low' | 'mid' | 'high'                // 后防线
    engagement: 'low' | 'mid' | 'high'          // 开始逼抢的区域
    intensity: 'low' | 'mid' | 'high'           // 该区域内的压迫频率
  }
}

type ModernTactics = {
  schema: 2
  baseStyle: { id: string; revision: number } | null // 仅用于来源展示
  instructions: TacticalInstructionsV2             // 当前权威值
}
// Lineup.tactics = 旧五字段 Tactics | ModernTactics
```

- 上面的 `schema: 2` 是**战术数据结构版本**，不是比赛 `rulesVersion`，也不是游戏存档版本。最终类型名可以随实现调整。
- **唯一生效真值是已展开的 `instructions`。**应用模板时复制全部字段；用户修改后显示「高位压迫 · 已调整」。模板以后更新不反向改写已保存阵容或正在进行的比赛，`baseStyle.revision` 只记录来源。实现上保留可按 `id + revision` 查询的不可变历史模板，并与当前指令逐项比较；全部改回基准值则取消「已调整」。找不到历史模板时显示「自定义」，不能误报未调整。重新应用模板应提示会覆盖手动修改。
- 「空白」是没有风格来源的自定义配置；各字段仍有明确的中性值，不能以 `undefined` 暗中依赖未来可能变化的默认值。这里的中性值是本项目设计，不是截图提供的完整默认值。
- 现有**命名战术预设**实际上保存阵型、球员、替补、自定义位置和战术的整套快照（`src/game/squad.ts:snapshotLineup`）；它和上面的「风格模板」不是同一回事。保留原行为，应用时仍要校验球员和槽位。
- 赛前和比赛中分开：赛前可编辑完整指令；非预计算比赛中的心态是一个**临时层**。建议从赛前指令重新计算，均衡不改赛前值，进攻 / 防守只对明确公布的风险和站位倾向做有限偏移，不覆盖原始指令。重复切换不能累计偏移；比赛结束不改赛前配置。
- 对旧结构保留兼容映射：旧 `attack` 仍按现有方式决定 PES 宽度，旧 `press` 仍派生 `aggression`，新增独立行为默认不施加或走旧行为分支。只有用户主动选择新风格或转换为新配置时，才暴露可分别调整的方向、宽度、逼抢线和频率；转换预览要提示可能产生行为变化。规则版本是**整场比赛**的，不是两边各跑一个物理引擎：旧配置进入新规则比赛时使用兼容适配，但受新规则及对手行为影响，不能保证新场次与 v4 比分逐场一致；已开始的 v4 比赛和旧回放仍按 v4 恢复。

### 3.4 第一阶段建议开放哪些指令

| 类别 | 指令 | 引擎实现建议 | 阶段 |
| --- | --- | --- | --- |
| 持球 | 进攻方向、传球倾向、节奏 | 在现有方向、传球评分和 `reactionTime` 基础上调整；方向和宽度分开，快节奏不能当作凭空增加球员能力。 | 首版 |
| 持球 | 进攻宽度 | 只控制持球时队形的横向展开与接应距离；限制在场地内，防止重叠和离场。 | 首版 |

| 转换 | 丢球后反抢 / 均衡 / 回撤 | 在有限窗口内调整最近球员的上抢或回位任务，不能无条件持续全场。 | 首版 |

第一阶段先用短 / 混合 / 直接、慢 / 正常 / 快等三级，截图里的「极快」「大量短传」暂映射到相应极端档。后续只有在引擎行为和测试足够区分时才增加五级。**未实现的截图指令不进入首版模板的生效值，也不暗中折算成其他功能。**

### 3.6 怎么接进 PES 比赛行为

**1. 阵形与空间。**在 `src/game/pes/sim.ts:formationTarget` 中区分持球宽度和无球队形；后防线控制后卫的目标深度，逼抢线控制前场何处启动压迫，压迫频率控制触发与持续。进攻方向应影响传球、接应的区域偏好，而不是单纯把它等同于宽度。自定义摆位仍作为基础锚点，战术只在锚点上做有限偏移，并保留场地边界、门将、越位和最小间距约束。

**2. 压迫与代价。**扩展 `updateShape`：在逼抢区域和满足距离、体力条件时，从可用球员中选上抢者及协防；频率高时更积极地分配任务，低时优先守住位置。不能只调整一个 `press` 数字而让低位队也全场追球。增加的移动距离和速度应自然进入现有疲劳公式，避免再给体力加第二次固定惩罚。凶狠拼抢是后续独立选项，不应继续默认等同于高压。

**3. 传球和进攻选择。**在 `passValue`、`decideOnBall` 等处对候选动作加入**有限的倾向分**：短传更偏近距离支援，直接传球更愿意选择向前或较远的接球点，边路进攻更偏向可行的边路候选。仍由实际路线、距离、对手、球员能力和结算模型决定结果；好射门机会、越位和明显危险的回传不能被战术倾向简单覆盖。数值需要校准，不能预设为额外成功率。

**4. 攻防转换需要显式状态。**建议在 PES 快照中记录每队最近一次稳定控球归属、转换类型及窗口截止时刻。传球飞行时 `ball.owner = -1`，不能把每次无主球都当成失球；应结合触球、传球元数据和实际获得控制来确认转换，避免连续反复触发。死球、中场及终场清理窗口；抢回后短时间内失去又获得球权也要有明确规则。

作为测试起点，在默认 `D = 900` 模拟秒的比赛里，转换窗口可试 **1–2 个模拟秒**，约对应显示比赛时间 6–12 秒；这是待标定参数，并非截图数据。其他时长必须显式定义时间缩放并测试，不要把显示秒数和模拟秒数混用。窗口、时刻、球队归属及相关随机状态都需要序列化，确保读档后从同一阶段继续。

**5. 不要重复加成。**例如「高压」通过更合理的追抢站位制造实际压力；传球错误率由已有结算看到的压力、路线和属性产生。不要再给同一次传球额外乘一个「高压必定失误」系数。对 `tempo` 现有直接缩短反应时间的行为，也应重新校准上限，避免快节奏同时得到无代价的反应优势和额外全队能力加成。

### 3.7 赛前、临场和界面

- 在 `src/ui/screens/lineup.ts` 保留阵型与现有命名预设；新增「风格模板」入口和「持球 / 转换 / 无球」分组。选择模板显示核心指令、预计强度和风险；用户可逐项编辑。首版不展示实际无效的门将、传中等高级按钮。
- 切换阵型不自动重置已选择的风格或指令；需要手动确认才应用某阵型的默认战术。自动排阵和换人只更改人员，不应丢失战术。
- 阵容提示用作建议而非硬限制。例如高压看体能和阵容深度，短传看传球及技术，链式防守推荐但不强制三中卫；提示应与项目实际属性和已实现机制对应。
- 对非预计算比赛，首版可以只支持现有的三个临场心态，采用 3.3 的临时层；高级逐项临场调整留到事件记录和重放支持完成后再开放。不能误让新逻辑改变已有 v4 比赛的心态语义。
- 线上联赛目前是**锁阵后预先算完、开球后播放**：界面应明确该场只能观看，锁阵后的战术修改用于后续比赛。服务端也应显式拒绝对 `preplayed` 比赛的战术和换人操作，不能只靠隐藏按钮。若以后要让线上联赛真实临场调整，需要改成服务端权威实时模拟或可重算架构，不能只改 UI。
- 若非预计算比赛将来支持逐项临场修改：服务端或本地权威端先校验、分配确定性的模拟时刻及同刻顺序，再记录球队、修改前后值和动作；保存、恢复和回放都在相同物理步重放。仅有开球快照或文字播报不足以重建这些操作。

### 3.8 兼容存档、AI、联赛和回放

1. **旧阵容与预设：**旧五字段结构继续可读、可比赛，不自动替换为某个风格。覆盖玩家阵容、命名预设、AI 阵容、杯赛参赛者快照和已有活跃比赛；`autoFillLineup`、轮换和 `preservedExtras` 等路径也要检查，避免丢字段。旧到新的转换必须显式、可预览。
2. **统一校验：**客户端可以提前提示，但服务端才是可信边界。`server/agent.ts:isTactics / parseLineup` 目前只识别五项，整档 `PUT /api/game` 也不能依赖 TypeScript 类型；需要统一校验新旧结构、枚举、嵌套对象、未知字段和长度。无效数据返回错误，不能静默写入后让映射产生 `undefined`。调整 Agent 接口及 `docs/agent-api.md`。
3. **旧客户端：**旧页面整档保存可能覆盖新字段，单靠 `baseRevision` 不足以解决。建议上线时增加客户端能力 / 版本检查：不理解新战术结构的客户端拒绝相关写入并提示刷新；升级顺序和回滚策略需与服务端一起发布。`GAME_VERSION`、战术 schema 和引擎版本分别迁移，不能互相代替。
4. **锁阵快照：**战术留在 `Lineup` 内并跟随 `LockedTeam` 深拷贝；锁阵前修改影响本场，锁阵后只影响未来比赛。新队列任务一经创建就冻结已展开指令、阵容、随机种子及规则版本，不因模板更新或客户端提交而改变。现有 `MatchJob` 尚无规则版本字段：升级时对缺字段的旧任务按原选择逻辑固定版本——至少一方有教练为 PES v4，纯 AI 对 AI 为旧引擎 v2；升级前已入队但未计算的任务及重试都必须继续使用对应旧实现。
5. **两套引擎：**首版先让玩家可见的 PES 比赛使用新配置；后台纯 AI 对 AI 保持旧配置和 v2 行为，暂不把新模板分配给只走旧引擎的 AI。未来若要全面使用，需为旧引擎做明确的有损投影并验证统计差异，或评估全量改用 PES 的成本；不能说二者逐场等价。`AITeam` 顶层战术和 `lineup.tactics` 的优先级也要统一。
6. **PvE 和杯赛：**`src/game/pve-content.ts` 使用带版本和哈希的冻结快照，已有杯赛还可能保存参赛球队快照。新模板先用于新生成内容；旧挑战 / 已开始杯赛按原快照继续，若决定迁移或重冻，需同时更新内容版本、资产、缓存和服务端部署，并重新跑平衡测试。
7. **比赛规则与历史回放：**现有 PES 是 `rulesVersion: 4`；新模拟建议使用新规则版本，并保留 v4 的实际计算实现和版本路由，不能只把标签改成 5。初始快照、进行中比赛和队列任务都带其实际规则版本；旧比赛用旧算法恢复，新增的转换窗口和临场事件也要保存。随机数调用顺序变化同样可能让历史比分分叉。若无法保留旧实现，应采用包含足够帧 / 事件的独立回放方案，或明确停止支持旧回放，不能承诺同 seed 必然一致。

### 3.9 实施顺序与验收

| 阶段 | 工作 | 主要验收 |
| --- | --- | --- |
| 0. 固化基线 | 固定种子样本、记录现有比分和行为；建立 PES v4 版本隔离、旧档和回放测试。 | 升级后旧进行中比赛与历史回放仍可按旧规则恢复；不以改版本号代替旧实现。 |
| 1. 模型与首版行为 | 加战术 schema、模板、校验和迁移；实现方向 / 宽度分离、逼抢线 / 频率、攻防转换；接入战术页和非预计算比赛心态。 | 每个开放项都能在场上产生可观测区别；旧五项配置不被静默替换；保存、自动排阵、预设和锁阵往返不丢数据。 |
| 2. 平衡与发布 | 运行多对手、多阵型、主客互换的批量模拟，更新 PvE 内容策略；评估后台引擎和性能。 | 高压、控球、防反有方向性的行为差异，也有代价；没有明显万能模板，赛果、进球、体力分布不出现不可接受的偏移。 |
| 3. 高级指令 | 按需增加传中、门将出球、拼抢等；具备事件时间线后再讨论更多临场操作。 | 每增加一项均有机制、解释、确定性及回归测试；未实现项继续隐藏或标明规划中。 |

**建议的具体测试：**

- **单元与边界：**模板每一项都合法；应用模板后手改、再次应用、复制预设和旧档往返的结果符合优先级；非法 API 输入被拒绝；宽度与方向、逼抢线与频率能分别调整；心态切换不累计偏移。
- **确定性：**同一规则、种子、输入和指令时间线，连续运行与中途序列化 / 恢复应得到一致结果；包含传球飞行中的无主球、转换窗口中途存档、死球、中场、红牌、换人和主客换边。固定 v4 历史样本验证旧比分与关键事件不变。
- **行为指标：**相同球员、阵型和对手，分别对比短传 / 直接、窄 / 宽、高 / 低逼抢、反抢 / 回撤。记录平均传球距离、向前传比例、球队横向宽度、夺回球的位置与时间、转换后推进、跑动和比赛内剩余体力。缺少的指标先在测试 / 调试统计中增加，不要仅用胜率判断。
- **平衡实验：**使用多组对手及阵容，主客互换、配对种子并报告均值和区间；持续监控控球率、传球成功率、射门、xG、比分、犯规和跑动。建议先跑小规模回归，再用更大样本校准；随机比赛不应要求每一场都严格符合某个趋势。
- **线上和兼容：**测试锁阵前后、旧客户端写入、服务器校验、AI 轮换、PvE 旧快照、队列升级前后、双方联赛记录及直播 / 回放比分一致。检查 `src/game/season.ts` 和 `server/match-job.ts` 两条赛后体能结算路径；如果以后引入跨场高压消耗，必须两端统一并单独平衡，不能只改其中一处。
- **项目命令：**实现后运行 `npm run typecheck`、相关 Vitest 测试和 `npm test`；涉及 PvE 参数时运行 `npm run balance:pve` 并检查冻结内容及平衡报告。本文目前只是设计，尚未实现或验证上述效果。

## 四、各战术风格的效果范围与验证规格

> **交给实现者和验证者的契约。**本节的参数、效果范围和战术克制关系都是待验证的设计假设，**不是已有引擎的实测数据，也不是给球队直接加减的胜率、进球或 xG**。当前 PES v4 还不具备第三节列出的全部独立指令和埋点；在实现前，本节完整验收的正确结论应为「尚未实现 / 无法测量」，不能把现有五项近似结果说成新风格已通过。
>
> 每种风格使用 **3.5 的完整模板**。模板共同作用于球员行为；不同风格的数值表现由这些指令、阵容及对手共同产生，不另写 `if (styleId === …) 加能力 / 加胜率`。`空白`是同规则下的新模型中性配置，**不是**旧 PES v4，也不保证拥有全场 50% 控球或中等水平。

### 4.1 指令怎样产生可控的实际效果

下表给出可供实现、调参和复核的**初始参数范围**。范围是工程建议，首选值便于第一轮实验；效果不符时先检查实现和统计口径，再通过训练集调参，不能按比赛结果硬塞进球奖励。

| 指令 | 首选实现与可调范围 | 对现有引擎的约束 |
| --- | --- | --- |
| 短传 / 混合 / 直接 | 针对候选传球，令 `p=-1/0/+1`，`d` 为出脚者到候选接球人距离，`S传球 = wP × p × (clamp(d / (40K), 0, 1) - 0.5)`；`wP` 首选 `0.08`，可调 `0.04–0.10`。短传偏近、直接传偏远，绝不是改变传球成功概率。 | 新规则中，以当前 `passValue` 在 `direct=0.5` 时的评分为基底，再加本项；不要再把旧 `direct` 对同一候选的直接加分叠一次。现有跑位的直传影响也要单独记录和校准。`K` 是 `PitchSpec.K`。 |
| 中路 / 均衡 / 边路 | 候选接球人横向位置 `z=clamp(abs(y)/(HW-2.5),0,1)`，`f=-1/0/+1`，`S方向 = wF × f × (z-0.5)`；`wF` 首选 `0.08`，可调 `0.04–0.10`。只作为可行传球 / 接应的偏好。 | `f=-1` 偏中路，`+1` 偏边路；需要边界、越位与射门机会约束。不可再把方向直接当宽度处理。 |
| 窄 / 正常 / 宽 | 在**持球阶段**先算正常宽度的外场球员目标横坐标 `yBase`，求这些目标的球队中心 `yCenter`，再用 `yCenter + (yBase - yCenter) × (1 + wW × {-1,0,+1})`；`wW` 首选 `0.15`，可调 `0.10–0.20`。最终坐标裁到场内。 | 围绕球队目标中心展开，避免将整体随球移动误当宽度；接应和前插目标也应用同一规则，每个目标只缩放一次。要测试球在两侧边线时的裁剪与接应。这是持球宽度，不等于无球防线收缩。 |
| 慢 / 正常 / 快 | 第一轮沿用 `tacticsOf` 的 `0.25 / 0.50 / 0.80` 和现有反应时间公式；统计真实动作决策间隔，评估快节奏是否过强。 | 不额外加传球、跑速或射门属性；如调整现有公式，必须记录新系数和规则版本。 |
| 低 / 中 / 高防线 | 第一轮沿用 `tacticsOf` 的 `0.20 / 0.50 / 0.80`，由 `formationTarget` 的防线计算产生实际位置差异。 | 这里的值是无量纲输入，**不是直接前移 20/50/80 米**。不同球位置和阵型会影响实际防线高度。 |
| 低 / 中 / 高逼抢线 | 在防守队朝对方球门进攻的方向上，`u = (ball.x × team.dir + HL) / L`，其中 `u=0` 为本方球门线、`u=1` 为对方球门线；常规逼抢只在球的 `u` 不超过阈值时允许发起。低 / 中 / 高首选 `0.35 / 0.60 / 0.90`，各允许上下调 `0.05` 并限制在 `[0,1]`。 | 阈值越高，允许球队在离对方球门更近的位置开始压迫；这是**允许区域**，不是强制一直追球。`team.dir` 随主客和半场变化，需分别测试；门将或死球不自动成为压迫目标。 |
| 低 / 中 / 高压迫频率 | 合格上抢者的搜索距离建议分别为 `8–10 / 10–13 / 13–16` 米；最多上抢人数分别为 `1 / 1 / 2`。首选 `9 / 12 / 15` 米。 | 距离指实际物理距离，11 人制为准；候选还要满足区域、可达性和体力条件，并留出至少两名外场球员不承担上抢任务（人数不足时相应降额）。不要把频率自动当成凶狠拼抢。 |
| 得球后保持 / 均衡 / 反击 | 得球转换窗口内，令 `q=-1/0/+1`、`forward` 为候选传球朝对方球门的纵向位移，`S转换 = wT × q × clamp(forward/(20K),-1,1)`；`wT` 首选 `0.06`，可调 `0.03–0.08`。在原前插条件满足时，前插尝试概率由 `0.12` 分别改为 `0.08 / 0.12 / 0.16`。 | `q=-1` 降低向前传倾向并偏向回传，**不等于保证安全**；对纵向回传超过 `2K` 且传球线净空不足 `1.5K` 的候选，禁止产生正的 `S转换`，原有路线、压力评分仍生效。`+1` 偏向前，均衡不叠加本项；前插还受原有人数、越位、体力和空间限制，不得强制前插。 |
| 丢球后回撤 / 均衡 / 反抢 | 在转换窗口内，反抢优先让附近符合条件的球员上抢，回撤优先恢复防守位置；反抢可临时越过常规逼抢线，但仍受搜索距离和人数上限约束。 | 只改变任务与移动，体能仍按实际跑动结算；不直接提高抢断成功率。 |

`S传球 + S方向 + S转换` 的总额建议裁剪到 `[-0.10,+0.10]`，单位与现有候选动作评分相同；对原有明确拒绝的候选不加分，单刀限制、边界和危险回传保护继续生效。现有候选越位主要是软扣分，最终还受越位开关与技能影响，**不能误称越位或整个禁区已是统一硬约束**；第一轮沿用现有判定顺序并专测越位候选与技能，不新增一条会否决越位开关或技能的隐藏硬规则。以上公式只用于**新规则分支**；v4 的计算、随机数调用顺序和历史回放不因此改写。新配置中的球门球、传中类型、凶狠拼抢等仍按 3.4 暂不承诺。

为避免把新旧战术影响叠加两遍，新规则的 `width` 和 `focus` 应以旧 `tactics.width=0.5` 的持球目标为基底，只应用上表的方向与宽度调整；新规则的防线基底中，将旧 `press` 对阵形的连带位移固定为 `0.5`，再由新的逼抢线 / 频率分配任务。特别注意，当前 `SettlementKernel.foulShare` 直接读取 `opp.tactics.press`，并影响盘带对抗的犯规 / 抢断分配；新规则的**新结构球队**须在该结算路径固定采用旧 `press=mid` 的基线，不随新频率额外改变凶狠程度。应按每支球队构造版本化的结算兼容视图或适配器：新结构暴露有效的 `press=mid` 给共享结算内核，且不覆盖权威的独立指令；旧结构仍映射它自己的 `press`。盘带对抗和战术犯规两条路径都使用这个视图，不能直接将嵌套新结构当旧五字段读取，否则可能产生 `PRESS_LEVEL[undefined]` / `NaN`；要测试新旧结构双方混合对阵。历史 v4 保留旧语义。应以固定球员和局面的结算单元测试证明：只改新频率、不改局面时，原始抢断 / 犯规结算概率不变；全场概率和犯规次数仍可因实际位置、接触和球员变化而变化。

**上抢调度的首版可执行起点：**开放比赛由防守方持球对手作为目标，每 `0.25` 模拟秒或在球权转换时重评；仅在规定逼抢区域、搜索半径内、未被罚下且不为门将的外场球员中选择。候选需 `stamina ≥ 0.20`、未被眩晕，按距持球人距离升序、再按 `pid` 升序选最多 `1 / 1 / 2` 人，且留出至少两名外场球员不承担上抢任务；不可达或已有拦截等优先任务时跳过该候选。回撤窗口取消常规上抢并恢复原防守目标，反抢窗口将搜索半径加 `3` 米、上限 `18` 米并暂时忽略逼抢线，人数上限不变；均衡不作转换修正。所有档位对距离持球人不超过 `3` 米的合格球员允许最多一名紧急上抢，防止禁区内完全不防守；该人计入而不额外突破人数和留人上限。无持球目标时不凭空安排上抢。任务并非瞬时抢断，实际跑动、接触与对抗仍走物理 / 结算模型；调度时钟、选择结果进入快照。人数和距离限制只约束**主动追持球人**的上抢任务，不表示其他球员完全不能跟防或近身抢断：已有拦截、合法盯人和无主球争抢走各自规则，近身 `tryTackles` 仍按实际接触结算；紧急防守例外也不代表无限制追球。实现时须显式区分这些任务和优先级，否则不能把盯人 / 争抢人数当成调度器人数。固定局面测试应检查区域、半径、并列排序、留人、窗口结束和紧急例外。

**固定局面算例：**标准场地 `K=1`，除传球倾向外全部中性、其他评分和随机扰动固定。传球距离为 `10m` / `30m` 的两个候选，短传给出的 `S传球` 分别是 `+0.02 / −0.02`，直接传球则是 `−0.02 / +0.02`。若两候选原评分分别为 `0.50 / 0.51`，短传后为 `0.52 / 0.49`，直接传后为 `0.48 / 0.53`；只说明**选择偏好可能反转**，并不代表传球必然成功。再分别启用方向和转换项，验证三项合计被裁到 `±0.10`，不能用该算例推断整场统计。

**转换判定建议固定如下，便于不同验证者得到同一口径：**

1. 在开放比赛中维护「最近确认控球队」和独立的「候选新控球队」。另一队球员第一次取得 `ball.owner` 时记为候选起点 `t0`，立即进入**暂定**得球 / 失球转换；若原控球队随后取得实际控制，或尚未确认即死球，则取消候选，不回滚已经发生的合法动作。
2. 候选球队实际持球，或在有效的同队传球 / 传中飞行中保持预计接球归属，累计 `0.20` 模拟秒后确认换队；若候选球员实际控球后主动传球、传中或射门，则在出脚时立即确认，避免遗漏一脚反击。同队接球人变化不重置计时；其他无主球暂停计时，原控球队取得实际控制则取消。按第一次实际取得控制的 `t0` 记录转换起点并回填供统计使用；未确认即死球的候选单独报告。
3. 窗口从 `t0` 开始，默认整场 `D=900` 时长 `1.5` 模拟秒，约对应显示钟 `9` 秒。新候选一出现就**暂时挂起**之前尚未结束的窗口，双方只执行新候选的暂定转换；新候选确认则永久替换旧窗口。新候选被取消时，若旧窗口原截止时间尚未到、且没有死球 / 半场，则恢复旧窗口但不延长截止时间，不能回滚已发生的动作。新候选到 `t0 + 1.5` 尚未确认就超时取消；若之后重新实际取得控制，则从新时刻开始新的候选。其他整场时长的窗口及超时按 `1.5 × D / 900` 缩放；本节实验先固定 `D=900`。开球、界外球等死球和半场结束立即清除候选、挂起及窗口；死球后的首次控球用于建立归属，不当作开放比赛中的夺回。
4. 「最近确认归属」不等于实际控球统计。给 `W` / `DL` / `HLR` 的**稳定控球暴露时间**只在开放比赛中累计：本方实际持球，或本方有效的同队传球 / 传中飞行且在 `looseT ≤ 4` 内，均计给最近确认球队；对方候选未确认、其他无主球、射门、死球和半场时不计给任何一方。候选短暂抢断被取消后，从原队再次实际控球起恢复计时，不回填模糊时段。
5. 活动窗口、被挂起窗口及其原截止时间、候选球队、`t0`、已累计确认时长、上次确认球队及随机数都进入快照，恢复后逐位一致。反抢 / 回撤的物理行为由实际球员移动产生，不赋予自动抢回球的结果。已有 `PesSettlement.secondWindUsed` 当前未随 `toJSON()` 保存，拥有 `lg_second_win` 的球员恢复后可能再次触发：新规则也须序列化该状态，并实测技能触发前后存档恢复；不能只保存新增战术字段就声称全部恢复确定。v4 历史路由如何处理该既有问题需单独决策，不能无声改写旧回放行为。

### 4.2 统一指标与分母

下列指标用于 4.3 的所有目标，均区分主客进攻方向并在下半场换边时转换。标注「需埋点」表示现有汇总不能直接可靠算出；埋点必须只观察、不改变决策或消耗额外随机数。

| 缩写 | 定义 | 当前可用性 |
| --- | --- | --- |
| `PL` | 开放比赛中，非门将每次**传球尝试**出脚点到当时预定接球人位置的距离，先算每场均值，单位米；不只统计成功传球。 | **需埋点**传球时的起点与目标位置。 |
| `W` | 本方稳定控球暴露期间，每模拟秒对在场外场球员世界坐标的 `y` 取 `P90-P10`，再算每场均值，单位米；少于 8 名外场球员的采样时刻不计，并单独报告红牌。 | **需埋点**位置与稳定控球状态。 |
| `HLR` | 在本方进攻方向的最后 1/3 场地（`u ≥ 2/3`）确认的开放比赛夺回球权次数，位置取候选开始时 `t0` 的球位置；除以对手稳定控球暴露的显示分钟，再乘 `10`，单位「次 / 对手控球 10 分钟」。 | **需埋点**确认夺回、`t0` 位置和对手控球暴露时间。 |
| `EF` | 每次开放比赛确认夺回球权，**从回填后的实际起点 `t0`** 到 `1.5` 模拟秒窗口结束、对手下一次取得实际控制、射门或死球中最先发生者为止，至少尝试一次向前 `≥5K` 米的传球的夺回次数 / 全部这类夺回次数，单位 `%`；11 人制 `K=1` 时门槛是 5 米。 | **需埋点**转换、传球方向和终止原因。窗口中途射门或死球视为一个确定的竞争结果，若此前无符合条件的传球则计入分母但不计入分子。 |
| `CF` | 开放比赛中非门将传球尝试，以出脚时预定接球人 `abs(y) ≤ HW/3` 判为中路；中路尝试数 / 全部此类尝试数，单位 `%`。 | **需埋点**传球时目标位置。 |
| `DL` | 对手稳定控球暴露期间，每模拟秒取本方在场后卫及低位中场槽位的进攻方向坐标均值，再求每场均值，单位米；坐标以己方球门线为 0，越大越靠前。槽位用**开赛阵型**中 `formationRows` 的 `line ≤ 0.35` 且非 GK 定义，可能包含后腰；换人继承槽位，无合格球员时该采样不计。 | **需埋点**位置、槽位和稳定控球状态；报告红牌与可用采样数。 |
| `Stam` | 固定的原首发外场球员在踢满整场时的期末体力百分数；同时对**全部**原首发报告起始体力、离场时体力、在场时间、距离和离场原因，并按在场时间标准化消耗。完整比赛者可能因红牌产生选择偏差，只作为补充。 | PES 有球员体力和距离；需核对换人、红牌的可比性。 |
| `xGD` | 本队模型 xG 减对手模型 xG，按场统计；与实际净胜球、胜平负并列报告。 | 现有 `state.stats` 可得；这是本项目模型的概率之和，不等于现实足球的经验证 xG。 |

- **Δ** 表示「所测风格 − 指定对照」。`PL` 的相对变化为 `100 × (风格组均值 / 对照组均值 − 1)%`；`EF`、`CF` 和控球率之差使用**百分点 pp**；`W`、`DL` 用米，`HLR` 用上表的速率差。
- `HLR` 以所有相同条件比赛的夺回次数总和 / 对手稳定控球时间总和计算，bootstrap 时整块重算；其他每场均值先按主客平均，再对种子平均。若 `PL`、`EF`、`CF` 某场没有分母，或 `HLR` 对手暴露时间为零，该项记为缺失，报告缺失数量，不能当成 0。样本不足以估计时结论为**不确定**。
- 控球率按双方**有实际持球人**的累计时间归一化，飞行中的无主球不计入该分母；不要重复归一化。比赛内体力 `Stam` 不是跨场 `condition`：当前跨场体能仍按出场分钟扣除。
- 开放比赛指标：每次定位球 / 开球 / 界外球开始时置「非开放」，直到发球后有球队按上述累计 `0.20` 秒或主动出脚的规则首次确认稳定控球，**从该确认时刻之后的动作起**才恢复开放比赛；触发首次确认的那一脚仍属于定位球阶段。因此开出的第一脚、角球和任意球直接传中 / 射门都不计入开放比赛分母。再次死球、中场或终场又置「非开放」。整场 `xGD`、进球和胜平负包含常规时间内的定位球；所有实验固定无点球大战，定位球子项单独报告。

### 4.3 每种风格：行为目标、结果假设和代价

行为目标的范围是对**均值差**的初步期望区间，允许调整；「最小有意义差异」是用来判断效果是否大到值得保留的预注册门槛，不是逐场必须达到的数值。表中 `xGD` 区间仅用于平衡探索，**不是行为验收硬门槛**：区间内也可能无效，区间外也不自动证明代码有错。

统一对照 `B0`：本队使用 3.5 的「空白 / 自定义」全中性值、对手和阵容不变；特殊对照在表中明确指定。目标按 4.5 的镜像、技术型和速度型三种实验场景分别报告，同时报告三场景等权总体，不只挑选最有利的一组。

| 风格 / 对照 | 主要行为目标：Δ目标范围；最小有意义差异 | 初步结果假设：Δ`xGD` / 场 | 必看代价或失败方式 |
| --- | --- | --- | --- |
| 控制球权 / B0 | `PL` **−18% 至 −6%**；至少缩短 `3%`。 | **−0.10 至 +0.15**。 | 统计控球率（探索目标 `+1 至 +6 pp`）、传球成功率、后场被抢；被高压时短传未必更安全。 |
| 高位压迫 / B0 | `HLR` **+0.5 至 +3.0 次 / 对手控球 10 分钟**；至少 `+0.25`。 | **−0.10 至 +0.20**。 | 高位夺回后的射门、对手打身后 xG、跑动及 `Stam`；高压不应同时免费提高抢断成功率和跨场体能。 |
| 密集短传 / 控制球权 | `EF` **−10 至 −3 pp**；至少减少 `2 pp`。两模板在 3.5 只差得球转换，因此这是对「保持队形」的直接检验。 | **−0.15 至 +0.10**。 | 得球后保持控球与推进速度、对手落位时间；不能把少向前传直接当作更会控球。 |
| 垂直密集短传 / 密集短传 | `CF` **+6 至 +18 pp**；至少增加 `3 pp`。 | **−0.10 至 +0.20**。 | 同时看 `W`、`EF`、中路被拦截；其方向、宽度和转换均改变，本行不是某单项的因果证明。 |
| 双翼齐飞 / B0 | `W` **+3 至 +8 米**；至少增加 `1.5` 米。 | **−0.10 至 +0.20**。 | 记录边路接球与现有传中次数、丢球及边路空当；首版不保证套上或指定传中类型。 |
| 长传冲吊 / B0 | `PL` **+8% 至 +25%**；至少增加 `4%`。 | **−0.15 至 +0.15**。 | 统计向前推进时间、长传完成率与第二落点后得失球；长传不必然都是高球或争顶。 |
| 灵活防反 / 快速防反 | `PL` **−25% 至 −10%**；至少缩短 `4%`。 | **−0.10 至 +0.15**。 | 看得球后推进、失球后反抢与回防空间；两者不仅传球不同，逼抢线和失球转换也不同。 |
| 快速防反 / B0 | `EF` **+4 至 +15 pp**；至少增加 `2 pp`。 | **−0.10 至 +0.20**。 | 看低位夺回后的推进、尝试传球成功率、对手持续占据前场的时间；低位逼抢线不等于低压迫频率。 |
| 链式防守 / B0 | `DL` **−10 至 −3 米**；至少后撤 `1.5` 米。 | **−0.20 至 +0.05**。 | 看禁区射门、对手总 xG、边路与己方机会；首版不会自动换成三中卫，也没有独立无球宽度指令。 |
| 摆大巴 / 链式防守 | `EF` **−12 至 −3 pp**；至少减少 `2 pp`。两模板在 3.5 只差得球转换。 | **−0.20 至 +0.05**。 | 看己方射门、对手长时间围攻和禁区机会；首版的窄宽度只影响持球，不能假称已实现「无球密集站位」。 |
| 空白 / 相同中性指令 | 风格元数据或标签不同但实际指令相同，比分、物理事件流、RNG 状态和**去除已声明来源元数据后的**模拟快照应逐位一致。 | **0**，作为确定性要求而非统计区间。 | `baseStyle` 等来源元数据可以不同且须正确保存恢复；不得有隐藏的风格加成或因标签不同额外消耗随机数。 |

例如：对照组 `PL=20m`、风格组 `PL=18m`，则相对变化为 `−10%`；对照 `EF=30%`、风格 `EF=35%`，则为 `+5 pp`。密集短传 / 控制球权与摆大巴 / 链式防守的比较检验的是单项改变对**总体 EF 的因果效应**，不是保证公式必然令 EF 单向变化；还须报告窗口内向前传候选、实际选择、射门及死球等竞争结果。上表不是说所有风格都应该比 B0 赢得更多：防守型可能降低己方机会，某些对手也会克制某种风格。

### 4.4 结果应该怎样受到影响

除检查「球员看起来踢法不同」，还要用以下预先提出的**条件性假设**检查行动是否合理传导到机会和结果。只计算由实际位置、传球、对抗和射门得到的统计；不直接应用下表的数值。

| 对局 / 对比 | 预期方向和探索范围 | 需要一起检查 |
| --- | --- | --- |
| 高位压迫对短传组织 vs 高位压迫对直接出球 | 相对于本方 B0，对短传对手的 `HLR` 增幅，预计比对直接出球对手再高 **0.25–1.5 次 / 对手控球 10 分钟**。这是两个增幅之差，不是两支对手的绝对夺回数直接相减。 | 对手后场失球数、传球尝试位置、进攻三区夺回后的射门；若结果相反或区间很宽，先查出球和暴露时间再调整。 |
| 高位压迫面对速度型反击 / B0 面对同一对手 | 探索对手每场 xG 的差值 **+0.03 至 +0.25**，反映防线身后可能出现的机会。 | 必须同时看到实际防线位置及身后射门，不能用该范围直接增加对手 xG；对手没有能力利用空间时该假设可以不成立。 |
| 控制球权 / B0，在技术型与低技术阵容上分别测试 | 设计假设：技术型阵容采用短传后，传球成功率变化相对低技术阵容更有利，探索差中之差 **+1 至 +5 pp**；模型 `xGD` 的对应差中之差探索 **+0.02 至 +0.15 / 场**。 | 固定两组相应位置和初始体力；先报告两组各自成功 / 尝试数、xG 和净胜球，不把能力差异归因给战术。 |
| 链式防守或摆大巴 / B0 | 预期防线更低、对手控球和前场停留更多；禁区内高质量机会占比**可能**降低，但对手总射门和总 xG 不保证降低。 | 按射门发生位置、模型 xG、射门总数和定位球分组，避免用单一射门数宣布防守成功。 |
| 双翼齐飞对窄阵型 vs 对有边路保护的阵型 | 预期前者较容易增加边路接球和传中机会，但净 xG 效果是探索性问题，不先给固定胜率。 | 两种阵型应尽可能匹配球队实力和适配度；先比较各自的 B0，再比较风格增幅，不能直接用不同阵型比分比较。 |

上述数值是**条件成立时**的试验起点；某一假设被数据反驳，应保留结果并修订设计，而不是按预期改统计。结果影响建议按下面方式分别判断，**行为通过不自动等于结果通过**：

- **指定方向的实例：**高位压迫面对速度型反击时，比较对手的 `xG`：`高压 − B0`。若预注册配对的 `95%` 区间下界 `> 0`，且实际防线前移、对手身后射门增加也得到支持，记作「支持预期风险」；若区间上界 `< 0`，记作「方向与假设相反」；其余为「证据不足」。不要因为低于 `+0.03` 就自动判错，它只是探索范围。技术 / 低技术的 `xGD` 差中之差亦按相同的正、负、不确定规则报告。
- **每个风格的整体结果：**单独报告 `xGD` 和实际净胜球的配对差及区间。没有预先规定正负方向的风格，区间排除 `0` 可作为**探索性的结果变化信号**，不能自动说「影响正确」；若区间完全落在预先设定的 `−0.05 至 +0.05 xGD / 场` 内，仅说明在本实验条件下排除了更大的 `xGD` 影响，既不证明胜负完全不受影响，也不证明行为无效。其他情况报告不确定。实际进球 / 胜平负还要报告原始比分分布，不能用 xG 代替。
- 以上结果和克制比较属于多项**探索性分析**，未做多重比较校正，不能把单个 `95%` 区间当作正式确认；若要声称已验证结果影响，应另用新的独立种子集复验，并预注册主要结果指标、方向、最小有意义差异和多重校正。特别是同种子下战术改变会造成随机调用分叉，共同种子不能保证两场的每次射门或传球逐事件一一对应。

#### B. 每个种子如何配对

对每个风格 `S` 和其表中对照 `C`，在每个预设场景、每个种子跑 **4 场**：

```text
1. 本方 S 主场，对手 O 固定战术客场
2. 本方 S 客场，对手 O 固定战术主场
3. 本方 C 主场，对手 O 固定战术客场
4. 本方 C 客场，对手 O 固定战术主场
```

四场使用同一比赛种子，并且同一支本方球队换边而不是换球员。每个种子先分别求本方两场主客均值，再求 `S − C`；百分比指标按 4.2 重算组均值。这个**四场组合是一个种子块，不是四个独立样本**。控制球权对密集短传、链式防守对摆大巴时，只替换本方风格，其余不变。风格相克实验另做 4.4 所列的双对手差中之差；不能把两个对手不同的原始比分直接相减。

#### C. 样本、统计与判定

- **烟雾 / 调参：**每风格每场景先用种子 `1–30` 跑 `30 × 4` 场，检查程序、埋点、耗时和趋势；可扩至训练集 `1–200` 调参数，不用训练集宣布正式通过。10 个有名称的风格、3 场景、30 种子共 **3,600 场**；全训练集是 **24,000 场**，不含特殊克制实验。
- **独立验收：**冻结实现和参数后，另用种子 `10001–10200`；每风格、每场景 `200` 个种子块，即 `800` 场。10 风格 × 3 场景共 **24,000 场**；按执行速度、预算和试跑方差调整样本时，应在看验收结果前确定。若精度不足，可以报告「不确定」，不要用小样本强行判失败或通过。
- **缺失与估计量：**每个场景 / 指标只保留四场均可计算的完整种子块，报告各组缺失和原因；三场景总体使用三个场景都完整的同种子块。每个场景单独结果使用该场景的完整块；总体则重新基于三场景交集计算各场景效应。任一场景或总体有效块低于预定数量的 95% 时，该主指标判「不确定 / 数据不足」，不得静默换分母。每个场景先按 4.2 从完整块重算风格与对照的效应（`PL` 先求组均值比，`HLR` 先求各组总次数 / 总暴露），再对三个**场景效应**等权平均；不要对每个种子的非线性比率取平均冒充总体比率。
- **区间：**固定 bootstrap 种子，对完整比赛种子块进行 `20,000` 次配对重采样；总体每次同步抽取三个场景的相同种子，从原始数值或计数 / 暴露重新计算各场景效应及等权总体。报告每场景与总体的效应、分子 / 分母、缺失量和未调整双侧 `95%` 区间。分类统一使用 Bonferroni 校正的**双侧 99.5% 百分位区间**（bootstrap 第 `0.25%` 和 `99.75%` 分位数），覆盖 10 个预注册主比较；因此不以未调整的 95% 区间替代分类界限。
- **主指标通过：**10 个非空风格各有 4.3 的一个主指标。按预期方向将效应变成正数，校正区间下界严格大于最小有意义差异，才认定该风格在预注册总体中「行为有效」。同时核查各场景方向和缺失情况；不能从单场胜负推断。
- **不确定 / 无效：**使用同一校正区间：上界严格低于门槛，报告「未达到最小有意义差异」；区间包含门槛或端点恰好等于门槛，报告「不确定 / 需要更多样本」。若明显反向，优先检查坐标、指令映射、球权判定和分母。不要用「统计不显著」直接证明无效。
- **单项与整套分开：**以上只能证明整套模板造成的总体差异。机制测试均以 A=B0 为对照，在相同三场景与配对种子中每次只改 A 的一项：`passing=short/direct` 预期 `PL` 分别下降 / 上升；`focus=middle/wing` 预期 `CF` 分别上升 / 下降；`width=narrow/wide` 预期 `W` 分别下降 / 上升；`tempo=slow/fast` 在同一固定局面、球员及随机输入下预期决策反应间隔分别增加 / 缩短，比赛中同时报告机会数、跑动与结果；`line=low/high` 预期 `DL` 分别下降 / 上升；`engagement=low/high` 预期上抢任务的平均 `u` 分别下降 / 上升；`intensity=low/high` 在相同逼抢线上预期合格暴露期间的上抢任务发生率分别下降 / 上升；`onGain=hold/counter` 预期 `EF` 分别下降 / 上升；`onLoss=regroup/counterpress` 预期丢球窗口的上抢任务发生率分别下降 / 上升。后面三类任务指标需新增埋点并同时报告暴露时间和候选数。先做固定局面单元测试，再做全场方向性探索；单项比较未预注册数值门槛或多重校正，不宣称正式统计通过。重点检查「方向 ≠ 宽度」「逼抢线 ≠ 频率」「反抢 ≠ 自动断球」，不得拿整套风格的胜率证明某单项有效。
- **结果与护栏：**`xGD`、实际净胜球、胜平负、总进球和全场体力作为独立次要指标，报告区间而不强行要求每种风格正收益。对总体总进球和总 xG，若相对同规则 B0 的偏移超过 `max(0.35 球/场, B0 总进球的 15%)` 或 `max(0.30 xG/场, B0 总 xG 的 15%)`，标记平衡告警并调查，不视为自动通过 / 失败。检查是否出现多场景无明显代价的万能风格；每次结论都附足够的区间和样本量。
- **规则与恢复：**逐位测试同输入可复现、转换窗口中存档恢复与连续运行一致；对中立标签无效应，比较比分、物理事件和 RNG，以及**只去除 schema 明确标记为来源展示的 `baseStyle` 等元数据后**的模拟快照，单独检查这些元数据各自保存恢复，不能删除球队 / 球员 ID 或其他行为字段来制造一致。另测主客换边、传球飞行、死球、半场、红牌与旧 v4 回放。埋点开 / 关必须得到同比分和同事件流。

#### D. 验证报告最低格式

每项至少输出：风格和对照、引擎版本 / commit、场景与球员快照哈希、种子和实际场次、主指标的双方均值与分子分母、差值及区间、是否达到有意义阈值、`xGD` / 净胜球 / 胜平负、风险指标、失败和缺失场数，以及异常种子。最终分别标记：**已实现 / 行为有效 / 行为不确定或无效 / 结果影响仅为探索 / 兼容性通过与否**。

本分支只写设计，尚无本节专用批量脚本，也没有这些实验结果。现有 `npm run pes:game -- --n 30 --d 900` 可作 PES 性能和整体统计参考，但**不能**替代上述风格对照；实施者需要先增加不改比赛行为的埋点和独立实验脚本，再运行验收。
