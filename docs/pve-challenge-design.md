# 挑战玩法重设计：传奇挑战 / 杯赛挑战 / 巅峰之路

> 状态：**设计稿，未实施**。本文档是「挑战」页面的 PvE 玩法扩展方案，先于代码评审定稿。
> 定位：**纯 PvE**。不引入任何联机时间、全服同步或跨玩家竞争；所有状态存在各自存档里，服务器不需要任何改动（联机模式下也只落在玩家自己的存档命名空间内）。

## 一、现状与目标

### 1.1 现状

- 挑战页（`src/ui/screens/challenge.ts`）目前只有**友谊赛**：按联赛分区列出世界球队，单场约战，平局进点球（`knockout` 语义），战报进 `challengeHistory`，无收入、不涨球迷。
- 比赛管线已经支持「对任意一支 `AITeam` 开一场淘汰赛语义的比赛」（`startChallengeAgainstTeam(game, ai, seed)`），引擎、战报、复盘、点球全部现成。
- 球员数据是 0–1500 的主属性制，CA 上限 1500；球星有 `era`（年代）、`tier`（强度档）、风格画像（`profiles-curated.ts` 手工画像 + FM 导入画像）决定「强在哪」。
- 俱乐部页已有「历史成绩」标签（历年联赛），没有奖杯/荣誉陈列。

### 1.2 目标

在挑战页增加三个新模式，与现有友谊赛并列：

| 模式 | 一句话 | 对手 | 反复性 |
|---|---|---|---|
| 友谊赛（现有） | 和世界球队单场约战 | 当前世界的 AI 球队 | 无限 |
| **传奇挑战** | 挑战历史最强俱乐部赛季的复刻阵容 | 固定静态数据（50 支起步） | 无限，记录战绩 |
| **杯赛挑战** | 单败淘汰杯赛，夺冠进荣誉橱窗 | 世界球队 / 纯随机生成（按杯赛定义） | 同一杯一赛季一次，输球淘汰 |
| **巅峰之路** | 100 关由弱到难闯关 | 前 20 关国家队，其余生成 AI + 少数固定配置 | 过关推进，输可重试 |

### 1.3 全部模式共用的比赛口径（不改引擎）

| 事项 | 口径 |
|---|---|
| 引擎 | 复用现有比赛创建管线（新物理引擎 + 结算内核），`knockout = true`，平局进点球 |
| 收入/球迷 | 与友谊赛一致：**不产生轮收入、不涨球迷**（杯赛/闯关奖励走显式发放，不混入比分驱动的经济） |
| 体能/伤病 | 与友谊赛一致：赛后扣 condition、伤病照记（沿用 `applyMatchConditions` / `recordMatchInjuries` 现行为） |
| 种子 | 固定种子：`splitSeed(game.seed, '<mode>-<key>-<attempt>')`，读档不能刷新射门 |
| 进行中互斥 | 与现在一致：同一时刻只有一场进行中的比赛（`activeMatch`），PvE 比赛与联赛不并行 |
| 战报 | 进 `challengeHistory`；`MatchRecord` 增加 `mode` 字段区分（见 §5.2），复盘页按 mode 显示标签 |

## 二、传奇挑战

### 2.1 规则

- 50 支（首批）**历史最强俱乐部赛季**的复刻队伍：真实俱乐部名 + 具体赛季 + 当年教练 + 当年真实阵容（每队 16 人：11 首发 + 5 替补）。
- **同一俱乐部允许出现多个不同年份**（如 AC 米兰 1988-89 / 1993-94 / 2006-07 三支并存）。
- 阵容、属性**固定**：静态数据文件，不随存档、不随赛季变化；每个玩家看到的都是同一支（不像世界 AI 会成长）。
- 自由约战，无解锁门槛；每支队伍记录**战绩**（胜/平/负、进球数），挑战页直接展示。
- 全开放、可无限重打；「击败全部 50 支 / 某俱乐部全部年份」的成就式里程碑留作后续扩展（只加展示，不加数值奖励）。

### 2.2 属性怎么「根据现实设计」

数值是玩法数据、不是能力鉴定，但尊重历史共识。设计口径（已实装）：

- 每名球员的目标是 **7 项主属性**（外场：传球、射门、盘带、抢断、力量、速度、爆发力；门将：反应、手控球、出击、一对一、传球、镇定）的**平均评分 80–100**，不是要求每一项都 ≥88。
- 主属性按位置/风格/手工画像展开：强项推到 100，弱项可以落到 45–75，再统一平移，使 7 项平均落在目标值。因此会明确出现强弱形状，例如范巴斯滕射门 100 / 抢断 53，皮克传球 100 / 射门 58。
- **隐藏属性**（视野、决断、无球跑动、防守站位、预判、镇定、团队合作、停球、头球、灵活、耐力）优先参考 FM 画像 `fmProfileFor`（FM24 + 2013-14 导出表）；没有 FM 数据的球员回退到 `profiles-curated.ts` 手工画像或风格画像。隐藏属性不参与「主属性平均 80–100」这个目标，单独按较平的分布生成。
- CA 不再作为硬约束，由全部 18 项（门将 22 项）自然推导；当前 50 队首发平均 CA 约 1100–1200。
- 上限 = 当前值（`ceilings = attrs`，`PA = CA`）：复刻阵容不存在成长，所见即所得。
- 每队整体强度按当年实际战绩分档，档位只影响队内主属性平均目标的分布（全部在 80–100 内）：
  - **S+**：公认历史最强梯队（08-09/10-11 巴萨、12-13 拜仁、14-15 巴萨）→ 首发主属性平均约 88–92
  - **S**：欧洲冠军级（88-89 米兰、16-17 皇马、99 曼联等）→ 约 86–90
  - **A**：联赛冠军/欧冠决赛级（95-96 尤文、90-91 桑普等）→ 约 84–88
  - **B**：有历史意义但整体稍弱（森林、凯尔特人、摩纳哥等）→ 约 80–84
- 首发位置、阵型、战术都按当年真实配置；替补按当年轮换写。
- 数据来源声明沿用现有口径：真实姓名与俱乐部名仅用于原型玩法测试，属性为玩法数据；50s–70s 球员不依赖 FM 导入，隐藏属性由手工画像/风格画像补齐。

### 2.3 数据格式

新文件 `src/game/data/legend-teams.ts`（静态数据，方便人工核对与增补）：

```ts
export type LegendPlayerTuple = [
  name: string,          // 中文名
  enName: string,        // 英文名（确定性生成、画像匹配的键）
  country: string,
  pos: Position,         // GK/CB/W/CM/ST 五位置制，贴合现有引擎
  style: StyleId,        // 踢法风格 → 主属性基准
  avg: number,           // 7 项主属性（门将 6 项）的平均目标，80–100
  foot?: Foot,           // 可选，默认右脚
]

export type LegendTeamDef = {
  id: string              // 'milan-1988-89'
  club: string            // 'AC米兰'
  clubEn: string
  season: string          // '1988-89'
  coach: string           // '阿里戈·萨基'
  tier: 'S+' | 'S' | 'A' | 'B'
  formationId: ElevenFormationId
  tactics: Tactics
  color: string
  accent: string
  note: string            // 一句历史注解（欧冠夺冠、三冠王…）
  players: LegendPlayerTuple[]  // 16 人，前 11 按阵型槽位顺序排列
}
```

构建器 `src/game/legend.ts`：

1. 7 项主属性：`LEGEND_MAIN_STYLE`（按打法的基准）→ `profiles-curated.ts` 覆盖 → 统一平移，使 7 项平均等于 `avg`。
2. 隐藏属性：`fmProfileFor`（FM 画像）→ `profiles-curated.ts` → 风格画像，按较平分布生成。
3. 阵容：按数据顺序把前 11 人填进阵型槽位，后 5 人替补，`validateLineup` 校验。
4. 结果按队缓存；比赛直接走 `startChallengeAgainstTeam`，**引擎零改动**。

## 三、杯赛挑战

### 3.1 规则

- 若干**固定定义**的杯赛（见 3.4），玩家在赛季中报名参加一个**单败淘汰**签表。
- **同一个杯赛在一个赛季内只能参加一次**：报名后本季锁定；中途输了就被淘汰，只能等下一赛季重新报名（换季后重新抽签）。
- 每轮打一场淘汰赛（平局点球决胜）；同轮其他对阵由 AI 对 AI 自动模拟（复用 `simulateAIvsAIState`，v2 快速结算），玩家胜则晋级下一轮，直到夺冠或被淘汰。
- **夺冠 → 获得奖杯**，永久记录在存档里，俱乐部页可查看奖杯与夺冠记录；同一杯赛多赛季多次夺冠会累计。
- 未完成的杯赛在换季时作废（不补赛、不发奖），下一赛季可重新报名。

### 3.2 流程

```text
报名（本季未参加过）→ 抽签（按 seed 派生，本季固定）→ 打第 1 轮
  ├─ 胜：同轮 AI 对 AI 结算完毕 → 下一轮对阵更新 → 继续打
  └─ 负：标记「已淘汰」，本季该杯锁定；战报保留
夺冠：写入 TrophyRecord，发放夺冠奖励（金钱为主），荣誉橱窗 +1
换季：进行中的签表作废（status = 'void'），全部杯赛解锁可重新报名
```

### 3.3 状态设计

```ts
type CupRun = {
  cupId: string
  seasonIndex: number
  status: 'active' | 'eliminated' | 'champion' | 'void'
  round: number                     // 当前进行到第几轮（1 起）
  bracket: CupBracketSlot[]        // 每轮对阵与比分
}
type TrophyRecord = {
  cupId: string
  cupName: string
  seasonIndex: number
  wonAt: number                     // 现实时间戳
  finalOpponent: string
  finalScore: { home: number; away: number }
  finalShootout?: { home: number; away: number }
  matchId?: string                  // 决赛战报 id
}
```

- 判定「本季已参加」用 `cupRun.seasonIndex === game.season.index && status !== 'void'`。
- 奖杯列表只增不减；跨赛季持久。

### 3.4 首版杯赛定义（3 个）

| 杯赛 | 规模 | 参赛池 | 定位 | 夺冠奖励（金钱，待平衡） |
|---|---|---|---|---|
| 社区杯 | 8 队（3 轮） | 本分区 AI 球队 | 入门，练阵容 | 100 万 |
| 联盟杯 | 16 队（4 轮） | 全世界按联赛级别抽 | 中期主力杯 | 300 万 |
| 冠军杯 | 16 队（4 轮） | **纯随机生成球队**（见下） | 高难度，毕业杯 | 800 万 |

- **冠军杯的参赛队全部随机生成**：报名时按 `splitSeed(game.seed, 'cup-champions-<seasonIndex>')` 确定性生成 15 支球队（含名字、球衣、阵型战术、球员名单），强度落在冠军杯定义的目标区间（首发均值约 1150–1300，高于世界顶级联赛平均水平）。随机生成让冠军杯的难度与世界成长解耦、始终是「压轴难度」，也避免了「混传奇队导致中期玩家必然一轮游」的问题。同一存档同一赛季的签表固定；换季作废后下季重新生成。
- 社区杯 / 联盟杯的参赛池从 `game.world.clubs` / `game.aiTeams` 现取，强度自然跟随世界成长；**杯赛定义是配置，不是存档**——增删杯赛不影响旧存档（新杯自动可报名，删掉的杯只是不再出现在报名列表，奖杯记录仍显示）。
- **传奇杯**（8 队、全部传奇队抽签、特殊奖杯样式）作为后续扩展预留，本版不开放。
- 换季时正在进行的签表作废的理由：世界球队名单换季后重建，签表里的队伍引用会失效；作废最干净。冠军杯同理（随机球队按季生成，跨季无意义）。

### 3.5 展示

- **挑战页 · 杯赛标签**：杯赛卡片列表（名称、规模、参赛池说明、奖励、状态：可报名 / 进行中（当前轮对阵与签表）/ 已淘汰 / 已夺冠 ×N）。
- **俱乐部页 · 历史成绩标签**：顶部新增**荣誉橱窗**——奖杯图标 + 杯名 + 夺冠次数 + 最近夺冠赛季；下方按时间列出每座奖杯的决赛对手与比分。
- 杯赛战报同样进 `challengeHistory`（`mode: 'cup'`），复盘页可回看每一轮。

## 四、巅峰之路

### 4.1 规则

- **100 关**由弱到难线性推进：只能挑战「当前关卡」，过了解锁下一关，没过不推进（可无限重试）。
- 每关一场淘汰赛，平局点球决胜（闯关不能靠平局混）。
- **前 20 关为固定国家队阵容**（历史国家队，同样静态复刻、属性按现实设计、由弱到强排序）；21–100 关为**生成 AI 球队 + 少数固定配置**：
  - 生成部分（约 60 关）：按关卡序号派生种子生成球队，平均首发 CA 沿难度曲线（§4.2）爬升；名字、球衣风格、阵型战术按国家/年代池随机，但**同一存档同一关的对手永远一致**（种子派生自 `game.seed` + 关卡号）。
  - 固定配置（约 20 关）：里程碑关卡（25/50/75/100 及若干 5 的倍数）用传奇队或特制 Boss 队（如第 100 关「全明星传奇」由各时代最佳混编）。
- **奖励**（后续版本加数值，本版先搭框架）：每关定义一个奖励槽 `RewardDef`，默认 `{ type: 'none' }`；里程碑关发金钱；技能卡奖励预留（见 §4.4）。**每关奖励只发一次**（记录已领取的最高关卡）。

### 4.2 难度曲线（草案，待 `scripts/balance.ts` 校准）

- 关卡 s 的目标首发平均 CA：`ca(s) = lerp(350, 1480, (s-1)/99)`，再按段位微调：
  - 1–20（国家队）：约 350 → 900，按每支国家队的真实档位定 CA，而非机械插值；
  - 21–60（生成）：约 900 → 1250，覆盖世界中游到冠军级；
  - 61–99（生成 + Boss）：约 1250 → 1450，**超过世界中任何一支球队**（世界 AI 顶级首发均值约 1200–1300），逼玩家用培养满的卡阵；
  - 100（Boss）：均值约 1480 的全明星。
- 关卡 CA 单调不降，允许相邻关持平，不允许倒退。

### 4.4 奖励框架

```ts
type RewardDef =
  | { type: 'none' }
  | { type: 'money'; amount: number }
  | { type: 'skillCard'; skillId: SkillId; tier: SkillTier }
```

- 本版先实现 `money`（进 `economy.balance`，不影响球迷）与 `none`；里程碑关（每 5 关）发钱，金额随关卡递增（5 关 20 万 → 100 关 1000 万，具体待平衡）。技能卡奖励在 P6 接入，奖励槽向后兼容（先按 `money` 占位发放，P6 后切换）。
- **技能卡形态已定（方案一：可装备的技能卡道具）**：奖励发放为一张**技能卡道具**，进 `pve.skillCards` 库存后由玩家**选择一名球员装备**；装备后该球员获得该技能（银 / 金 / 彩虹档，倍率沿用现有 silver 1 / gold 1.2 / rainbow 1.4），道具消耗。技能本体完全走现有技能系统，不新做一套效果。注意命名区分：这是「技能卡」道具，与培养产出的「球员卡」（`game.cards`）是两回事。

## 五、数据与存档

### 5.1 GameState 扩展（全部可选字段，旧档读档补默认值）

```ts
export type PveState = {
  /** 传奇挑战战绩：按队伍 id 记胜平负与进球 */
  legends: Record<string, { played: number; won: number; drawn: number; lost: number; goals: number }>
  /** 杯赛：每个杯赛本季（或历史最后一季）的进行状态 */
  cups: Record<string, CupRun>
  /** 奖杯陈列 */
  trophies: TrophyRecord[]
  /** 技能卡道具库存（P6）：与培养产出的「球员卡」game.cards 无关 */
  skillCards?: { id: string; skillId: SkillId; tier: SkillTier; source: string; acquiredAt: number }[]
  /** 巅峰之路 */
  peak: {
    cleared: number                       // 已通关关卡（0-100）
    rewardClaimed: number                  // 已领取奖励的最高关卡
    history: { stage: number; at: number; matchId: string }[]  // 最近若干次闯关记录
  }
}

// GameState 增加一个命名空间字段：
pve?: PveState
```

- 迁移：`loadGame()` 里 `ensurePve(parsed)`（缺省补空对象），与现有 `economyOf`/`ensureCards` 同一模式；不动 `SAVE_KEY`。
- 纯 PvE 状态与联机世界的同步无耦合：服务器只转发存档，不需要校验（用户已明确本模式不考虑联机对抗与一致性）。

### 5.2 MatchRecord 扩展

```ts
// 现有 isLeague: boolean 保持不动（球员数据统计、赛季口径都依赖它）
mode?: 'friendly' | 'legend' | 'cup' | 'peak'
cupId?: string    // mode = 'cup' 时
stage?: number    // mode = 'peak' 时
legendTeamId?: string // mode = 'legend' 时
```

- 复盘页与挑战记录列表按 `mode` 显示标签（「传奇挑战 · AC米兰 1993-94」「冠军杯 · 决赛」「巅峰之路 · 第 37 关」），无 mode 的旧战报显示「友谊赛」。

## 八、已定决策与开放问题

### 已定（本方案内）

1. **D1** 三种新模式全部复用友谊赛比赛管线，不改引擎与结算。
2. **D2** 传奇队/国家队为静态数据文件，构建成标准 `AITeam`；确定性属性生成，不随存档漂移。
3. **D3** 杯赛：每季一次、单败淘汰、输了淘汰、换季作废、奖杯永久记录。
4. **D4** 巅峰之路：输可无限重试、平局点球、奖励按关卡只发一次；前 20 关固定国家队。
5. **D5** 全部状态进 `GameState.pve` 可选命名空间，读档补默认值；不碰服务器。
6. **D6** `MatchRecord.mode` 区分模式，`isLeague` 语义不动。
7. **D7** **首版 3 个杯赛**：社区杯、联盟杯、冠军杯；传奇杯（全传奇抽签）预留后续扩展，本版不开放。
8. **D8** **冠军杯参赛队全部纯随机生成**（按季确定性生成，强度落在杯赛定义区间，约 1150–1300），不用世界球队、不用传奇队；难度与世界成长解耦。
9. **D9** **技能卡形态：可装备的技能卡道具**（发放进 `pve.skillCards` → 玩家自选球员装备 → 球员获得对应档位技能，装备后道具消耗）；P6 实现，效果完全走现有技能系统。
10. **D10** 97-98 AC 米兰不收录（该季意甲第 10，非强档）；首批清单按 §2.4 执行。
11. **D11** 奖励金额均为占位值，P7 用平衡脚本校准后写死。
12. **D12** 巅峰之路前 20 关国家队排序按 CA 校准（现实成就仅参考，备选名单见 §4.3）。

### 遗留问题（不阻塞开工）

1. **传奇杯**的开放时机、规模与特殊奖杯样式（后续版本）。
2. **技能卡的获取面**：首版只从巅峰之路里程碑发（杯赛夺冠奖励是否也发技能卡，P6 时定）。
3. **奖励数值**：所有金额占位，待 P7 平衡（同 D11）。
