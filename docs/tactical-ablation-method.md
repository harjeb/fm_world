# 战术单项消融：数据口径与复现

> 供探索、排查和重新调参使用，**不是正式平衡验收脚本**。结果及限制见
> [战术验证报告 §12](./tactical-validation-report.md#12-单项消融与本轮优化探索)。

## 夹具与变量

- `baselineTeams(1)`：双方 4-4-2、相同阵型槽位、属性和技能；先统一属性，再把主队完整首发、替补和战术
  复制给客队，仅保留球队身份。`condition=100`，删除 autoSubs / chemistry，11 人制、`D=900`、越位开、无新伤病。
- 属性 `--squad 67` 的同一口径：主属性 1005、隐藏属性 13，外场不适用的门将属性为 0；不是所有存档字段等于 1000。
- 快反 vs 高压：快反的 `receiving=mixed/space` × `defense.width=normal/narrow`，其余九项不变；
  控制 vs 链式、双翼 vs 链式：只切换链式的无球宽度。每条件按主客配对并以比赛种子为块。
- 被测战术球队熟练度分别为 1 和 0.4，对手为 1；`fam` 是现有整队单值，不是四族个人熟练度。
- 独立组 `previous` 参数 `spaceLeadScale=1, defenseCompactness=0.15, defenseMarkBuffer=1.5`；
  `proposed` 为 `1.5, 0.25, 3`。**后两项同时变化，不能将 proposed 的效果归因到某个具体参数。**
  指令对照是单项，但两个参数画像的比较仍是组合对比。`previous` / `proposed` 使用相同当前代码；不是跨引擎版本对照。
  之后新开实验比赛默认设置为 `spaceLeadScale=1, defenseCompactness=0.25, defenseMarkBuffer=3`，
  这是两组的折中而不是独立文件里的任何一组；消融脚本始终显式覆盖三项。

## 观测量和局限

- `defensiveWidth`：`possessionTeam()` 认为对手控球期间，每秒采样被测队外场 `y` 的 P90−P10，
  每场均值；少于 8 名外场不采样。其包含同队传球飞行，不完全等同于设计文档中的稳定控球暴露口径。
  `null` 表示无样本，差值先每主客平均再配对种子。
- `spaceDecisions`：显式启用 space 且开放比赛的持球决策；`eligible` 是该决策实际产生至少一个额外候选的次数。
  候选统计只记录该决策已执行的计算，**没有**为 `mixed` 运行影子候选，也不能在混合组计算对应机会率。
- `spacePasses` 是实际出脚的计划空当球，`settledOk` 是出脚时结算预测成功，`received` 是目标球员最终实际接到；
  `receivedOk` 是二者交集。不能拿预结算成功冒充已实际接球，miss 后期仍可能被接球人拿到。
- `spaceRejections` 以“队友候选调用次数”为分母；一场持球决策可有多个队友候选，也可能有多个不同失败原因。
  不等于传球失败率，也不代表该决策没有其他进攻机会。`noActiveRun` 包括不在跑动状态的普通队友，
  不能简单理解成有意前插失败。
- `taskFrames` 是执行防守任务分配的帧数，`taskConflictFrames` 是该帧中本队上抢 / 协防者的 `marks[slot] ≥ 0`；
  不能用 `marks` 里面的对手 pid 直接与本队 pid 比较。死球、己方控球和无可用外场的帧不在该分母内。
- `xGD` 为模型 xG 差，不是实际净胜球。分两组统计每格主客、种子，成对差使用整个种子块 bootstrap；
  所有区间是未校正的探索性 95%，仅 4 / 6 个种子时非常不稳定。相同 seed 下 RNG 路径会分叉。
- `counter:space×narrow` 为同一对位、同一熟练度下的**两条本方指令交互**，不是 A 风格相对 B0 的克制交互。
  `familiarity` 对比是被测方自己的熟练度效应差，不是双方熟练度 3×3 的完整克制实验。

## 操作

```bash
# 训练集：256 场 = 8 个配置 × 2 参数画像 × 2 熟练度 × 4 种子 × 主客
npm run tactics:ablation -- --n 4 --seed0 1 --workers 2 --out /tmp/ablation-train.json

# 小规模独立种子：384 场；仍只是探索，不是正式验收
npm run tactics:ablation -- --n 6 --seed0 10001 --workers 2 --out /tmp/ablation-independent.json
```

脚本保存所有比赛的原始行、指令、参数、种子、夹具 / 源码哈希及每个对比的种子块值。需在仓库根目录运行。
更改代码后源码哈希不同；仅脚本 `--out` 不同也可能覆盖自己指定的路径。原始结果的源码哈希包含测试文件，
如后续补测试也会改变哈希，即便比赛代码未变；必须报告实际运行时的 hash / dirty 状态，不能冒充同一源码。

正式验收仍需扩展：更多独立种子和阵型 / 人员画像、机会集分母、预注册阈值与多重比较校正、原始缺失率、
完整的 A/B 熟练度 3×3 因子实验，以及版本路由、服务器校验和旧回放恢复。
