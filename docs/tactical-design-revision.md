# 战术风格与球队指令：基于首轮实验的修订方案

> **状态：已有部分实验实现，但未测试、调平或上线。**本方案在保留现有首轮实验及九项指令的前提下，
> 设计下一版的场上机制、风格模板和验证方法。数值均是实验起点，不是现实数据、xG 加成或胜率。
> 第二上抢者冲突修复、身后空当和无球宽度已有代码原型；用户要求本轮不运行测试，效果及兼容性仍未验证。
> 首轮结果与勘误见 [tactical-validation-report.md](./tactical-validation-report.md)；
> 数据协议和高级指令以 [team-instructions-system-design.md](./team-instructions-system-design.md) 为基础。
> 第二上抢者、身后空当和低位紧凑的实现级契约与验收，以
> [三项机制详细设计](./tactical-mechanics-implementation-plan.md) 为准。

## 1. 要解决什么

- **让踢法更明显，而不是给风格标签加能力。**控球有耐心和安全接应，高压依靠协同追抢，反击利用对手留下的空间，
  低位防守压缩中路，边路战术制造横向拉扯。每种方案都要有机会成本与可被针对的场景。
- **各项指令独立、可编辑。**`styleId` 只决定复制什么模板；模拟只读取展开后的指令、球员、空间与体能。
  相同指令、人员、阵型及随机状态下，名字不同不得改变任何事件。
- **熟练度影响执行，不直接影响胜负。**进攻方能否组织跑动、防守方能否维持队形分别由本队执行；
  双方的实际位置和决策形成对位差，不直接读取双方熟练度之差给 xG 加分。
- **现有九项是首轮实验原型，不等于完成发布。**本方案的无球宽度、接空当、支援跑动、传中和出球等均是
  P2 待实现能力；不能把它们记成已生效。转换快照、线上接入及旧规则路由仍是上线阻塞项。

### 1.1 从实验可以、不能得出的结论

| 观察 | 当前可用的判断 | 不能直接得出 |
| --- | --- | --- |
| 首轮高压 / 控球系 vs B0 的 xGD 点估计大幅为正，低位系多为负 | 先检查高位防线风险、压迫任务、疲劳和低位覆盖是否合理 | 哪个机制已经证明是唯一原因；所有阵容下都该被等量削弱 |
| 统一属性阵容的排序 / 对位点估计与基线不同 | 阵容画像可能影响结果，必须分层 | 「基线一定低估某风格」；区间显著与不显著之差本身显著 |
| 单项传球、方向、宽度、转换的方向性有信号 | 这些机制值得保留并逐项验收 | 小样本已经通过多重校正的正式验收 |
| 宽度随熟练度降低未如预期收敛 | 先检查熟练度实际覆盖，补固定局面 | 已证明具体是宽度反向抽签导致——当前持球宽度根本没有该抽签 |
| 若干对位残差的未校正区间不含 0 | 值得预注册新的对位假设 | 已确立克制链；也不能从区间跨 0 推出克制不存在 |

注意：首轮 `baselineTeams(1)` 的客队会四舍五入，双方对应首发 221 个属性值不同；它是相同球员来源，
不是严格同属性。统一属性 `--squad 67` 对主属性给 1005、隐藏属性给 13（评分 65），不等于所有存档字段都是 1000。
首轮样本 5–12 个种子块，未做多重校正，属于探索而非最终平衡。

## 2. 十种风格的新版本：特色、成本和针对方式

下面的现实例子仅帮助理解战术原则，不是精确还原某队的阵型或每一场的指令，更不是统计证据。
现实球队也会随球员、对手、比分和比赛阶段改变方案。

| 风格与现实参照 | 主要意图、可能优势 | 要明确表现的代价 / 应对 | 依赖的球员与机制 |
| --- | --- | --- | --- |
| **控制球权**（如瓜迪奥拉时期巴萨的控球原则） | 近距离接应、耐心换边，失球后保护球权；较少无准备的长传 | 后场短传被压迫时可能危险；对手落好位时推进慢、易被迫横传 | 传球、接应、视野；短传、正常宽度、反抢、后场破压 |
| **高位压迫**（如克洛普时期利物浦的压迫原则） | 多人协作切断短接应，高位夺回后尽快攻门 | 后场留空、被一脚打身后；高强度跑动造成后程体能压力；不能保证抢回 | 无球跑动、速度、耐力、团队；高逼抢线、反抢、门将逼抢 |
| **密集短传**（控球原则的更耐心版本） | 短距离多点接应，得球后先稳定，等待路线 | 纵深推进较慢，对高质量跑位和技术要求高；对密集防线不自动破防 | 传球、接应；短传、脚下接球、保持队形 |
| **垂直密集短传** | 仍以短传配合为主，但中路 / 肋部尽早寻找向前跑动 | 中路拥堵、失球后中路转换风险；宽度不足时容易被封锁 | 决策、接球和跑动；短传、中路、接空当、反击 |
| **双翼齐飞**（如依靠边后卫和传中的一些英超球队） | 拉开横向间距、边路接应，合适时传中；有机会绕开拥挤中路 | 空中 / 禁区接应不够或对手防空强时效率下降；边后卫前插留下空当 | 传中、速度、禁区争顶；持球宽度、边路、支援跑动、传中时机 |
| **长传冲吊**（如普利斯执教斯托克城时期的直接打法） | 受压时更早绕过中场，争第一及第二落点 | 传球更难、球权易丢，依赖前场对抗；长传不保证争顶成功 | 传球、力量、头球、第二落点跑动；直接传球、绕过压迫、长球门球 |
| **灵活防反** | 先在较低位置争夺，夺回后通过短传和跑动找空当，也可就近反抢 | 出球点和技术不足时容易丢失第一脚；面对低位对手可用纵深较少 | 决策、盘带、跑动；短传、接空当、中位逼抢、局部反抢 |
| **快速防反**（如拉涅利时期莱斯特城的部分转换进攻） | 低位稳住后直接打对手压上留下的纵深 | 对手不前压时空间不足，长距离传球和冲刺有失误 / 越位风险 | 速度、加速、传球、无球；直接传、接空当、得球反击 |
| **链式防守**（借鉴意大利链式防守的保护纵深原则） | 低位压缩中路、保护后场，夺回后有组织地反击 | 允许对手在外围控球和转移；攻防脱节时难支援反击 | 防守站位、团队；低防线、低逼抢线、窄无球队形、反击。可推荐而不强制三中卫 |
| **摆大巴**（借鉴穆里尼奥球队部分比赛的深位防守） | 更强调维持低位队形，尽量减少中路高质量机会 | 对手前场停留、转移和传中机会可能增加；本方得分和反击支援更少 | 防守站位、争顶；低位、窄无球队形、回撤、得球先稳住。定位球不是免费进球 |

**针对是条件性的假设，不是石头剪刀布：**

1. 反击面对前压且身后有空间的对手：跑动时机、接空当和传球能力足够时，可能产生更多身后接球；
   若对方留人、门将出击或反击者速度不足，不保证占优。对低位阵地则可能难以启动。
2. 高压面对短传出球：若上抢覆盖真实接应点，可能迫使后场更快出球或失误；若短传方技术好、留有安全回传
   或直接越过压迫，防守方可能被身后打穿。
3. 窄低位面对中路短传：可能增加中路堵截和射门压力；但弱侧横向转移、传中、远射和第二落点可能更危险。
   不能仅凭阵型缩窄直接下调对手射门成功率。
4. 边路面对窄防守：可能得到更多边路接球 / 传中机会；对有边路保护、优秀防空的队伍，未必转化为高 xG。
5. 长传面对高位压迫：可能减少本方后场连续受压；面对强中卫 / 争顶和充足保护，反而可能连续失去球权。

## 3. 修订模板：P1 不回写旧档，P2 能力分期开放

以下是**目标 revision 2**，不是当前 `STYLE_LIST`：P1 所列仍是已定义的九项。代码中另有实验性的
`STYLE_LIST_REV2`，目前只启用了 `receiving=space` 和 `defense.width` 两项；表中其他 P2 字段仍未实现。
任何指令都不能在服务端 / UI 宣称可用，直到实现、验证并完成版本与兼容工作。
之前保存的九项模板及已开始比赛不自动迁移；新 revision 应与旧 revision 共存，可预览差异后手动应用。

记号：持球 `方向/传球/节奏/宽度`，防守 `防线/逼抢线/频率`，转换 `得球/失球`。档位均使用现有枚举。

| 候选风格 | 持球 | 防守 | 转换 | 候选 P2 非中性字段（未实现） |
| --- | --- | --- | --- | --- |
| 控制球权 | balanced / short / slow / normal | high / high / high | balanced / counterpress | `receiving=feet, buildUp=penetrate, goalKick=short` |
| 高位压迫 | balanced / mixed / fast / narrow | high / high / high | counter / counterpress | `supportRuns=more, pressKeeper=true` |
| 密集短传 | balanced / short / slow / normal | high / high / high | hold / counterpress | `receiving=feet, patience=patient, buildUp=penetrate, goalKick=short` |
| 垂直密集短传 | middle / short / slow / narrow | high / high / high | counter / counterpress | `receiving=space, supportRuns=more, buildUp=penetrate` |
| 双翼齐飞 | wing / direct / fast / wide | mid / mid / high | counter / balanced | `supportRuns=more, crossTiming=early` |
| 长传冲吊 | balanced / direct / fast / normal | low / mid / mid | counter / regroup | `buildUp=bypass, goalKick=long, crossTiming=early` |
| 灵活防反 | balanced / short / fast / normal | low / mid / high | counter / counterpress | `receiving=space, creativity=free, defense.width=narrow` |
| 快速防反 | balanced / direct / fast / normal | low / low / high | counter / balanced | `receiving=space, buildUp=bypass, defense.width=narrow` |
| 链式防守 | balanced / direct / slow / narrow | low / low / low | counter / regroup | `defense.width=narrow` |
| 摆大巴 | balanced / **mixed** / slow / narrow | low / low / low | **hold** / regroup | `defense.width=narrow, showWide=true, goalKick=long` |
| 空白 / 自定义 | balanced / mixed / normal / normal | mid / mid / mid | balanced / balanced | 所有 P2 字段中性：`receiving=mixed`、`supportRuns=balanced` 等 |

`receiving`、`buildUp`、`patience`、`crossTiming` 等列属于 `advanced.possession`，表中用短名；
`defense.width / showWide / pressKeeper` 属于 `advanced.defense`。未列出的 P2 字段均用对应具名中性值。

相对首轮 P1，唯独建议把摆大巴从 `direct + balanced` 改为 `mixed + hold`，使其更重视夺回后的组织和保位，
与链式的 `direct + counter` 拉开差异。**这不是说守队不许解围或一定短传**：危险时仍可解围，未来
`goalKick=long` 也只影响有合格选项的球门球；不能把 `hold` 解释成禁前传。两项变化混在一起，整套结果
不能归因于某单项，实施前须做 2×2 拆分。其余表中变化是未来 P2 revision，不能改写历史 P1 实验。

## 4. 引擎机制：更明显的行为，必须由真实机会产生

下列常数为 11 人制、`K=1` 的首轮试验值；依次冻结后单项验证，不因某对比分数不理想就给该风格结果加成。
高级指令及共享基线修改必须在**新的、可路由的比赛规则版本**下进行，保持 v4 / P1 冻结实现和历史回放。

### 4.1 身后空间与转换：让高位既能压迫也有风险

**现状：**`spaceBehindLine`、前插、`passKind` 与路线 / 越位结算已存在；但常规前插目标目前被放在
越位线之前，而传球主要瞄准当前位置加速度提前量，候选、落点和对手位置是否充分联动尚未验证。
不能断言「完全没有身后机制」。

**提案：**在实际夺回的有限转换窗口及其他有可行跑动的局面，以持球人方向统一坐标 `lx = x × dir`：

1. 用球与倒数第二名对手的出脚瞬间位置求现有越位参考线 `Loff = max(0, ballLx, secondLastLx)`；
   保留越位开关、技能与既有判罚语义。跑动目标可以越过防线，**出脚瞬间的接球人位置**仍按现有规则判越位；
   不可把目标坐标当球员实际位置。
2. 只对活跃且未眩晕的合法接球人，生成受场地边界、当前速度 / 加速度和可到达时间限制的空当目标；
   比如前方预测提前量最多 `6K`，接球人近乎静止或没有可达目标时回退原候选。后卫和门将可实际回追、拦截。
3. `receiving=space` 时，对**原本可行、向前且目标越过对手防线**的候选增加最多 `+0.04` 倾向分，
   按可用空间和执行质量衰减；`feet/mixed` 走各自已有候选规则。该分并入高级传球总预算 `±0.06`，
   不是在原 P1 `±0.10` 之外再加第三层。`onGain=counter` 仍只使用现有转换偏好，不再额外奖励一次。
4. **同一个计划目标**用于候选评分与 `contact.pass`；飞行演出、拦截和接球按预结算结果及物理过程发生，
   `icpt/miss/out` 可能另有偏离后的实际演出点，须分别记录。具体开放比赛、可达性与越位契约见
   [详细设计 B](./tactical-mechanics-implementation-plan.md#b-可达身后空当与越位)。

初始只改候选 / 目标，不改传球成功率、不按「高位防线」或风格标签直接加成；先查 `HLR`、身后传球、
接球和射门是否变化，再决定是否调整常规前插概率（首轮暂保留 `0.08 / 0.12 / 0.16`）。
**反例：**对手后卫留在身后或接球者无速度时，纵深收益应很小；防守队也可造越位或实际回追成功。

### 4.2 低位紧凑与边路：减少中路空当，同时暴露弱侧

引入 P2 `advanced.defense.width=narrow/normal/wide`。无球时以**合格防守目标的横向中心**为轴，
首轮缩放 `0.85 / 1.00 / 1.15`，之后执行边界、角色和人数约束，保留现有移动分离力，不虚构硬最小间距保证。
独立于持球宽度与防线高度。当前盯人、协防目标会覆盖 `formationTarget`；
[详细设计 C](./tactical-mechanics-implementation-plan.md#c-低位无球紧凑中路覆盖与边路代价) 明确仅对
合格的盯人和无任务队形目标做有界收缩，主动上抢、协防、紧急门前防守和拦截目标不被强行拖回。

- 守中路通过**实际站位**影响线路净空、射手压力和封堵者；现有射门 / 传球结算只读真实位置，
  **不**给低位队一个「禁区射门概率减成」。
- 同时记录弱侧到位时间、对手边路接球、传中及二点；必要时保证最低边路保护，不把弱侧防守清零。
- `showWide=true` 只让合法上抢者尝试从中线侧接近，不改变对方指令。窄防守不是自动阻止穿透，
  多人压入中路也可能留下远射和传中空间。

### 4.3 高压与体能：压迫来源和代价对称

- `engagement` 决定允许区域，`intensity` 决定候选半径及人数，`onLoss=counterpress` 仅在有效窗口内改变任务。
  常规阶段的第二上抢者应有条件：另一名球员已就位、候选在实际搜索半径内，且承担后场保护的最低人数仍满足；
  附近有必须保护的高威胁球员时优先协防。具体威胁判据要可埋点，先与无条件两人对照，不预设胜率方向。
- 先修任务一致性：当前 `updateShape` 未在每轮开始时清除 `presser2`，分配盯人时的 `used` 集合也没有
  包含它，第二上抢者可能同时占用盯人名额。新规则须每次更新清空过期任务，并将两名上抢者和协防者排除
  在盯人候选外；由于 `decideT` 会延迟目标刷新，还须按[详细设计 A](./tactical-mechanics-implementation-plan.md#a-第二上抢者任务冲突)
  处理旧 `target`。这是代码缺陷观察，尚不能推断它对 xGD 的贡献。
- 失球回撤或逼抢线不满足时，仍需保留**计入人数上限的门前紧急上抢**；当前实现的紧急分支受 `allowed`
  限制，和原设计不一致，应在新规则中修正并做固定局面测试。
- 压迫通过更多实际高强度跑动进入现有疲劳模型，**不另扣一份风格体力**。同时比较上半场、下半场、末段
  的速度、决策、距离、冲刺、体力与高位夺回。若现有体力到表现的传导过弱，另开共同基线实验标定，
  新旧配置在该新规则下共用；不只给高压风格加惩罚。跨场 `condition` 当前仍按分钟，不能宣称已跟跑动挂钩。
- 逼抢门将须以活球门将为合法目标，并让实际距离形成压力；不能直接提高门将失误率。疲劳、受伤和牌都按现有
  机制及规则统计，不用本方案虚构伤病率。

### 4.4 边路传中、长传与二点

- P2 先实现并验证 `crossTiming`、`supportRuns`：**有边路位置及禁区接应时**，双翼才更可能传中；
  防守者高度 / 站位 / 接触、传中距离及第一落点共同决定结果。若尚无可行贴地轨迹，不开放 `crossType=ground`。
- 长传 / 绕过压迫只改变选择和球路；保留传球距离、拦截与越位代价。第二落点由实际球轨迹、可到达时间和
  双方人数决定；没有该逻辑时先埋点再做，不增加「长传二点必胜」概率。
- `tempo` 不直接加速度或射准。快节奏是决策倾向，现有公式的幅度较弱；先测候选间隔、跑动与失败率，
  再决定是否重新标定，避免和高压体能重复计算。

## 5. 熟练度、复杂度与相互应对

当前引擎只接收每队一个 `familiarity` 并赋给该队球员；`StyleDef.complexity` 在存储中存在但尚未用于计算。
以下是下一版**待实现**的数据及执行模型。具体成长数值须另行模拟经济和训练周期，不把首轮试验值当承诺。

### 5.1 以指令族而不是风格名记录

每名球员在比赛开始时冻结 `possession / transition / block / press` 四族 `F∈[0,1]`，分别对应：

| 指令族 | 涵盖的执行 | 对位传播路径 |
| --- | --- | --- |
| possession | 传球、方向、宽度、节奏、接空当等 | 接应位置、候选选择和实际球路 |
| transition | 得球后前插、失球后反抢 / 回撤 | 转换窗口内实际启动和位置 |
| block | 防线、无球宽度、协防 | 防线位置、间距和实际线路净空 |
| press | 逼抢线、人员协同与门将逼抢 | 任务及时性、位置和实际持球压力 |

显示的「风格熟练度」只能是这些族按**已启用指令**计算的摘要；改名、换同指令模板不改变执行。
门将是否参与各族平均须按任务决定，不得默认把其影响到所有外场防线。比赛内换人、红牌后重算在场平均，
每名球员保留自己的值；不能让替补继承被换球员的熟练度。

### 5.2 连续执行强度的起点

对被启用的非中性指令 `i`，从该球员的所属族熟练度 `F_i` 和**指令本身**难度 `d_i` 计算：

```text
q_i = 0.35 + 0.65 × clamp(F_i, 0, 1) ^ d_i
已执行的偏好/目标 = 中性值 + q_i × (该指令目标 − 中性值)
```

`d_i` 可先沿用传球 `0.8`、宽度 `1.0`、转换 `1.2`、高压协同 `1.3` 作为待验证起点；高 `d` 使未熟练者
偏差更大。例：`F=0.4` 时 `d=0.8` 的 `q≈0.662`，`d=1.3` 的 `q≈0.548`；`F=1` 均为 `1`，
`F=0` 均为 `0.35`，**不是 0 或保证回到中性**。高难组合由同时启用的指令与局部协调要求体现，
而不是让 `styleId.complexity` 偷偷改相同指令。团队队形类先用参与该任务的有效球员 `q_i` 聚合，个人选择类用本人值；
需要协作的任务可记录成员间差异，但不凭团队均值给球员增加属性。

- 各指令的目标缩放**只在一个位置**应用一次，包括持球宽度、接应、节奏、逼抢及转换；不能同时对偏好和
  同一个结果再乘一次。中性指令没有额外奖励；无合格候选则回退正常动作。人数等离散项不能取小数；
  首轮可按任务重评时 `round(lerp(1, 2, q_press))` 选择 1 / 2 人，再受留人和可用候选约束，
  并显式测试阈值两侧的不连续性；不在每个物理帧额外抽签。
- 不再每帧抽「低 ↔ 高」或宽 ↔ 窄；先用连续缩放避免队形来回抖动和随机调用爆炸。未来若加入失误，
  应按明确决策 / 任务生命周期抽签，倾向于执行不完整或晚到，而非频繁做相反战术；保存抽签状态和 RNG。
- 较高熟练度是更准确地执行自己的意图，**不保证 xGD 更高**：坏战术或不合适的阵容执行得更彻底，也可能更差。
  不能拿结果单调性替代指令固定局面的执行准确率。

例如快反一方 `transition` 高，前插、出球更接近所设意图；高压一方 `block / press` 高，防线协同和
压迫更接近其意图。最终从两队球员的**实际空间、时间和动作**计算结果，而非 `k × (F_A − F_B)` 或给 xG 加分。
后卫熟练也不代表自动防住反击：高防线本来就可能让出身后空间。

### 5.3 保存与迁移

- 用户旧档缺字段时先按现有默认满熟练兼容，不能突然把旧球队变生疏；新成长系统上线时单独设计初始化、训练
  与衰减、UI 解释和服务器校验。只接受有限 `[0,1]`；比赛快照冻结每个参与球员的四族值。
- 需要序列化转换候选、窗口起止、上抢任务 / 调度时间、执行随机状态以及 `PesSettlement.secondWindUsed` 等已有缺口；
  中途保存 / 恢复必须和连续运行一致。旧 v4 无 `instructions` 的行为与随机顺序不变。
- 当前 `PesGame` 心态调整会替换战术，需要先设计新规则临时层、保存和回放，不能声称已完成。
  后台纯 AI 的 v2 引擎暂不支持 P2；没有兼容适配前，不给该路径分配只能由新引擎执行的预设。

## 6. 验证方案：从理论假设到可发布结论

### 6.1 夹具和真实控制变量

| 夹具 | 构造与用途 |
| --- | --- |
| 严格镜像基线 | 主队首发 / 替补及各自属性、技能、角色、阵型复制给客队；球队身份独立。保证每项属性、条件、角色及技能相同。保留原有不严格基线作为历史对照，不把它改名为同一批结果。 |
| 统一属性 | `--squad 67 --exact-mirror`：主属性 `1005`，隐藏属性 `13/20`，不适用的外场门将属性按 0；双方槽位与技能相同。单独加一套无技能版本隔离特性；另测中、低属性档。 |
| 技术型 / 速度型 | 在严格镜像基础上，将同一套可复现变体**应用于双方**，分别测整张对位或预注册对位；记录实际属性、CA、技能、位置适配，不能假定变体 CA 必然相等。 |
| 阵型与球员差异 | 至少一套 4-4-2、一套含后腰的阵型，以及前锋速度 / 后卫速度、头球的配对差异；记录阵容选择和适配，不能把阵型引起的人员变化都归因于指令。 |

现有 `technical` 是只改 A，`speed` 是只改 B 并强制其快速防反，**不是双方同一种阵容画像**；只能用于原定义的
条件实验。所有夹具记录完整快照及哈希、主客球员逐项断言、初始体力、规则和随机种子。`--exact-mirror`
已加入实验脚本用于严格复制；阵型 / 双方画像 / 无技能变体仍待实现，不能声称已跑。

### 6.2 先测行为与物理机会，再测成绩

| 假设 | 预注册对照、主指标 | 必报代价 / 反例 |
| --- | --- | --- |
| 高压更能干扰后场短传 | 固定位置先测合格上抢与接应，整场比较 `highPress` 对短传 vs 直接出球的夺回速率**增幅差** | 对手绕过压迫、身后接球 / 射门、末段体力；对手接应不可行时报告机会数 |
| 快反可利用前压 | 相同进攻方先比较对手高 / 中 / 低防线及留人，分别测身后候选、尝试 / 完成与接球后射门 | 越位、被拦截、低位对手场景；实际高位须由防线高度确认 |
| 窄低位改变中路和边路 | `defense.width=narrow` vs `normal`，只改一项；测无球实际宽度、对手中路可行线路 | 弱侧边路接球、传中、进禁区次数及进攻方自身 xG；不预设总 xG 必降 |
| 双翼能利用横向空间 | `wingPlay` vs 中性，分别面对窄守 / 宽守；测边路接球和可行传中机会的增幅差 | 防空、传中完成 / 被拦截、禁区接应人数 |
| 低熟练更不准确 | 各项固定局面及全场记录目标偏差、满足指令的候选 / 任务完成率；测试 `F=0/0.4/0.7/1` | 指令方向不能反转、宽度单独收敛；结果输赢不要求随熟练度单调 |

每个分母为 0 的场次记缺失并报机会数，埋点只观察、不额外抽随机数。应新增按真实位置定义的身后接球、
线路净空、两线间距、弱侧转移、压迫暴露 / 人数、冲刺与体能随时间数据；现有 EF / HLR 不足以单独证明因果。

### 6.3 相对中性与对位：四场因子设计

**待实现：**现有 `--matrix` 仍使用旧的 B0 残差近似；`--matchup` 只输出原始 xGD，
不会自动生成以下四场交互项或熟练度差中之差。必须扩展脚本并测试后才能按本节声称已验收。

固定 A/B 阵容画像、主客及一对熟练度，跑以下每种情况的主客各一场：

```text
Y11 = xGD(A 风格, B 风格)       Y10 = xGD(A 风格, B0)
Y01 = xGD(A B0, B 风格)         Y00 = xGD(A B0, B0)
对位交互 I = Y11 − Y10 − Y01 + Y00
```

每个 `Y` 先按同种子主客两场平均，四个 `Y` 共 8 场是一个种子块，基线场可复用但必须同步重采样。
`I>0` 表示相对这个 B0 参照，组合对 A 比两个单方改变的可加预期更有利；仍需实际机制和独立复测，
不能宣称无条件必胜。若场景并非严格镜像，必须**实际运行 `Y01`** 而不能由 `B vs B0` 取负替代。

比较熟练度时，对 A/B 的 `F∈{1.0,0.7,0.4}` 每格都算同样 `I(F_A,F_B)`，而不是仅比原始 `Y11`；
例如固定 B 比较 `I(1,1)−I(0.4,1)`。两队各自中性对照仍保留各自熟练度，才能从整体强弱里分离。
若风格根本未形成有意义的基础行为，或精度不足，不对其熟练度交互下克制结论。

建议预注册 **5 条主对位假设**，其余完整矩阵为探索：

1. 快速防反 × 高位压迫：高防线相对中性时，快反可利用的身后接球增加。
2. 高位压迫 × 短传组织：与直接出球相比，后场受压 / 高位夺回增幅更高。
3. 双翼 × 窄低位：与宽防守相比，边路接球 / 可行传中增幅更高。
4. 链式 × 中路短传：相对于正常防守宽度，中路净空减小，同时侧翼暴露可能增大。
5. 长传 × 高位压迫：相对短传，后场受压出球和远距离传球占比改变，但第二落点 / 丢球必须同时报告。

本组主要验证**行为及机会的差中之差**；xGD 交互、净胜球和胜率作为次要探索，不保证方向或强制翻盘。
每条假设在查验收集之前冻结主指标、方向、最小有意义差异、分母及多重比较族；统一用种子块 bootstrap，
例如 5 项族用双侧 99% Bonferroni 区间，并报告未校正 95% 区间。置信区间跨门槛或机会不足为不确定。

### 6.4 样本、平衡与兼容门槛

1. **固定局面 + 冒烟：**先单测候选、落点 / 结算一致、对手防线前移、左右 / 半场换边、越位开关、
   失球回撤紧急上抢、体能和 `F=0/1`；每个预注册条件先跑 `1–30` 个训练种子块，不用结果宣称正式有效。
2. **独立验收：**实现和参数冻结后使用 `10001–10200`；每个风格行为沿主文档 4.5 的 10 项族校正，
   每个预注册对位按本节 5 项族校正。先估计方差、缺失率、算力和目标区间，资源不足应报告不确定。
   若跑 11 个风格含 B0 的完整无序矩阵、含 11 个自身对局，`66 × 30 × 2 = 3,960` 场 / 画像；
   四场因子及 3×3 熟练度实验另外计数，可复用共同基线，不能把复制引用当新增场次。
3. **结果护栏：**同时报告风格 / B0 的 xG 进攻、防守、xGD、进球、控球、犯规、体力与机会分布。
   文档 4.5 的总进球偏移 `max(0.35, B0 的 15%)`、总 xG 偏移 `max(0.30, B0 的 15%)` 是调查告警。
   应消除跨画像无代价的万能模板；`±0.1～0.2 xGD` 只是探索量级，不可直接注入引擎或作为逐场硬限制。
4. **兼容与性能：**有 / 无埋点同输入物理事件和 RNG 相同；同规则连续运行与转换 / 技能触发中途恢复一致；
   旧 v4 golden、旧比赛任务 / 回放、主客半场、红牌换人及无候选均过关。登记 `Node`、源码与夹具哈希、
   规则 / 能力 / 模板 revision、版本路由及失败数，测每场耗时和内存。
