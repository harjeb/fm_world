# PvE 平衡基线（P7）

> 状态：**基线完成，样本偏小**。曲线保持 **350→1300**，当前不修改 CA；玩家成长上限由后续系统提升到 1500。
> 机器可读结果：`docs/pve-balance-results.json`；内容快照 SHA-256：`16540c9c...`。

## 方法

```bash
npm run balance:pve
# 例：真实引擎、8 场/格、3 届/杯、输出 JSON
PVE_GROUPS=peak,legend,cup,tournament PVE_CAS=800,1000,1200,1400,1500 \
PVE_STAGES=1,20,40,60,80,90,100 PVE_MATCHES=8 PVE_CUPS=3 \
PVE_REPORT=docs/pve-balance-results.json npm run balance:pve
```

- 玩家基线：先真实执行一轮完整自动培养（含项目、事件、球员卡），再保留属性形状缩放到 800/1000/1200/1400/1500。**这不是声称当前玩家已经能培养到 1500**，而是为成长上限提升后的 P7 做压力测试。
- 单场：真实 `PesEngine`（rulesVersion 4），真实点球大战，主客场各半；不再使用 v2 或“平局×0.5”。
- 整届杯赛：玩家场次用 v4，AI 对 AI 用 v2；含小组循环、淘汰赛、两回合、点球，实际统计出线率/夺冠率。
- 每格 8 场、每杯 3 届；95% 置信区间很宽，只适合发现异常，不能当作精确胜率。

## 结论与后续

1. 真实引擎下，800 CA 对 1300 终局确实不可通关；这不是规则 bug，是成长上限未到位的预期。
2. 1500 CA 对终局约 50%，终局可打但偏难；是否微调等更大样本，不先改曲线。
3. 杯赛/传奇的样本量不足以支持精确平衡，当前只用于发现规则异常（已发现并修复：小组赛点球、两回合总比分、提前泄露赛果）。
4. 奖励与技能卡仍未启用；P7 只做强度基线。
