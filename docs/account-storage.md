# 联机账号存档与世界快照

- SQLite 中的 `accounts.game_json` 保留账号进度。对手球队、共享赛区赛程、后备人才、冻结杯赛世界队分别以内容哈希引用 `account_game_parts`，账号与快照引用在同一事务内提交。
- 读取时还原保存当时的精确内容，不从当前赛季的实时球队重造对手。旧的完整行照常读取，账号正常保存时逐个转换，不在启动时强制全库重写。暂不改变服务端内存游戏结构。
- 新浏览器可通过 `X-FM-Lazy-Cup: 1`（SSE 使用 `lazyCup=1`）请求省略后备人才及冻结杯赛名单；旧客户端仍收到完整响应。打开杯赛挑战时才请求 `GET /api/pve/cup-season?season=N`。已经开始的一场旧挑战杯仍携带恢复该场所需的冻结数据。正式赛季杯赛仍由服务器结算，浏览器不需要下载对手能力。
- 世界页使用 `X-FM-World-Summary: 1` 请求榜单、赛程和俱乐部概览，点击单队才请求 `GET /api/world/club?id=...` 的公开名单。独立离线存档仍然完整，联机缓存只保存个人进度。

## 换季清理与球队继承

全服换季提交 world.json 并确认 SQLite 账号快照写入后，清理以前赛季已 published 的比赛任务（索引及 input/result 文件）。正在排队、计算或等待发布的比赛不删。任务索引先记录删除授权，崩溃重启可续做；上季的 2D 回放不再提供，比分和文字战报仍在球队存档中。

最后一次上线在第 N 赛季，整个 N+1、N+2 赛季均未上线，在进入 N+3 时删除教练账号。在线会话及已认证的 Agent 操作计入活跃，AI 自动推进不算。升级前没有上线赛季记录的账号从升级所在赛季开始计算。

删除的是教练身份、凭据和所有登录会话，而非球队。SQLite 在同一事务将完整球队进度转交给无登录凭据的托管席，有效账号计数不含托管席。它继续正常换季，不重建阵容、设施、库存或历史。回收队恢复初始名，不限级别开放注册；下任教练使用新账号 ID 和新凭据。球队存档仍需占用空间，此规则主要释放注册席位。world.json 若在交接时未写完，重启会依据 SQLite 的 club_handovers 修复归属。

## 备份与回滚

上线前备份 `accounts.sqlite`（使用 SQLite 在线备份，或停服后备份）及 `world.json`。生产服务默认不转换旧行；备份后设置 `FM_ACCOUNT_COMPACT_WRITES=1` 并重启，才启用精简写入。设回 `0` 会暂停去重，已有精简行仍然可以读取。

若要回退到**不支持快照引用**的后端，先停服并备份，用当前版本展开账号，再切换后端代码：

```bash
node --import tsx scripts/expand-account-saves.ts --server-stopped data
```

不要手工清空共享快照表。释放的 SQLite 页可以重复利用，但文件不会立即缩小；不要在上线迁移时同时做 `VACUUM`。
