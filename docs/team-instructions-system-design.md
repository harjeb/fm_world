## 1. 产品模型：风格与球队指令的关系

- **球队指令是生效配置；战术风格是指令的可编辑模板。**选「高位压迫」等于复制一组具体指令；球员如何执行取决于指令、阵型、角色、球员能力、体能、空间和对手，风格 ID 不参与模拟。
- 赛前球队指令分为 **持球、攻防转换、无球**。阵型和球员职责独立管理；调整阵型不自动清空指令。
- 球队指令表达的是**选择和站位倾向**：短传不是额外传球成功率，更多远射不是更准，反抢不是自动断球。任意指令都不强制每次动作符合偏好。
- 玩家编辑单项后显示「风格名 · 已调整」；点击恢复风格要确认覆盖哪些字段；切换模板前可预览差异。已有命名阵容预设保存的是完整阵容快照，不与风格模板混同。
- 所有生效指令、临场临时心态与比赛规则版本分别保存；执行优先级、版本与兼容性见下文。**当前 v4 只有旧五字段**，没有本文描述的新 UI 或独立指令。

## 3. 数据结构、默认值与发布能力

### 3.1 数据契约

主文档的 `TacticalInstructionsV2` 是九项首版值；以下是未来高级指令的**目标结构示意**，不是当前 TypeScript 类型。每个字段的枚举就是允许的完整值；不能用 `undefined` 代表隐藏默认值。

```ts
type Tendency = 'less' | 'balanced' | 'more'
type TeamInstructionsV3 = {
  schema: 3
  baseStyle: { id: string; revision: number } | null // 只作来源展示
  instructions: TacticalInstructionsV2              // 主文档 3.3 的九项
  advanced: {
    possession: {
      creativity: 'disciplined' | 'balanced' | 'free'
      timeWaste: 'normal' | 'more'
      drawFouls: 'retain' | 'seek'
      patience: 'patient' | 'balanced' | 'early'
      longShots: Tendency
      crossType: 'ground' | 'mixed' | 'lofted'
      crossTiming: 'early' | 'balanced' | 'late'
      dribbleFinal: Tendency
      dribbleProgress: Tendency
      supportRuns: Tendency
      receiving: 'feet' | 'mixed' | 'space'
      buildUp: 'penetrate' | 'balanced' | 'bypass'
      goalKick: 'short' | 'mixed' | 'long'
      keeperTempo: 'quick' | 'balanced' | 'patient'
      keeperTarget: 'centerBack' | 'mixed' | 'fullBack'
    }
    defense: {
      tackling: 'careful' | 'balanced' | 'hard'
      pressKeeper: boolean
      showWide: boolean
      width: 'narrow' | 'normal' | 'wide'
    }
  }
}
```

- `schema: 2` 仍是九项配置；`schema: 3` 是**未来的战术数据版本**，不是 PES 规则版本或游戏存档版本。规则版本决定引擎，schema 决定如何读取指令。schema 3 的唯一生效真值是展开后的 `{ instructions, advanced }` **整体**，不能只读取前九项而漏掉高级字段；`baseStyle` 仅作展示。主文档「`instructions` 是唯一生效真值」描述的是 schema 2，不能用它覆盖本条 schema 3 定义。
- 新增高级字段的中性值使用**具名默认对象**，不能依赖字段顺序：

  ```ts
  const neutralAdvanced = {
    possession: {
      creativity: 'balanced', timeWaste: 'normal', drawFouls: 'retain',
      patience: 'balanced', longShots: 'balanced', crossType: 'mixed',
      crossTiming: 'balanced', dribbleFinal: 'balanced', dribbleProgress: 'balanced',
      supportRuns: 'balanced', receiving: 'mixed', buildUp: 'balanced',
      goalKick: 'mixed', keeperTempo: 'balanced', keeperTarget: 'mixed',
    },
    defense: { tackling: 'balanced', pressKeeper: false, showWide: false, width: 'normal' },
  } as const
  ```

  `retain` 的含义是**不额外寻求接触**，不保证一直控球。
- schema 2 升级到 schema 3 时，只在明确升级或新规则适配中补上述中性值；不改变九项设置。**同一新规则版本和相同九项下**，全部高级字段中性应与 schema 2 的适配结果在物理事件、比分和 RNG 状态上逐位一致；剔除各自合法存在的 schema、来源元数据再比较快照。该要求不是让新规则比赛逐场等于旧 PES v4。实现方式是 schema 2 先规范化为同一 `neutralAdvanced`，两者调用**同一版本的共同基线路径**，不能分别重写随机决策；传中距离 `0.27L`、常规前插上限 2、默认门将等待、球门球回退、拼抢基线和无球宽度都应在候选、事件与 RNG 测试中逐项验证。P2 新比赛版本若需要修补共同基线，应同时作用于该版本的 schema 2 和中性 schema 3；已冻结的 P1 比赛仍运行原实现。
- 风格修订版本不可变。初次扩展 schema 3 时，原 3.5 模板和第四节实验继续使用九项值，新增项全部中性，不能悄悄让某个风格获得额外指令。以后若希望「双翼齐飞」默认尽早传中，需发布新风格 revision、展示模板差异，并用新 revision 单独复验；既有阵容不自动重写。
- 服务端维护独立的 **schema 版本、引擎规则版本和功能能力表**。P1 发布时继续接受旧结构和已实现的 schema 2；P2 / P3 按实现进度开放 schema 3 字段。某能力尚未启用时，中性值可用于向前兼容，**非中性值必须校验失败并返回字段与原因**，不得存入后静默忽略；也可直接拒绝整个未支持的 schema。旧客户端不得整档覆盖它不认识的指令。
- 每次公开新增能力、改变已有模拟行为或随机调用顺序，都需发布可路由的**新比赛规则版本**及不可变能力表修订；比赛、开球快照、锁阵和队列任务共同冻结规则版本、能力表修订 / 哈希和完整展开指令。只支持新能力前的旧任务继续使用旧规则实现，不能仅更换同名能力表。降级 / 回滚时保留原始指令并允许只读查看和旧规则回放；服务端不能执行或理解的非中性值不得静默改回默认，需拒绝新比赛 / 写入并提示升级，除非用户明确确认新的有损转换。
- 校验 JSON 的结构、允许字段与枚举，拒绝未知字段、`null` 替代枚举、非有限数及未支持指令；在服务端可信边界执行。按 `baseStyle.id + revision` 查询不到旧模板时仍保留实际指令，来源展示为「自定义」，不能重置生效值。

### 3.2 生效顺序和冲突

```text
规则版本与有效输入
  → 阵型 / 角色 / 球员及体能
  → 当前球队指令（展开后的唯一权威值）
  → 当前心态的有界临时层 + 有效转换窗口
  → 动作合法性与候选生成
  → 指令的有界偏好与任务分配
  → 物理移动、接触与现有结算
  → 事件、统计、体力、存档
```

1. 死球、场地边界、人员有效性、既有单刀候选保护和安全规则先于战术偏好。当前越位候选主要是软扣分，最终是否吹罚受开关和技能影响；沿用主文档 4.1 的规则，**不**宣称它已是统一硬限制。
2. 宽度和方向、低逼抢线和高频率、短传和反击、慢节奏和反击都允许并存，不自动修改用户设置。UI 可以说明可能产生的抵消或空间风险，但不得断言一定无效。
3. 前场耐心和远射分别控制不同维度：前者影响前场结束进攻的倾向，后者仅影响指定距离的射门候选。两者可以同向或相反；相加后统一裁剪，不能重复计算同一奖励。
4. `pressKeeper` 不等于提高 `intensity`；`tackling` 不等于更频繁安排上抢。启用逼抢门将只是让门将成为**可选目标**，自身上抢者仍不是本方门将。回撤、紧急上抢和人数上限沿用主文档 4.1。
5. 临场心态以后可在赛前指令上形成受限临时层，但均衡必须回到赛前值，重复切换不能累加。首版不承诺逐项临场编辑；联赛锁阵后预计算比赛只能观看，修改用于后续比赛。旧 v4 比赛仍按旧心态语义运行。

## 4. 指令如何影响场上行为

### 4.1 统一记号和评分预算

- 第一轮实验固定 `D=900`、11 人制、105×68 场地；主客与换边统一用 `u=(x × team.dir + HL)/L`，本方球门线为 0、对方球门线为 1。`K` 使用引擎 `PitchSpec.K`；11 人制时 `K=1`。
- `u < 2/3` 定义为**进程区**，`u ≥ 2/3` 定义为**前场区**；球在边界时只算前场。这个划分是项目设计，不是截图对两处「盘带」的官方解释。
- 主文档 4.1 的 `S传球 + S方向 + S转换` 仍先裁至 `[-0.10,+0.10]`。本文件新增的传球候选评分加成（包括创造力、破压和门将目标）求和后另裁至 `[-0.06,+0.06]`，两组再加到原有合法候选评分中；同一传球的全部新旧指令倾向因此最多 `±0.16`，不得再添加第三份风格 ID 奖励。对于纵向回传超过 `2K` 且路线净空不足 `1.5K` 的候选，禁止任何正的新增高级奖励，不能用创造力绕过主文档的危险回传保护。
- 射门、盘带、传中每个候选各将本文相关偏好项相加后裁至 `[-0.12,+0.12]`。所有偏好中性时为 0。先应用既有动作合法性及单刀保护，不能用加分让无效候选复活；禁区和危险回传遵循主文档 4.1。
- 系数是首轮建议，测试不符合目标时只在训练集调整并记录。通过实际位置、压力、路线和既有能力结算；除「拼抢尺度」明确规定的接触机会和犯规分配外，不按指令直接修改成功概率。动作打分埋点只观察，不增加随机数调用。

### 4.2 持球与前场

| 指令 | 首选机制与参数 | 成本、限制和验收方向 |
| --- | --- | --- |
| 创造力 | 对每个**原本可行**的传球、盘带、传中候选计算 `risk`：路线被阻挡程度、距离和持球压力各归一到 `[0,1]`，分别按 `0.5 / 0.3 / 0.2` 加权；盘带用行进路径净空、预计移动距离和压力。纪律 / 平衡 / 自由分别加 `−0.04×risk / 0 / +0.04×risk`。 | 只改变相对选择，不添加随机能力、成功率或射门加成；单刀和危险回传保护优先。自由风格应更多选择原本已有的高风险候选，但失误可能增加。 |
| 耐心 | 前场区且射手距对方球门 `>12K` 时，对射门、传中候选分别加 `−0.05 / 0 / +0.05`（耐心 / 平衡 / 早结束）。 | 已确认单刀、门前明确终结、定位球以及没有其他可行动作时不抑制终结；不能无止境倒脚。比较前场决策中射门 / 传中选择、每次进攻传球数和 xG。 |
| 远射 | 仅对距门 `20K ≤ d < 32K` 且原本有射门候选的动作，加 `−0.07 / 0 / +0.07`。 | 不扩大射程、不改变射门模型概率；远射比例可能提高，但每脚机会质量和拦截 / 反击风险需一起报告。 |
| 前场 / 进程盘带 | 按上面的场区只读取对应字段，对 `carryValue` 加 `−0.06 / 0 / +0.06`。选「更少」且存在安全可行传球时，允许跳过当前 `holdUntil` 强制带一步分支；安全候选要求原传球评分 `≥0.28` 且线路净空 `≥1.5K`，每个候选只计算一次并复用。单刀、无其他合法选择和紧急保护仍优先。 | 不改变速度、过人能力或成功率。自家禁区遭紧逼时不能为了造犯规额外奖励危险盘带；统计有传球备选时的带球选择、失球及推进。 |
| 造定位球 | `retain` 不加分；`seek` 仅在前场、对手距持球人 `≤2.5K`、没有明确单刀时，对盘带候选加 `+0.04`，同其他盘带偏好合并裁剪。 | 通过更可能选择持球接触，**可能**增加被犯规，也可能失球；结算的犯规和牌概率不直接提高，禁区内也不自动给点球。 |
| 传中时机 | 原提案为早 / 平衡 / 晚 `0.35L / 0.27L / 0.15L`。当前实验只实现 `early / balanced`：开放比赛的 early 按熟练度从 `0.27L` 向 `0.35L` 插值，并对合格候选最多加 `0.12 × execution`；`late` 暂不接受。 | 沿用边路、禁区接应及现有越位筛选；不直接提高成功率。首轮小样本与代价见 [验证报告 §13](./tactical-validation-report.md#13-两套阵型复验与尽早传中探索)。 |
| 传中类型 | `mixed` 维持该规则版本的原始传中方式；`ground` 贴地，`lofted` 在可行的开放比赛传中使用比中性更高、更久的弧线；详细球路与回退见下方。三者仍选可行队友 / 落点并走传球裁决。 | P2 必须先实现真实贴地轨迹、沿途拦截、接球及后续动作；贴地传中**不能**直接调用空中争顶后强制头球。高球才进入相应争顶逻辑。保留传中类型、球路和结算事件供验证。 |
| 支援跑动 | 对开放比赛的**新常规前插申请**，把允许申请时的活跃 `runTarget` 人数上限设为 `1 / 2 / 3`（少 / 平衡 / 多），沿用原有空间、体力和越位约束。转换窗口前插概率仍用主文档 `0.08 / 0.12 / 0.16`。 | 平衡上限 2 与首版一致；P2 的 `more` 明确只在本规则扩展该上限到 3。活跃人数沿用原实现的所有有效 `runTarget` 计数（包含传中冲点）；`sendRunners` 是独立任务，仍可直接安排，故该上限不是对全队所有跑动的硬限制。跑动变多可能减少后场接应。 |
| 接球 | `feet` 以接球人出脚时当前位置为目标；`mixed` 沿用原提前量；`space` 令 `t=clamp(d/15,0.3,1.2)`，以 `接球人位置 + 接球人当前速度 × t` 为目标，提前位移长度裁至 `6K` 并将坐标裁在球场内 `0.5K`。接球人速度 `<0.5` 米 / 秒或裁剪后提前量 `<0.2K` 时回退 `mixed`。 | 传球裁决、飞行和拦截使用同一个实际目标，不能只改动画。越位另按**出脚瞬间接球人位置**与规则参考线判定，不把目标落点当球员位置；接球人不能瞬移。报传球目标位移、接应成功、越位与失球。 |

**创造力的可复现风险分：**对持球者 `p` 与目标点 `T`，沿用现有 `laneClearance(p,T,opps)` 得到最近对手离线路的距离 `lane`，没有对手时按 `6K`；距离 `d=dist(p,T)`，压力 `press=clamp(pressure(p),0,1)`。令 `risk = 0.5 × (1−clamp(lane/(6K),0,1)) + 0.3 × clamp(d/(40K),0,1) + 0.2 × press`。普通传球的 `T` 为出脚时接球人位置，传中用候选落点；盘带用沿进攻方向向前 `5.5K` 的点。固定例：`lane=3K,d=20K,press=0.4` 时 `risk=0.48`、自由项 `+0.0192`、纪律项 `−0.0192`。相同局面所有值与评分分支必须可从埋点重算，不能另抽随机数。

**传中与越位的既有边界：**当前 `crossOption` 实际上对开放比赛传中候选执行无条件 `!isOffside` 筛选，即使越位开关关闭也会筛掉；这与普通传球主要用软扣分并非同一语义。P2 的类型 / 时机首轮沿用本规则的传中路径及其筛选，不新增更多越位限制，也不声称它已经完整支持越位开关 / 技能。若要修复该既有问题，应另起比赛规则版本并验证现有旧回放、越位关闭、技能和两类传中；不能为满足本设计悄悄改变 v4。

**传中轨迹起点：**仅对开放比赛的 `crossOption → execCross` 生效，角球和任意球传中沿用原规则。现有中性传中计划飞行时间 `tf0=clamp(d/15,0.9,1.9)`；`mixed` 原样执行。`lofted` 令 `tf=min(2.2,1.15×tf0)`，横向速度为目标位移 / `tf`，竖直初速为 `4.905×tf`，以更高弧线近似到同一目标。`ground` 用贴地传球路径、保持 `loft=false`，轨迹到地面后必须允许实际拦截 / 接球，不能走原来的空中落点自动头球路径。`d`、目标、结果与拦截者仍来自一次实际传球裁决；对不可执行贴地 / 高球的候选记录原因并回退 `mixed`，不得把回退伪记为指令成功。

### 4.3 后场组织与门将

| 指令 | 首选机制与参数 | 成本、限制和验收方向 |
| --- | --- | --- |
| 进攻启动 / 破压 | 仅本方后 1/3（`u < 1/3`）且 `pressure ≥ 0.25`：`penetrate` 对向前 `≥5K`、传球路线净空 `≥1.5K` 的候选加 `+0.05`；`bypass` 对距离 `≥25K` 的候选加 `+0.05`；均衡为 0，计入进攻候选的 `±0.06` 总预算。 | 「穿透」可尝试从压迫间向前传，「绕过」更可能选择较远目标；路线、守门员、越位和能力决定实际结果，不强制穿透或免疫压迫。 |
| 活球门将出球速度 | 快 / 耐心的持球等待建议为 `0.5–0.9 / 1.2–2.0` 模拟秒；平衡**逐来源沿用既有初始化**，不是统一 `0.9–1.8`。在每个实际获得持球的位置统一初始化一次，覆盖抱球、近身没收、普通接球及门将出球分支。 | 快 / 耐心用该来源本来就要抽取的一个均匀随机数映射到相应区间，不额外抽签；对手接近 `≤3K` 时允许提前出球。平衡必须保持既有原分支和随机调用顺序；引入合法持球上限时优先于指令。 |
| 活球门将出球对象 | 平衡不加分；选中后卫 / 边后卫时，对开赛阵型对应仍在场且原本可行的 `CB` / `LB,RB` 传球候选加 `+0.06`，计入 4.1 的高级传球总预算。 | 不满足条件、位置缺失或所有候选不安全时，沿用普通候选 / 解围回退，不能死等或强制传危险球；对象偏好只改变选择，不提高传球成功率。 |
| 球门球 | 在 `goalkick` 的实际出脚路径独立选择：短传在距离出脚者 `≤20K`、长传在 `≥30K` 的优先候选中，按**含高级偏好且已裁剪**的最终评分选最高者，同分按 `pid` 升序；原 `passValue` 只用于判断安全门槛。混合或没有目标时走该规则原有重新开球出脚逻辑。 | 必须保存发球上下文至实际出脚或取消，并区分门将被罚下时的外场发球；详细生命周期见本节下方。目标距离是发球者到出脚瞬间接球人位置，不是最终球路落点。 |

**门将与球门球的状态、选择及优先级：**

1. `keeperTempo` 在活球门将**首次实际取得控制**时初始化一次并保存 `holdUntil` 和持球来源。抱球、没收、普通接球和无现成 `holdUntil` 的门将控制都要覆盖：非中性用该来源原本抽取等待时使用的均匀 `u∈[0,1)` 映射到对应区间，若该来源原本没有此抽签则取确定性中点 `u=0.5`，不得为此额外消费主 RNG。平衡保持原有逻辑和 RNG；保存后恢复不能再初始化或再抽。非中性期间每次决策时如对手距离 `≤3K`，可以将剩余等待提前到当前步，实际选择仍需要合法候选。
2. 当前重开球在将球交给发球人后会清掉 `restart`，所以新规则要独立保存 `restartContext={type, team, takerPid, pendingFirstAction}`。球门球发给发球人时开始生效；首次主动传 / 传中 / 解围 / 射门、对手实际控球、发球人离场、再次死球、半场或 `3×D/900` 模拟秒超时即清除。该状态进入快照和回放；外场球员替代门将开球也使用相同规则。
3. 非中性球门球 / 门将目标的**优先候选**可行性要求接球人在场、非发球人、未眩晕，且原候选评分 `≥0.28`、线路净空 `≥1.5K`；不能让目标偏好把原本不安全候选变成优先候选。只计算一次候选得分并缓存，平分按 `pid` 排序。短 / 长球门球有合格范围候选时在该范围中选择最高分；找中卫 / 边卫的 `+0.06` 计入该候选的高级评分预算，且仅在发球人是门将时适用。无范围候选时退回普通路径而不是死等；`goalKick=mixed` 和全部高级值中性时不得新增筛选或随机调用。
4. 球门球与门将目标同时启用时，**球门球先限制范围**，再在范围内按已有评分和门将目标偏好排序；没有范围候选才回退普通门将决策。`keeperTempo` 控制实际持球等待，不代替球门球范围选择；重开球取消后其他活球出球只使用门将字段。
5. 为让逼抢门将通过真实压力传导，P2 的新比赛规则须让所有球队（无论 schema 2 / 3 或 `pressKeeper` 开关）在门将出球候选中读取**实际物理压力**。这是对该新规则共同基线的修改，不是因开启 `pressKeeper` 直接附加压力；先冻结 / 保留 P1 和 v4 规则并另测基线变化。相同物理局面下只改对手 `pressKeeper` 标签，不得改变传球结算概率；仅球员移动后产生的实际压力可以改变决策和结算。

### 4.4 无球与攻防转换

| 指令 | 首选机制与参数 | 成本、限制和验收方向 |
| --- | --- | --- |
| 防守宽度 | 对无球队形目标，以在场外场球员的防守目标横向中心为轴，窄 / 正常 / 宽分别缩放相对距离为 `0.85 / 1.00 / 1.15`，再裁到场内并执行最小间距。 | 独立于持球宽度；不直接更改球员能力。观察防线 `P90−P10`、中路及边路的实际空间与对手射门。 |
| 拼抢尺度 | `tryTackles` 外层和 `tryTackle` 内层共用一个实际接触半径：标准 11 人制建议 `1.4 / 1.6 / 1.75` 米（小动作 / 平衡 / 凶狠），`distance ≤ radius` 才进入，其余仍受冷却、站位及角色限制。共享结算的 `foulShare` 在原中性结果上分别乘 `0.85 / 1 / 1.15`，再裁在 `[0.10,0.35]`。 | 原外层 `<1.7` 不可截断 `1.75` 凶狠距离；非标准场地需在新规则中单独标定。`foulShare` 只在一个共享结算位置调整，不能再额外给抢断成功率加成；分别测试盘带对抗与战术犯规。 |
| 对门将逼抢 | 默认 `false`；开启时，将对方活球持球门将加入上抢目标，仍遵循逼抢线、距离、人数、留人及回撤窗口规则。针对该门将的实际位置压力须能进入其出球评估；没有球员接近时不额外增加压力。 | 不能传送球员、增加人数或直接判门将失误；固定局面应显示上抢任务、实际距离和出球变化，其他时间与默认行为一致。 |
| 逼对手走边路 | `true` 且已合法选出持球人上抢者时，令 `side=sign(ball.y)`；若球正好在中线则用 `sign(presser.y)`，两者都为 0 时偶数 `pid → +1`、奇数 `pid → −1`。上抢目标横坐标设为 `ball.y − side × 1.5K`，裁到场内；其他任务不变。 | 这是尝试从中线侧封路，不修改对手指令或强制球路；应统计对手实际向边路的出球比例，也要看中路漏人和被突破。 |
| 得 / 失球转换 | 仍使用主文档 4.1 的 `1.5` 模拟秒窗口、候选确认、暂定 / 挂起、回撤、反抢和存档规则。 | 不再为 schema 3 额外叠加一套反击或自动抢球概率。P1 单独达标后才能把高级项叠上去。 |

**拼抢的条件概率与数值例：**令现有 `dribbleModel.p=q` 为持球方过人成功概率，现有中性 `foulShare=f0` 是「过人失败后发生犯规的条件比例」，新值 `f=clamp(f0×factor,0.10,0.35)`。沿用现有 `dribbleOdds`：`P成功=q`，`P犯规=(1−q)f`，`P干净抢断=(1−q)(1−f)×0.72`，`P其他无主球=(1−q)(1−f)×0.28`，四项和为 1。例：`q=0.60,f0=0.20`、凶狠 `factor=1.15`，则 `f=0.23`，四项分别为 `0.60 / 0.092 / 0.22176 / 0.08624`。这也表明提高犯规分配会改变条件抢断比例，不能再叠另一份「成功率奖励」。这是共享内核 `dribbleOdds` 的原始分布；PES 后续还有现有 `DUEL_RATE` 对接触机会的处理，最终事件频率不能直接拿本例的四个数冒充。战术犯规路径也只读取这个 `f` 一次并沿用其现有裁剪；混合结构双方分别计算。

### 4.5 拖延时间：有前置条件的 P3

当前 PES 在开球 / 重新开球等待时不推进比赛 `time`，不能只把等待动画加长然后宣称消耗了比赛时间。P3 必须先设计统一比赛钟、死球计时、补时、半场 / 终场边界和回放，并冻结新规则版本。

作为**实验起点**，`more` 每次可选择的死球准备额外消耗最多 `0.25 × D/900` 模拟秒，每半场总预算最多 `2 × D/900` 模拟秒；该等待计入比赛钟，并按已公布的规则计入补时。限制仅作用于合法可拖延的重开球，不冻结对手、不跳过比赛、不延长活球持球规则。`normal` 为 0，且要与原有新规则基线一致。完整补时公式和对现有时钟的改造必须先经单独设计与验证；在此之前服务器拒绝 `more`，UI 标记「尚未开放」，P1 / P2 的统计和样本不包含该指令。

## 5. UI 与一次完整编辑流程

### 5.1 界面分组

- **持球 / 概况**：传球、节奏、宽度、方向、创造力、拖延、造定位球。
- **持球 / 前场进攻**：耐心、远射、传中时机与类型、前场盘带。
- **持球 / 进程**：支援跑动、进程盘带、方向、接脚下 / 空当。方向与概况是同一个 `focus` 的两个入口，不存两份状态；两个盘带则是本文明确的两个不同场区字段。
- **持球 / 组织进攻**：破压、球门球、门将出球速度与对象。
- **攻防转换**：得球后与丢球后。
- **无球**：防线、逼抢线、压迫频率、拼抢、门将逼抢、防守宽度、逼边。

每个控件展示当前值、简短行为解释、可能代价和「默认 / 已调整」；高级字段不支持时显示原因及开放状态，但不可提交非中性值。界面提示是定性建议，不用未经验证的数值声称胜率提高。

### 5.2 示例：从高位压迫改成短传并压迫门将

1. 玩家应用主文档 3.5 的「高位压迫」模板，复制完整九项；高级字段在对应 schema 发布时全部取中性值。
2. 玩家将传球从混合改为短传；如果 P2 已实现，再开启 `pressKeeper`。标题显示「高位压迫 · 已调整」，预览展示两个字段变化及潜在风险。
3. 保持其他球员、阵型和指令不变；保存时服务端验证并写入完整展开值。风格来源只用于展示，战术决策读取实际字段。
4. 联赛锁阵前保存影响本场；锁阵后修改只影响后续场次。重新应用模板要确认覆盖短传和门将逼抢，而不是暗中撤销手动修改。

## 7. 逐项效果目标和验证

### 7.1 可观测量

下列量均分开记录分子、分母和未发生机会的场次；不要将无分母记为 0。固定场景使用主文档 4.5 的夹具、主客配对、种子和规则。指令参数先做固定局面单元测试，再做完整比赛统计；**表中的变化范围都是尚未验证的方向性假设，不是实现时写入的概率修正**。

- `Choice(A)`：先选定**同一机会集**：在指定区域 / 条件中，A 与至少一个不属于 A 的其他动作均为合法候选的决策。分母为这些决策数，分子仅为其中**最终执行** A 的决策数，按场汇总；A 可以是「射门或传中」这样的集合。强制动作、无其他可行候选或裁决前被犯规中断的决策不进该机会集，原有随机改选以最终动作归类并另计。必须保证 `0 ≤ 分子 ≤ 分母`，零分母记缺失；额外保存备选动作和裁剪前后评分。
- `Target(C)`：出球目标属于 C 的实际出脚次数 / 可选 C 且最终出脚的次数；同时报告「没有合格 C」次数。**分子也必须只包含分母内的合格场景**。
- `CrossEarly`：从到底线距离 `>0.27L` 的区域发起的开放比赛传中出脚次数 / 所有开放比赛传中出脚次数；`CrossLate` 改为到底线距离 `≤0.15L` 的传中数 / 同一分母。分别用于早 / 晚两档：平衡和晚传都不能超过 `0.27L`，所以不能用 `CrossEarly` 判晚传。报告原始次数与空场数。
- `GKWait`：活球门将实际持球至**主动传球、传中、解围或射门出脚**的模拟秒，提前出脚也算已观察结果；按场先求完整出脚样本的均值，再做主客配对。对手或队友在出脚前实际获得球权、门将受伤 / 红牌 / 换人导致失去球权是竞争事件，半场 / 终场或再次死球发生在未出脚前是右删失；分别记录数目与时间，不计作 0 或完整出脚。某场无完整出脚则缺失；报告非参数生存曲线和竞争事件比例，若任何场景两组的删失或竞争事件比例差超过 **5 pp**，将该项正式判定降为「不确定 / 选择偏差」，仅作探索。
- `PressGK` 主指标：对方活球门将持球的每个模拟步，**假设允许以门将为目标**（无论待测 `pressKeeper` 是开或关），若常规 / 反抢条件允许且至少有一名在场外场球员符合当时区域、体力、搜索距离和人数规则，则计入「合格暴露」；其中有至少一人实际承担主动上抢任务且距门将 `≤7K` 的时间为分子，分母为全部合格暴露时间。另以全部对方门将持球时间为分母报告全暴露占比；无合格暴露记缺失。由于实际球员位置可受战术影响，两种分母都不能直接解释为每次开球的无条件效果。
- `DefWidth`：对手稳定控球暴露期间，本方外场球员 `y` 的 `P90−P10`，每模拟秒采样并按场取均值；红牌和不足 8 人时按主文档 `W` 规则处理。
- `SupportCount`：本方开放比赛稳定控球暴露期间，每模拟秒数当前活跃、由常规前插决策产生的 `runTarget` 人数，按场求均值；需给 `runTarget` 增加仅供观测的来源标记，传中冲点不计入本指标，独立报告。无有效采样记缺失。
- `GoalKickShort / GoalKickLong`：球门球上下文内，每次发球人首次**实际主动出脚**均进入分母，包括传球、传中、解围和射门；前者分子是传给出脚瞬间距发球人 `≤20K` 队友的次数，后者分子是传给 `≥30K` 队友的次数。没有目标的解围 / 射门只计分母；无出脚的取消 / 超时单独计数，不记为成功或 0。每场零分母记缺失。
- `CrossGroundRate`：`ground` 档实际传中中，出脚前被判定为可执行贴地轨迹的机会中，真实以贴地状态出脚的比例；不可执行及回退以全部传中出脚为分母另报。`CrossFlight`：实际开放比赛传中计划飞行时间 `tf` 的每场均值，用 `lofted − mixed` 比较；固定完全相同局面另做配对轨迹公式测试。两指标都需报告出脚数、实际飞行提前被拦截数和零分母场次。
- `RiskChoice`：按 4.2 的候选风险评分，分别计算实际选择的合格传球 / 带球 / 传中各自风险均值；创造力的预注册主指标是**同类传球风险均值差**，其余两类及类型占比单独报告，不把样本构成变化误认为同类动作更冒险。
- `ShowWide`：对手实际出脚的开放比赛传球中，若我方已有合法上抢任务且上抢者距持球人 `≤7K`，则计入分母；目标接球人出脚时位置满足 `abs(target.y) − abs(carrier.y) ≥ 2K` 的记入分子。记录满足条件的传球、射门 / 带球及上抢暴露总数；没有合格传球记缺失，不把对手未传球的时间当作不往边路。
- `xGD`、实际净胜球、比分、胜平负、犯规、黄红牌、球权和比赛内体力：沿用主文档 4.2 / 4.4，分别报告，不能以单一比分判断某一指令有效。

### 7.2 独立指令的初始目标

每行只改 A 队的该字段，**同一场景内**其余指令、球员、对手和规则完全一致；跨场景的对手按主文档 4.5 固定，其中速度场景的对手是快速防反而非中性。与相同场景的平衡 / 默认值比较，单位 `pp` 是百分点。两端均有设置时分别与中性对照，不能只比较两个极端。范围是调参和审查的起点，超出不自动判错，尤其少见机会必须先报告置信区间。

| 指令 | 一个预期行为方向与首轮范围 | 必须同时看见的代价 / 边界 |
| --- | --- | --- |
| 创造力 | `free` 的 `RiskChoice` 在同类候选中较平衡 **+0.01～+0.08**；纪律倾向相反。 | 原本可行候选、传球失误、各类动作占比；不能改变结算成功率。 |
| 前场耐心 | `patient` 的前场 `Choice(射门或传中)` **−2～−10 pp**；早结束倾向相反。 | 单刀未被抑制、每次进攻推进和 xG；少射不等于更会创造机会。 |
| 远射 | `more` 在 `20K–32K` 有合法射门机会时的 `Choice(射门)` **+2～+10 pp**；`less` 相反。 | 报远射次数、每射模型 xG 和射门总数，不加大射程或射准。 |
| 前场盘带 | 前场 `more` 的 `Choice(盘带)` **+2～+10 pp**；进程区该字段单独改动时应无直接评分差。 | 前场失球与推进；固定局面测场区边界、`holdUntil` 和单刀。 |
| 进程盘带 | 进程区 `more` 的 `Choice(盘带)` **+2～+10 pp**；前场字段不受直接影响。 | 后场带球失误、推进与受压；不直接提高过人能力。 |
| 造定位球 | `seek` 在前场有合格近身对手时的 `Choice(盘带)` **+1～+8 pp**。 | 被犯规和失球分别报告；不预设犯规增加，更不凭空判点球。 |
| 传中时机 | `early` 的 `CrossEarly` **+3～+15 pp**；`late` 的 `CrossLate` **+3～+15 pp**。两档使用不同指标。 | 记录可行候选、传中数、距离和成功 / 被拦截；没禁区接应时不能强制出球。 |
| 传中类型 | `ground` 的 `CrossGroundRate` 首轮目标 **≥95%**，按单组绝对值检验而不是对照差；`lofted` 的主比较为 `CrossFlight` 相对 `mixed` **+0.10～+0.30 模拟秒**。固定同一传中局面应验证 `lofted` 未触顶时计划 `tf` 恰为中性的 `1.15` 倍。 | 中性 `mixed` 原本就是高球，所以高球占比不能证明 `lofted` 与中性不同；分别报计划 / 实际飞行时间、提前拦截、不可执行与回退。贴地球不得自动触发空中争顶。 |
| 支援跑动 | `more` 的 `SupportCount` **+0.1～+0.5 人**，`less` 相反。 | 同时人数上限、越位、后场保护与跑动消耗；传中冲点另计。 |
| 接球 | `space` 的实际瞄准点距接球人出脚时位置均值 **+0.5～+3K 米**；`feet` 的同一指标预期 **−0.5～−3K 米**。两档各自与 `mixed` 比较。 | 报实际完成率、接球人是否移动、目标越界和越位；不可让接球人瞬移。 |
| 破压 | 合格后场受压机会中，`penetrate` 的向前 `≥5K` 传球选择 **+2～+10 pp**；`bypass` 的 `≥25K` 传球选择 **+2～+10 pp**。 | 机会基数、失球与推进必须分开；不保证成功破压。 |
| 门将速度 | `quick` 的 `GKWait` **−0.2～−0.8 模拟秒**，`patient` 倾向增加。 | 按完整出脚样本计算，同时报告提前出球、右删失、目标选择及既有合法持球规则；不靠额外删减比赛钟。 |
| 门将对象 | 有合格中卫时，`centerBack` 的 `Target(CB)` **+3～+15 pp**；边卫设定对应比较 `Target(LB/RB)`。 | 不合格与无对象次数、回退、失误；不能强制传危险目标。 |
| 球门球 | `short` 的 `GoalKickShort` **+3～+15 pp**；`long` 的 `GoalKickLong` **+3～+15 pp**。 | 只统计球门球实际首脚，记录无候选回退、未出脚取消及实际落点。 |
| 拼抢尺度 | 固定标准场地接触局面先精确验证触发距离 `1.4 / 1.6 / 1.75` 米；整场 `hard` 的近身对抗尝试 / 对手控球分钟探索 **+2%～+15%**，`careful` 预计 **−2%～−15%**。 | 犯规、牌、对手成功过人与原始球员能力；不能叠加另一份抢断成功率加成。 |
| 对门将逼抢 | 合格门将持球机会中 `PressGK` **+3～+15 pp**。 | 同时测低逼抢线及回撤例外、实际出球变化和留人；无合格目标时不得凭空加压力。 |
| 逼边 | 已有合格上抢机会中，固定局面接近目标朝中线偏 `1.5K`；整场 `ShowWide` 探索 **+1～+8 pp**。 | 同时记录传球、射门 / 带球、上抢暴露和中路机会；对手可以不服从。 |
| 无球宽度 | `narrow` 的 `DefWidth` **−1.5～−6K 米**，`wide` 倾向相反。 | 检查边线裁剪、红牌、边路和中路威胁；与持球宽度分别实验。 |
| 拖延时间 | P3 时测试计时、半场预算、补时及回放；在计时方案冻结前**不设整场效果通过值**。 | 当前不允许开放非中性值，不把等待动画当作真实消耗的比赛时间。 |

`进攻方向 / 传球 / 节奏 / 持球宽度 / 防线 / 逼抢线 / 频率 / 得球 / 失球` 这九项继续执行主文档第四节已给出的固定局面检查及探索性单项全场对照；主文档只为**整套风格**预注册正式多重校正，不声称 P1 的每个单项已正式统计通过。P1 是否开放由确定性机制、有效入口、兼容和风格验收综合决定；若要正式宣称每档有效，必须另行预注册逐档门槛与比较族。本节 `m` 只包含实际开放的 P2 非中性档位，P3 暂不计入。

### 7.3 测试流程和结论标准

1. **字段契约：**逐字段测试每个枚举合法、非法值被服务端拒绝、不支持的非中性能力不能保存、UI 与提交一致、预设保存 / 恢复及 schema 2 → 3 中性迁移；同展开指令不同风格来源不影响 RNG 和事件。
2. **固定局面：**固定位置、球员、球权及随机输入，分别测每项影响的目标、候选、评分、调度和结算；涵盖主客 / 换边、边界等号、无候选、红牌、门将、单刀、禁区和对手正在压迫等场景。测试 `Choice` 仅 A 可行 10 次、A / B 同时可行且选 A 1 次时应为 `1/1`，不能得到 `11/1`。尤其验证同局面只改新压迫频率时，基础犯规 / 抢断概率不变；只改拼抢尺度时才启用 4.4 的显式路径。
3. **单项全场：**基线使用主文档 4.5 的镜像、技术、速度型三场景，每次只改变一项，以同种子下「本方试验主客各一场 + 本方中性主客各一场」为种子块；上下档分别与中性比较。每字段、每档先用 30 个种子块做烟雾，每三场景是 **360 场**；双端各测一次共 **720 场**，可先试跑估算时间与缺失率。
4. **正式统计：**P2 默认用主文档 4.5 的训练种子 `1–200` 调参，冻结后用独立验收种子 `10001–10200`；每场景每档 200 个四场种子块，即 **800 场**，三场景单档 2,400 场、双端 4,800 场。布尔项只测一个非中性档；可复用完全相同的基线场次，但必须保留种子块相关性。按主文档 4.5 的完整块、非线性比率和 95% 完整块门槛计算；仅对该发布批次中事先冻结、可用的 **P2 非中性档位主检验**计数为多重比较族 `m`，以双侧 `1−0.05/m` Bonferroni bootstrap 区间分类。两端方向使用 7.2 表各自的定义，无法达到机会量或精度时为不确定；不能假设两个极端必然对称。
   - 7.2 中写「相反 / 倾向相反」的非中性档，以该行相同指标的相反方向为预注册方向；`early` / `late`、两种门将目标、`ground` / `lofted`、`short` / `long` 使用各行明确给出的不同指标。对大多数档位，先计算试验档与中性档的效果差，再按预期方向正向化：校正区间下界严格高于门槛为「行为有效」，上界严格低于门槛为「未达标」，其余为「不确定」。`ground` 是明确的**例外**：对 `CrossGroundRate` 的单组绝对值（不是减中性）做同一校正区间判断；此检验计入 `m` 一次，以同一种子的 `ground` 主客两场组成单组种子块、同步重采样三场景；单组完整块只要求两场 `ground` 都有分母，不要求中性 `mixed` 具备 `CrossGroundRate`。仍按场、主客、种子和场景等权计算，另报告同组 `mixed` 作为参考。
   - 初始最小有意义差异：百分点类（`Choice`、`Target`、`CrossEarly` / `CrossLate`、`PressGK`、`ShowWide`、球门球比例）为 **1 pp**；`RiskChoice` 为 **0.005**，`SupportCount` 为 **0.05 人**，接球提前距离为 **0.25K 米**，`GKWait` 为 **0.10 模拟秒**，`DefWidth` 为 **0.5K 米**，拼抢尝试相对速率为 **1%**。`ground` 的单组绝对门槛为 **90%**；`lofted` 的 `CrossFlight` 相对 `mixed` 增加门槛为 **0.05 模拟秒**。表中的理想范围不是直接通过规则。
   - 为避免仅凭少数机会宣称有效，百分比和风险指标每场景每档 / 中性组各至少需 **200 次相应合格机会**；`GKWait` 每组至少 **100 次完整出脚**，`PressGK` 每组至少 **20 模拟秒合格暴露**，`SupportCount` / `DefWidth` 每组至少 **1,200 个一秒采样点**。`CrossGroundRate` 是单组绝对检验，只要求 `ground` 组满足对应机会数，中性组的传中 / 轨迹数据作为参考报告。这些要求同时独立于完整块比例和区间精度；不满足时为「不确定 / 机会不足」，并报告缺失与选择偏差。拖延 P3 未开放，不纳入本次 `m`。变更样本、能力批次或门槛必须在查看验收数据前冻结。
5. **结果及组合：**逐项汇报主指标及 `xGD`、净胜球、胜平负和风险；结果分析不预设所有指令都改善成绩。再测第 6 节组合与主文档 3.5 的整套风格；确认没有预算绕过、不可解释的万能组合、严重帧率下降或旧回放分叉。P2 新风格 revision 若非中性，需重新跑风格对照，不能沿用 P1 的验收结论。
6. **报告：**至少输出代码 commit / dirty 状态、Node 与引擎规则版本、schema 和能力表、完整输入快照及哈希、指令与对照、种子、分子 / 分母、各场景和总体差值与区间、缺失原因、异常种子、结果和风险。分别标记「已实现」「行为有效 / 不确定 / 未达标」「结果变化为探索 / 证据不足」「兼容通过 / 未测」。

## 8. 推荐实施顺序

1. **P0 基线与兼容：**冻结 v4 回放样本，设计服务器校验、旧客户端保护、新旧混合视图、队列和快照路由；修复或明确隔离影响恢复确定性的既有状态。
2. **P1 九项：**实现主文档 3.3–4.5 的首版 schema、模板、行为、UI 和单项 / 风格实验；没有实测前不宣称有效。
3. **P2 高级指令：**优先前场选择、跑动与门将出球；再实现贴地传中 / 真实接球、无球宽度、逼门将、拼抢与逼边。每项只有通过固定局面、回退、对应非中性档的正式单项全场验收和兼容测试，才开放 UI 和非中性服务端写入；若证据不足则暂不开放，不能将其写成已证明无效。
4. **P3 比赛钟 / 拖延：**独立设计比赛钟与补时，验证队列、直播、回放、旧存档及不同时长；完成前不可开放拖延值。
5. **后台 AI：**另定 v2 与新指令兼容投影，或评估改用 PES 的吞吐量和规则一致性；验证后再把高级指令分配给后台 AI。

本文件中的 P2「接空当 / 无球宽度 / 尽早传中」已有实验原型和小样本探索，其他 P2/P3 项仍是设计；尚未完成正式验收、服务端与 UI，见验证报告。
