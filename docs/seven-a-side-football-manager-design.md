# 《七人·青训经理》设计方案 v0.3

> 历史设计稿，部分规则已过时：当前培养从现有能力累积，主属性范围为 0–1500，隐藏属性范围为 0–20，不受 PA、个人天花板或球场等级限制；设施提供额外成长。下文的 0–100 属性尺度等旧规则仅供历史参考，比赛与 CA 仍使用内部 0–100 评分。实际规则以 [README](../README.md) 为准。

> 一句话：通过事件和训练反复培养有个性的球员，把他们组成七人球队，用战术和技能配合争取胜利。
>
> 本文是原创玩法提案，不是对现有篮球游戏算法的照搬或已经验证的实现。所有概率、权重、时长和产量都是原型起点，必须通过模拟与试玩调整。

## 1. 产品方向

### 1.1 三个核心乐趣

1. **养人**：相同球员可以经历不同事件，培养成不同流派，而不只是重复升级。
2. **配队**：培养出的射手、组织者、拦截者、门将各有所长，不能只按总评分选七个人。
3. **看球与指挥**：玩家看得懂机会如何形成，也接受强者偶尔失误、弱者偶尔进球。

核心循环：

```text
选择球员原型 → 一轮事件式培养 → 保存培养结果
       ↑                         ↓
复盘短板、重新培养 ← 七人制比赛 ← 组队、技能搭配、设置战术
```

首版定位为单人 PvE 经理游戏，包含短赛季和挑战赛。先验证培养与比赛是否好玩，不先做交易市场、实时 PvP、开放世界或完整俱乐部经营。

### 1.2 和篮球项目相似、不同的地方

- 保留：单球员培养、事件选择、属性与技能联动、按步骤结算、战报驱动表现。
- 改变：足球没有固定“同位置一对一”，传球线路、接应、协防与攻守转换更重要。
- 改变：一段进攻不是每次都射门；回传、被迫横传、失去球权也必须有意义。
- 改变：经理主要决定人员和打法，不靠连续 QTE 操控每次触球。

## 2. 球员培养：一次培养是一条独立路线

### 2.1 球员原型与培养成品分开

**球员原型**保存姓名、外观、初始属性、潜力 PA、单项天花板、惯用脚、初始位置熟练度、成长性格和一个专属特性。
**培养成品**保存本次训练形成的属性、位置熟练度、已学技能、成长经历和打法标签；当前能力 CA 由永久属性计算，不另发一份“战力值”。

建议一轮培养为 **6 周，每周 3 个行动，共 18 次行动**，目标体验时长 15～25 分钟。
每两周有一次测验或小比赛；测验不额外占训练行动，但不能无限重打刷奖励。

行动选择：专项训练、配合训练、休息、参加导师活动。玩家每次都能看到基础收益、疲劳变化和可能出现的事件类型。

### 2.2 “养得不好，可以继续养”的规则

这里建议采用“重新开一轮培养”，而不是在同一个成品上无限叠属性：

- 重养从相同原型出发，**旧成品仍然可以上场**。PA、单项天花板和初始位置熟练度不重新抽取，也不继承上次成品的成长。
- 新一轮结果先作为候选，结束后展示新旧属性、技能和适用打法的对比。
- 玩家明确确认后才能替换；失败、退出或重养本身不会删除旧球员。
- 同一原型的不同成品不能同时上场，防止复制七个同样的明星。
- 重养可解锁已见事件的文字跳过和路线提示，但不永久累加属性。
- 首版保留“当前成品＋一个候选”，不先做复杂的版本仓库。

重点是让玩家追求“更适合这支球队的版本”，而不只是追求更高总评分。

### 2.3 一次训练如何结算

```text
选择训练 → 展示基础收益/风险 → 扣除本次行动
→ 结算训练 → 至多触发一个主事件 → 应用选择结果 → 保存进度
```

初始参数示例：专项训练增加主属性 2～4 点、相关副属性 0～1 点；疲劳与训练类型决定收益档位和失误风险。具体总成长预算需要与 18 次行动一起校准。

- 所有永久属性同时受单项天花板和 PA 总预算约束；高属性阶段成长成本上升。
- 高疲劳训练可能收益减少，并增加下一次恢复需求；首版不设计永久伤病毁卡。
- 训练失误仍给少量基础成长，避免一次随机事件直接毁掉整轮体验。
- 明确区分培养期疲劳与比赛体力，不能把养成状态无说明地带入正式比赛。

### 2.4 借鉴 FM 的 CA / PA，但不用它们直接判比赛

以下是本作自定义规则，借鉴 FM 的能力/潜力概念，**不是 FM 内部公式的还原**。

| 概念 | 本作定义 | 对比赛的直接影响 |
| --- | --- | --- |
| 当前能力 CA | 已拥有永久属性所占的能力预算，建议内部使用 0～200 刻度 | 不进入动作成功率，只用于培养约束和展示 |
| 潜力 PA | 这个原型最多可以承载的能力预算 | 不加射门、传球或进球概率 |
| 单项天花板 U_i | 某项属性可以永久训练到的最大值 | 通过最终练成的属性间接影响比赛 |
| 成长效率 | 职业素养、成长阶段、疲劳及事件共同影响的训练效率 | 不作为额外比赛加成 |
| 当前状态 | 本场体力、压力和临时效果 | 影响本场表现，不重新计算永久 CA |

**PA 决定总量，单项天花板决定方向，训练选择决定分配。** 高 PA 不意味着可以把每项都练满，也不意味着一定比已经成型的低 PA 球员更强。

一套可用于原型的预算公式：

```text
B(a) = Σ w_i × (a_i / 100)^2
CA(a) = 200 × B(a) / Σ w_i

永久属性约束：1 ≤ a_i ≤ U_i ≤ 100，且 CA(a) ≤ PA
```

`a_i` 为永久属性，`w_i` 是固定成长成本权重。首版可全部取 1，再用数据校准：外场预算包含第 4.1 节的 18 项，门将包含这些属性及 4 项门将能力。成本集合随原型固定，不随上场位置或职责变化；首版不支持外场与门将互相转职。

- 这是成长成本模型，不是球员表现排名；不同成本集合的 CA 尤其不能直接比较场上强弱。
- 配置必须满足 `CA(初始属性) ≤ PA ≤ CA(各项天花板)`，否则会承诺一个属性上限根本无法容纳的潜力。
- 一次训练同时提升多项时，先逐项截断超出单项天花板的增量，再计算完整增量的预算。若仍超过 PA，按同一比例缩小这些剩余增量；预览使用同一规则。某项已满不会把其他属性的成长一起锁死。
- 预算结算使用未取整的内部数值；显示取整不能用来反复训练突破上限。
- 任何永久、无条件的属性增益都计入预算，不能用技能绕开 PA。条件型比赛技能使用独立技能预算，不改永久属性。
- 接近 PA 不再强推无效训练；界面提示可练位置、调整技能，或重养重新分配。换位置本身不返还 CA，也不自动改属性。

例如，在同样的成本权重下，射术从 90 升到 91 的预算增量，与从 50 升到 51 的比值为 `181/101≈1.79`。顶尖单项更贵，玩家必须在极致专长和补齐短板之间选择。

### 2.5 潜力、事件与反复培养如何共存

- 18 次行动是一条压缩培养路线，不是“六周必定兑现一生潜力”；本轮能练多少，还受初始能力、行动预算和训练效率限制。
- 高 PA 球员可能因为成长慢或路线不合适，本轮弱于低 PA、已成型的即战力球员。不能把 PA 当作出场排序。
- 事件可给予成长、改善训练效率、增加位置学习进度或解锁技能；首版不永久提高 PA，不靠反复抽事件无限突破原型。
- 职业素养影响训练稳定性，进取心影响主动加练路线，适应力影响新位置学习。这三项属于成长性格，不直接乘到进球率上；事件对它们的修改只属于本次培养成品。
- 正式赛不提供无限叠属性的出口；首版永久成长只发生于本轮训练及有次数限制的测验。
- 首版显示明确的 PA 与成长空间，方便验证玩法。后续若加入球探，只改变玩家对潜力的估计精度，不改变真实 PA。

### 2.6 经典经理功能的取舍

| 机制 | 融合方式 | 首版范围 |
| --- | --- | --- |
| 当前能力/潜力 | 决定已用预算和培养上限 | 做 |
| 多维属性 | 分别控制发现机会、选择、移动与执行 | 做，详见第 4、7 节 |
| 位置熟练度 | 决定比赛属性发挥率，设保底且可专练 | 做，详见第 4.4 节 |
| 位置职责 | 中场可组织、扫荡或前插，不同任务不同需求 | 做，不另加隐藏战力倍率 |
| 惯用脚/逆足 | 特定传球、射门角度下的执行修正 | 做，不作用于无关动作 |
| 球员习惯 | 喜欢直塞、内切、前插等选择偏好 | 复用专属特性/技能槽，限制同类叠加 |
| 职业素养等性格 | 改变培养效率和路线 | 做少量有实际用途的维度 |
| 默契/战术熟悉度 | 影响换位、接应与新打法的理解 | 后续做；首版不暗加团队加成 |
| 年龄曲线、衰退、伤病 | 长期职业生涯压力 | 后续做，不混入本轮可重养机制 |
| 球探、转会、合同 | 引入信息不对称与经营 | 后续做，不阻塞比赛与培养原型 |

## 3. 事件系统：随机故事，但玩家能经营方向

### 3.1 事件分层

| 事件类别 | 作用 | 示例 |
| --- | --- | --- |
| 主线事件 | 保证培养节奏 | 入队测试、阶段考核、毕业赛 |
| 训练事件 | 根据近期训练形成分支 | 连续练传球后遇到组织型导师 |
| 性格事件 | 形成球员风格 | 射门欲望、团队意识、逆境心态 |
| 队友事件 | 引出配合技能 | 与边锋练习撞墙配合 |
| 压力事件 | 在收益与恢复间取舍 | 赛前加练还是主动休息 |
| 连锁事件 | 让前期选择影响后期 | 失误 → 复盘 → 改变习惯 → 技能领悟 |

首版建议 **30 个事件，其中 3 条各含 3 段的事件链**；内容采用配置驱动，验证有效后再扩充，而不是先写几百段重复对话。

### 3.2 触发规则

先判断事件是否有资格出现，再做加权选择：

```text
候选事件 = 满足周次、属性、训练历史、前置事件、冷却条件的事件
事件权重 = 基础权重 × 最近训练相关度 × 路线选择倾向
```

“无事件”也是一个候选，防止每次训练都被打断。主线节点优先处理，每次行动最多一个主事件；已完成的一次性事件不重复出现。

事件数据至少包含：

```text
id、类别、触发条件、前置/互斥事件、基础权重、冷却、最多出现次数
选项、确定收益、随机分支及其概率、结果效果、后续事件、解释文本
```

规则要求：

- 不把重要毕业资格完全放在低概率随机事件上。
- 若玩家主动走某条路线，关键入口最迟在指定周次出现；这是公开的路线保障，不是暗中操纵比赛。
- 随机收益先展示概率；抽取结果立即保存，退出重进不重新抽取。
- 与事件效果有关的属性阈值，在选项中用文字或数值说明。
- 多阶段事件只写入一次奖励，读档不能重复领取。

### 3.3 一条完整事件链示例：从冒险传球到组织核心

**第一段：被断掉的直塞**

条件：第二周后，练过传球，尚未选择该路线。

- 选 A：“先练稳”——确定获得传球成长和 1 点路线熟练度，进入安全组织路线。
- 选 B：“复盘线路”——获得视野成长和 1 点路线熟练度，进入穿透传球路线。
- 选 C：“今天先休息”——降低疲劳，不锁定路线。

**第二段：导师的半场练习**

条件：选过 A 或 B，之后完成一次传球训练。

- A 路线进行稳健配合训练，可选基础练习或压力挑战。
- B 路线进行线路观察训练，可选基础练习或高难直塞挑战。
- 两条路线都确定获得 1 点路线熟练度；挑战成功才增加额外成长，失败不扣除基础熟练度。挑战概率取决于传球与视野。

**第三段：毕业赛前的选择**

熟练度达到 2 后，所选路线解锁对应技能，学习占用相同技能预算：

- A 路线“稳健分球”：改善安全短传，较少冒险。
- B 路线“穿线者”：改善直塞，但只有前方存在接应线路时才有价值。

两条路线都能通过完成指定训练解锁技能，关键后续事件按路线保障出现；随机挑战只影响额外成长，不决定能否毕业。

## 4. 属性与技能

### 4.1 多维属性：18 项外场能力，4 项门将能力

统一为 1～100，数值是本作能力尺度。替换 v0.1 中过宽的“意识、防守、身体”等合并属性，不是把两套属性重复相加。

| 类别 | 属性 | 进入比赛的具体环节 |
| --- | --- | --- |
| 技术 | 传球 | 选定线路后能否把球传到位 |
| 技术 | 第一脚触球 | 接球后的控制质量与处理时间 |
| 技术 | 盘带 | 持球变向、摆脱和推进的执行 |
| 技术 | 射术 | 射门精度和终结质量 |
| 技术 | 抢断 | 已经进入对抗范围后能否干净夺球 |
| 技术 | 头球 | 高空球接触后的处理质量 |
| 精神 | 视野 | 能识别哪些接应线路与进攻机会 |
| 精神 | 决策 | 如何评估传、带、射的收益和风险 |
| 精神 | 无球跑位 | 进攻时选择接应点与前插时机 |
| 精神 | 防守站位 | 防守时保护什么区域、如何保持队形 |
| 精神 | 预判 | 判断落点、运动趋势和拦截时机 |
| 精神 | 镇定 | 受压、单刀等场景下的技术稳定性 |
| 精神 | 团队合作 | 按职责接应、补位和留后，而非只追球 |
| 身体 | 加速 | 短距离起步和追上第一步 |
| 身体 | 速度 | 持续冲刺的最高移动速度 |
| 身体 | 灵活 | 转身与变向，避免速度快却转不过身 |
| 身体 | 力量 | 护球、身体争抢和对抗中的稳定性 |
| 身体 | 耐力 | 体力容量和持续跑动的消耗耐受 |

门将额外有 **扑救反应、手控、出击、一对一**：分别处理扑救、抱球/脱手、离门争抢、单刀防守。门将仍使用传球、决策、防守站位等公共属性。

身高、惯用脚等单独保存为身体特征，不伪装成可无限训练的数值。首版 UI 可以折叠显示技术/精神/身体三组，并高亮当前职责最重要的四五项；分组雷达与总评分只用于展示，不直接结算比赛。

### 4.2 职责决定需求，不存在通用最优加点

| 职责 | 关键属性 | 典型任务 | 同位置的另一种用法 |
| --- | --- | --- | --- |
| 组织中场 | 传球、视野、决策、第一脚触球 | 接应、转换方向、创造线路 | 防守中场更重视站位、抢断和耐力 |
| 防守中场 | 防守站位、预判、抢断、团队合作 | 保护后场、截断反击 | 不必像组织者一样追求最高传球 |
| 突击边路 | 盘带、加速、灵活、无球跑位 | 拉开、突破、下底 | 边路接应者可以少突破、多传递 |
| 终结前锋 | 射术、无球跑位、镇定、加速 | 抢点、制造单刀、终结 | 支点前锋更重力量、触球和传球 |
| 拖后中卫 | 防守站位、预判、抢断、速度 | 守住身后、补位 | 出球中卫还需要传球与镇定 |
| 清道夫门将 | 出击、预判、速度、传球 | 处理身后球、参与出球 | 门线门将更重扑救反应和手控 |

“位置”说明主要在哪活动，“职责”说明在那儿主要做什么。同是 CM，可以是组织者，也可以是扫荡者。

职责匹配度只从现有属性导出，供组队推荐；不再作为一个倍率叠到动作评分上。技能和训练推荐按“指定场景下的边际收益／培养成本”排序，没有可靠动作频率时，不伪装成整场胜率提升。

### 4.3 技能设计

首版每个成品保留一个原型专属特性，以及最多三个学习技能。学习技能共享固定预算；不靠技能数量无限叠强度。

| 技能 | 条件 | 效果方向 | 代价或边界 |
| --- | --- | --- | --- |
| 穿线者 | 前方存在有效接应跑位 | 改善直塞线路质量 | 无接应时不起作用 |
| 一脚出球 | 低压接球且有合法传球目标 | 缩短处理时间 | 不额外增加一次射门机会 |
| 禁区猎手 | 接到禁区内传球后射门 | 改善近距离终结 | 不强化远射 |
| 逆足训练 | 用非惯用脚处理球 | 减少逆足惩罚 | 是减少惩罚，不是全场加伤害 |
| 扫荡者 | 成为实际拦截参与者 | 改善抢断/拦截 | 消耗更多体力 |
| 出击门将 | 对方身后球进入可争夺区域 | 更积极争抢单刀球 | 可能失去门前位置 |

技能应尽量改变一种明确机制，不同时加十项属性。区分数值加成、动作解锁、AI 倾向和配合效果。

所有效果必须定义触发条件、目标、持续时间、叠加上限和冲突组。首版统一按“永久属性 → 当前体力修正 → 临时属性效果 → 位置发挥系数 → 动作评分 → 动作专属效果 → 概率”结算，同一效果只应用一次。

### 4.4 位置熟练度：能站这个位置，不等于擅长这个位置

每名球员保存位置熟练度表，而不是只能绑定一个位置。七人制首版使用：

- `GK` 门将、`CB` 中卫、`W` 边路、`CM` 中场、`ST` 前锋。
- `W` 是本作对边路位置的简化，具体纵深由阵型和职责决定，不声称等同于现实中的所有边后卫/边锋角色。
- 左右侧差异由惯用脚、站位和任务处理，不先把位置表拆成几十项。

示例：一名球员可为 `CM=90、W=50、CB=20、ST=30`。他可以踢多个位置，但在中场更熟悉接应和补位；高传球并不自动使他成为合格中卫。

UI 可显示擅长位置 85～100、熟练 65～84、可客串 40～64、生疏 1～39；尚未学会或职业类别不支持的位置为 0。未学会的外场位置可通过专项训练解锁，但外场与门将的类别限制不靠熟练度突破。档位只做提示，实际折扣连续计算；只有 100 熟练度完全发挥，85～99 仍有轻微折损。

**按用户要求改为：非擅长位置降低比赛有效属性，不只是影响站位。** 用带保底的线性公式，避免低熟练度球员变成零能力，也避免低于某个门槛时训练完全没有收益：

```text
r = 位置熟练度 / 100              # 有效输入必须在 0～100
L = 0.60                         # 位置发挥保底，原型待测参数
位置发挥系数 m = L + (1-L)×r
无疲劳、无临时效果时：场上属性 = 永久属性 × m
```

| 位置熟练度 | 属性发挥率 | 原属性 80 的场上值（无其他修正） |
| --- | ---: | ---: |
| 20 | 68% | 54.4 |
| 50 | 80% | 64 |
| 80 | 92% | 73.6 |
| 100 | 100% | 80 |

这里的 60% 是本方案的平衡起点，不是已验证的原游戏折扣。0 熟练度的理论系数为 60%，但本作仍禁止未解锁或不支持的位置上场；保底不能绕开阵容合法性。

- 比赛用到的技术、精神、身体及门将能力都读取位置折算后的有效值；不修改培养面板、CA 或 PA。耐力涉及体力状态的处理见第 7.1 节。
- 原先独立的“位置理解误差”机制取消。站位能力随属性折损自然下降，不再另外扣一遍站位或命中率。
- 熟练度按教练分配的阵容位置读取，不按当前球场坐标判断。前锋回撤接球不等于改踢中卫，职责切换也不自动更换位置。
- 正式换位从下一个动作开始按新位置重新计算，始终从永久属性和当前状态推导，不能在上一步已打折的数值上再次连乘。
- 位置学习占用本轮 18 次行动中的专项或战术训练，可受适应力影响；不另外消耗 CA，但不能靠开场反复换位刷熟练度。
- 同一原型重养从初始熟练度重新分配学习时间，不跨轮累计到全位置精通。
- 提升熟练度可以恢复包括团队合作在内的属性发挥，但不提供超过 100% 的位置奖励；战术匹配度也不是另一份隐藏属性加成。
- 外场客串不同外场位置允许；首版门将与外场不能互相转职，阵容校验必须保留一名合法门将。

## 5. 七人制比赛规则与节奏

本作采用自定义七人制规则，不宣称完全模拟某个现实赛事。

- 每队 **1 名门将＋6 名外场球员**，初始提供完整可用阵容，玩家逐步用培养成品替换。
- 首版阵型：`1-2-3-1`、`1-3-2-1`、`1-2-2-2`，编号都包含门将。
- 比赛显示为上下半场各 45 分钟（完整 90 分钟），联赛现实推进约 10 分钟。旧的“上下半场各 10 分钟”口径由比赛机会与进球模型修改方案取代。
- 3 个替补席位、最多 3 次换人；替补能力与体力进入实际计算。
- 首版无越位，采用界外脚踢球；实现角球、球门球和简化任意球/点球。
- 犯规只在抢断等明确动作阶段判断，结果与夺球互斥；首版不做红黄牌系统。
- 联赛允许平局；淘汰赛平局直接点球决胜，不先做加时赛。

这些是简化玩法的明确规则，尤其无越位会影响站位与身后球价值，需要在战术测试中检查“永远站门前”等退化打法。

### 5.1 玩家如何指挥

赛前选择阵型，为每名球员分配职责，再设置进攻方式、节奏和压迫强度。球队可以突出两名核心，但其余球员也必须有明确的接应、防守或留后任务。

比赛默认自动运行。每场提供 3 次可选教练暂停：调整战术或换人；战术指令影响后续选择，不直接保证下一球成功。没有操作也能完整踢完。

实时操作不卖额外次数，不设计“付费把本次射门变进球”。

### 5.2 阵型是空间与人数分配，不是对抗倍率

| 阵型（含门将） | 外场位置安排 | 优点 | 需要承担的风险 |
| --- | --- | --- | --- |
| 1-2-3-1 | 2 CB＋1 CM＋2 W＋1 ST | 宽度好，接应点多 | 边路同时前插会让两名中卫暴露 |
| 1-3-2-1 | 3 CB＋2 CM＋1 ST | 后场覆盖较稳，适合防守转换 | 前锋可能孤立，进攻宽度不足 |
| 1-2-2-2 | 2 CB＋2 CM＋2 ST | 禁区内终结点多，可形成支点搭档 | 中场可能被压制，边路保护薄弱 |

阵型提供起始锚点、防守责任区和攻守转换时的回撤目标，不把球员钉死在格子里。持球侧边路前插时，另一侧和后场需要有人留守；谁来补位由职责与团队合作影响。

首版前腰型、后腰型球员主要通过 CM 的职责区分，都使用 CM 熟练度。后续如果要拆成独立位置，需同步增加对应阵型槽位，不先让玩家培养一个无处上场的位置。

**不设置“某阵型克制另一阵型，直接加 15% 胜率”。** 对位优势应来自实际形成的宽度、人数和线路；人员不合适的阵型不会自动获得说明中的优势。

### 5.3 战术通过可观察的机制进入每一步

首版开放少量离散设置，不先做几十个滑条：

| 设置 | 改变的机制 | 明确代价 |
| --- | --- | --- |
| 进攻方向：中路/边路/均衡 | 无球接应目标与对应动作偏好 | 过度集中会被针对 |
| 传递：短传/混合/直传 | 候选线路偏好与失误风险取舍 | 直传失败暴露转换，短传可能过慢 |
| 节奏：稳健/正常/快速 | 可用处理时长和向前行动偏好 | 快速处理缩短双方移动窗口，也提高执行难度 |
| 防线：低/中/高 | 防守锚点的纵向位置 | 高位压缩空间但容易被打身后 |
| 压迫：低/中/高 | 谁愿意离开责任区逼抢、跑动消耗 | 压迫者离开后出现空位 |

节奏只对第 6.1 节的准备/处理时间使用有界倍率，不缩短球的飞行等执行时间；“快速”减少调整时间时，也要对应压力修正，不凭空增加全队速度。“防线高”和“压迫高”是两个不同选择，不应绑成同一个属性增益。

战术优先级：规则合法性最高，其次是必须执行的职责约束，再由球队偏好和个人习惯参与候选评分。互相冲突的指令要在界面提示或拒绝，不能让两个隐藏加成互相覆盖。

例如明确要求留后的中卫不能因“喜欢前插”无视留后任务；普通进攻位置上的前插习惯可以改变候选偏好。个人习惯让同战术球队有个性，但不能突破职责的硬约束。

### 5.4 不同球员如何支撑不同战术

- **短传控球**：需要传球、第一脚触球、决策，以及愿意接应的无球跑位和团队合作。不是只凑七个传球最高的人。
- **快速反击**：需要抢断后的第一脚传递、前锋跑位与加速；只堆速度但不能及时看到或传出线路，反击依然失败。
- **高位压迫**：需要站位、团队合作、耐力与回追速度；体力下降后必须允许它变得不划算。
- **双前锋打法**：可以是支点＋跑位终结者，而不必是两个一样的射手。

示例：同一个中场，改踢熟练度 50 的 W 时，位置发挥率为 80%，永久传球 80 在无其他修正时按 64 参与比赛；换到熟练度 100 的 CM 则恢复为 80。布阵界面同时显示原属性、场上属性和折损原因，而不只展示全队总评分。

## 6. 回合结构：以球权阶段为外层，以动作步骤为内层

```text
开球/定位球 → 获得稳定球权 → 根据当前状态预测接应 → 持球人选择动作
→ 冻结动作时长 → 接应与防守调整 → 核验实际参与者 → 计算结果 → 更新场上状态
    ├─ 成功传球：换持球人，继续本次进攻
    ├─ 突破成功：推进位置，继续本次进攻
    ├─ 拦截/抢断成功：交换球权，进入反击
    ├─ 射门：封堵/偏出/扑救/进球
    └─ 出界/犯规：进入相应定位球流程
```

“回合”不是双方轮流各打一次，更不是一次动作必然射门。成功回传也可以保留球权；节奏和体力成本会限制无意义的循环。

### 6.1 位置表示与无球行为

采用二维球场位置与 **纵向 4 区 × 横向 3 路** 的战术分区。原型用球员圆点、箭头、球权提示即可，不依赖 3D 物理碰撞决定结果。

每步从同一份已提交状态出发，决策只根据当前位置与职责预测接应机会，不读取尚未生成的本步实际移动结果。选定动作后，再冻结时长并计算实际移动；目标最终没跑到位，会降低传球质量或导致失败，不能回头替持球人重新选一次最优动作。

时长拆成准备/处理与执行两部分：原型可设短传 `2+2` 秒、长传/直塞 `2+4` 秒、盘带 `1+5` 秒、射门 `1+2` 秒；定位球准备 8 秒是独立死球步骤。执行部分是第一版对动作及球飞行时间的简化，不由动画速度或战术节奏压缩。

```text
接球调整时间 = 刚接到球时的 0.5×(1-第一脚触球/100) 秒，否则为 0
处理时间 = max(0.25秒, (基础处理时间+接球调整时间)×节奏倍率-时长技能减免)
本步时间 = 处理时间 + 执行时间
```

节奏倍率首轮可试稳健 1.2、正常 1.0、快速 0.8。“一脚出球”仅在步骤开始状态符合低压、已选择合法传球等条件时减免 1 秒；条件与时长在移动前冻结。不能用移动后的压力回头改变本步时长，形成循环依赖。

双方根据步骤开始时可观察的状态确定无球移动意图，再计算冻结时长内能到达的位置：

- 队友：接应、前插、拉开、留后保护。
- 防守：逼近持球人、封传球线路、跟随危险接应点、回撤。
- 门将：站位调整、是否准备出击。

移动距离受速度、体力和该步骤时间限制，不允许瞬移。防守意图不读取进攻方尚未公开的目标或随机结果；实际能否参与拦截，在双方预定移动与传球线路确定后再检查。原型每步只更新一次移动，不做连续物理追踪。

到达半场或全场时间时，完成已经开始的动作后吹停，不再开启新的普通动作；应执行的点球按规则单独处理。

### 6.2 谁来防守，不能只按位置配对

- 持球防守者：从能在本步骤接近持球人的球员中选择。
- 传球拦截者：从靠近传球线且来得及参与的球员中选择。
- 射门封堵者：必须位于有效封堵通道内。
- 协防者离开原位置后，给其他攻击者留下空间。

首版每次对抗最多计入一名主防守者和一名协防者。协防按实际覆盖折算，采用递减贡献，不把多个人的防守直接相加，也不把所有人的“失败率”机械连乘。

## 7. 比赛计算模型

复杂度应来自 **空间、技能、状态和战术的相互作用**，而不是塞进无法解释的随机公式。

### 7.1 当前有效属性

令当前体力比例为 `f`，取值 0～1，位置发挥系数 `m` 按第 4.4 节计算：

```text
疲劳系数 = 1 - k×(1-f)
有效属性 = clamp((永久属性×疲劳系数 + 临时属性增益)×m, 1, 100)
```

原型中加速/速度/灵活/力量的 `k` 可先取 0.25，技术、精神及门将专属属性取 0.10；耐力取 `k=0`，避免疲劳降低耐力后又递归增加疲劳。这是待调参数，不是现实生理模型。

体力容量按赛前永久耐力固定，当前剩余体力按实际消耗保存；位置折算后的有效耐力影响动作消耗耐受，但换位不改变既有容量、不恢复或凭空扣除当前体力，防止反复换位刷新体力。

**60% 保底只针对位置折扣，不是所有负面状态后的绝对属性保底。** 疲劳或负面效果仍可使最终属性低于永久属性的 60%；它也不是传球/射门成功率至少 60%。

个人天花板约束永久成长，临时比赛效果只受本场有效值上限约束。CA、PA、角色匹配度都不进入本公式；可以被技能临时强化，但不能因此永久扩大培养预算。

每次动作与跑动扣除体力，低强度等待可少量恢复。全场高压必须付出持续消耗，不能成为没有代价的最优战术。

### 7.2 AI 先选择动作，再结算成败

合法候选为“动作＋目标”：短传给谁、直塞给谁、向哪突破、是否射门等。无合法目标的动作不能进入候选。直塞候选使用当前状态与职责推测的接应线路；选定动作后，再核验真实到达点与执行型技能条件，不能把预计跑位当成已经完成。

每个候选估计：

```text
Q = 成功概率估计 × 成功后局面价值
  + 失败概率估计 × 失败后局面价值
  - 时间与体力成本 + 战术偏好
```

局面价值可先用小型手工表近似：本方后场受压、前场稳定持球、禁区内空位等状态有不同价值。射门的进球回报按 1 球计，其余状态价值也使用同一尺度；不能把 80 点属性和 0.2 个预期进球直接相加。

第一版只评估一步，不搜索完整比赛，也不做机器学习。评分模型是决策近似，结算模型才决定实际结果。

视野先影响可识别的接应机会，决策再影响评估误差：可用 `Q_hat=Q+ε`，误差幅度随决策提高而缩小，和 Q 保持同一尺度。误差在本次决策中固定保存，不因 UI 刷新重抽；它不能读取未来随机结果。合法性检查始终独立，不能因为球员没看见出界就让非法动作成立。

为了既有变化又不瞎踢：

1. 过滤非法动作，再按球员自己的 `Q_hat` 过滤明显劣势动作，至少保留其估计最好的合法动作；不能用引擎评分暗中替低决策球员纠错。
2. 对剩余候选按 softmax 抽取：

```text
P(动作 a) = exp((Q_hat[a]-Q_hat_max)/T) / Σ exp((Q_hat[i]-Q_hat_max)/T)
```

`T` 控制合理候选间的多样性，与 Q 使用相同尺度。首版保持一个较小的固定 T，不再用低决策同时放大 T，避免同一短板被重复惩罚。高决策也不是“永远选最高分”。同一类型存在多个接球目标时，应检查候选数量是否让该类型获得不合理概率优势。

**选择高评分动作，不等于选择卡面最高的动作。** 一次低价值的安全横传，或一次高收益但风险大的直塞，都可能在不同比分和时间下合理。

### 7.3 一般对抗概率

对有攻防比较的动作使用平滑模型：

```text
sigmoid(z) = 1 / (1 + exp(-z))
logit(p)   = ln(p / (1-p))

P成功 = clamp(sigmoid(logit(p0) + (A-D+C)/s), p_min, p_max)
```

- `A`：本次动作攻击评分。
- `D`：有资格参与的防守评分。
- `C`：距离、角度、压力、惯用脚等环境修正。
- `p0`：在标准环境、攻防评分相等时，该动作的基准成功率。
- `s`：属性差影响概率的速度；首轮可用 18 作实验起点。

所有评分和修正必须使用一致尺度。`p0` 按动作区分：普通短传的基准可以高于直塞，不能让所有均势动作都只有 50% 成功率。

概率上下限仅适用于合法但存在不确定性的动作；球已经出界、没有射门条件等情况直接判定，不用保底概率创造不可能事件。

### 7.4 传球

短传的初始评分示例：

```text
A = 0.70×传球者传球 + 0.20×传球者镇定 + 0.10×接球者第一脚触球
D = 0.75×主拦截者抢断 + 0.25×主拦截者灵活 + 协防贡献
```

协防贡献根据距离和线路覆盖计算，原型上限可设 12 分；无人能参与拦截时，该项防守评分为 0，但距离、逆足和接球难度仍保留。

`C` 包含长距离惩罚、接球者空位奖励和持球压力惩罚。视野/决策已负责发现和选择线路，无球跑位/防守站位/预判已负责参与者的位置与时机，不再统一叠一个“意识加成”到 A、D 上。直塞更依赖前插机会，长传更重视距离和接球难度，不能只是换动画。

例如 `p0=0.80、A=78、D=70、C=-4、s=18`，成功率约为 **83.3%**。即使传球者更强，这次仍可能失败。

传球结算直接形成互斥结果：成功接应、被拦截、传偏/出界、形成争夺球。可以先算成功概率，再将剩余概率按线路压力分给失败类型；没有拦截者时，被拦截的概率必须为 0。

接球者第一脚触球已经进入本次结算时，不再无条件追加一次“停球失败”抽签。技能若另开停球事件，必须明确它替代还是扩展了哪个阶段。

### 7.5 盘带、抢断与犯规

```text
盘带 A = 0.45×盘带 + 0.30×灵活 + 0.25×力量
防守 D = 0.65×抢断 + 0.20×灵活 + 0.15×力量
```

抢断激进度可提高夺球倾向，但同时提高犯规风险、消耗和被过掉后的空档成本。动作结果为“保住球/突破、干净夺球、犯规、争夺球”中的一种，不能同时判定夺球成功和普通犯规后继续带走球。

加速与速度决定能走多远、能否参与追赶；灵活决定变向后的执行质量。不再把速度无条件算进所有成功率，避免“速度同时决定能到场、能赢对抗、还能射得准”。突破成功主要改变位置和防线状态，不直接加比分。

### 7.6 射门：明确每个阶段的意义

将射门分为三个条件阶段：

1. 是否被外场球员封堵：防守站位、预判及移动决定是否到达有效线路，再计算封堵机会。
2. 未被封堵时是否射正：可先用 `0.75×射术+0.25×镇定` 形成精度评分，再考虑距离、角度、逆足与压力。
3. 已射正时是否进球：比较终结质量与门将扑救反应，并考虑门将实际站位、视线；只有单刀场景才引入门将“一对一”能力。

无球跑位决定射手有没有好位置，不直接使同位置同压力的一脚射门更准。射术可以分别影响射正和射正后的质量，但这两个阶段必须独立校准，不能直接复制同一概率做两次抽签。

令 `b=P封堵`、`t=P射正|未封堵`、`g=P进球|已射正且未封堵`：

```text
P封堵 = b
P偏出 = (1-b)×(1-t)
P扑救 = (1-b)×t×(1-g)
P进球 = (1-b)×t×g
```

四者之和必须为 1。原型可以计算四类概率后只抽一次最终结果，减少实现歧义。

例：`b=0.15、t=0.65、g=0.32`，则本次进球概率是 **17.68%**，不是 32%。

扑救后，门将手控决定抱住还是脱手；封堵和脱手进入争夺球流程，不直接送回原射手脚下。进球只由唯一的进球事件增加一次比分。

这里的乘法是三个不同条件阶段的联合概率，和“对每个防守人反复抽一次能否进球”不是一回事。

### 7.7 争顶、二点球与定位球

争夺球参与者必须来得及到达落点：预判影响落点判断，加速/速度与起始距离决定能否到达。进入争夺后再用力量处理身体对抗，高空球使用头球处理触球质量；不把未到场者的高头球属性算进结果。门将禁区内可使用出击/手控。

参与者争夺为一次多项抽取，不让每个人独立判断“我抢到了”，避免同时出现两个持球者。无合格参与者时，球继续运动或出界，不凭空生成球权。

定位球复用传球、争顶和射门结算，另加合法站位与压力修正。点球另设无封堵的一对一射门场景，规则中禁止补射的点球大战不进入二点球流程。

### 7.8 一次进攻里，多维属性各自在哪里起作用

以 `1-2-3-1` 中的 CM 向 ST 直塞为例：

1. **阵型与战术**提供中场接应点、前锋活动区和向前传递偏好；职责指定谁留后。
2. 决策阶段根据前锋当前运动和职责形成**预计前插**，而不是提前读取本步实际移动。
3. **中场视野**决定是否识别这条预计线路；传球高但视野低的球员可能只看到横传。
4. **中场决策**判断直塞值不值得冒险；选定后冻结时长，再由前锋经过位置折算的**无球跑位、团队合作与加速/速度**决定实际到达点，不能保证与预测相同。
5. 同时，经过位置折算的**防守站位、预判等能力**决定能否补到真实线路上，随后才有资格参与拦截；熟练度不再独立叠一次误差。
6. **传球、镇定、接球者第一脚触球**与实际拦截者的执行能力决定这次传球结果。
7. 接到球形成单刀后，才进入**射术、镇定与门将能力**的射门结算。

因此，“传球 90、视野 45”的球员可以传得准却很少创造好机会；“传球 78、视野 85”的球员可能创造更多机会，但每次执行未必更稳。两人的价值取决于职责、队友和战术，不能由一个属性相加得出。

整条链中不读取 PA 或拿 CA 比大小。两名属性、位置熟练度、技能与状态完全相同，仅 PA 不同的球员，在固定随机输入下必须产生完全相同的比赛行为。

## 8. 随机性的边界与可复现性

### 8.1 三类随机必须分开

| 随机来源 | 解决的问题 | 不应该做的事 |
| --- | --- | --- |
| 事件随机 | 每轮培养有不同经历 | 连续不给玩家完成路线的机会 |
| 决策随机 | 合理候选间有变化 | 为了随机，让球员反复做明显愚蠢的事 |
| 结果随机 | 好机会也可能错失 | 根据付费、连胜或预期比分暗改结果 |

动画、解说的随机独立于以上逻辑。跳过动画或改变帧率不能改变球赛结果。

### 8.2 随机实现约定

采用经过测试的标准伪随机数生成器，例如固定实现版本的 PCG32，不自创“复杂随机算法”。培养事件、AI 选择、动作结果和纯表现分别使用派生随机流。

比赛复现输入包括：

```text
初始随机种子 + 球员/阵容快照 + 战术与指令序列
+ 引擎版本 + 规则/技能配置版本
```

相同输入在同版本引擎中必须得到相同逻辑事件序列；跨语言/跨平台实现还需约定数值精度与取整，不能仅凭同种子承诺一致。

- 每个动作记录事件编号、参与者、关键评分、最终概率、抽样值和结果。
- 正式比赛开始后固定种子和配置，读档不能刷新本次射门。
- 不按预定比分反推每次动作，不暗设“必须输掉这一场”。
- 如果以后做联网竞技，权威结算与未公开种子放服务端；首版不实现联网系统。

复杂公式不保证公平。公平来自清晰规则、合理概率、稳定复现及大量对照测试；单场冷门本身不是算法错误。

## 9. 战术如何影响球队，而不是单纯加属性

| 战术 | 主要改变 | 对方可以利用的代价 |
| --- | --- | --- |
| 控球组织 | 增加接应和安全传递，耐心寻找空位 | 进攻慢，落后时可能浪费时间 |
| 快速反击 | 夺球后增加前插和向前传递 | 失误后队形容易拉长 |
| 边路推进 | 边路站位、套边、传中更多 | 中路接应不足时传中收益低 |
| 高位压迫 | 更多球员提前参与逼抢 | 消耗大、身后空间暴露 |
| 低位防守 | 保持紧凑并保护危险区域 | 较难持续控制球权和前场空间 |

首版战术只改变候选动作偏好、无球站位和资源消耗，不叠加“全属性增加 20%”这类通用奖励。

## 10. 培养与比赛如何闭环

比赛结束不只给胜负，还回答三个问题：

1. **没有创造机会，还是创造了机会没把握住？** 分开显示推进、危险传球、射门质量和终结结果。
2. **技能没有用，还是没有满足条件？** 显示符合条件次数、生效次数及影响的动作。
3. **应该补属性还是换打法？** 显示代表性失败的原因，避免把一次低概率失误判成球员必需重养。

例：

> 本场前锋只有两次低质量远射。优先改善接应与传球线路，不应仅因没进球就建议堆射门。
>
> “穿线者”符合条件 0 次，主要因为没有前插接应。先调整队友职责，再考虑替换技能。

属性推荐采用固定场景、固定其他输入的对照，报告训练前后的动作评分或概率变化。综合推荐需要用明确的场景占比加权；若来自少量比赛，应显示样本不足。

培养页面同时展示“当前属性、PA 剩余空间、单项天花板、位置熟练度、学习成本”。复盘要区分没看见线路、判断错、没有跑到位和技术执行失败，不能把所有失误都归为“传球不够高”。

## 11. 技术边界与最小版本

### 11.1 只分三块

- **配置与培养**：球员原型、训练、事件、技能、培养存档。
- **无界面比赛结算器**：输入阵容和种子，输出有顺序的事件及结果。
- **表现与复盘**：消费比赛事件，播放二维表现、生成战报。

表现层不能自行决定进球或修改逻辑体力。培养替换操作要确认并安全保存；遇到未知技能配置应报错，而不是当作“无效果”继续比赛。

每个动作结算顺序固定：读取状态并预测接应 → 选择动作 → 根据起始状态应用时长型修正并冻结时间 → 计算双方实际移动 → 核验参与者与执行型技能条件 → 应用执行效果 → 抽取互斥结果 → 一次性提交位置、体力、时钟和其他状态 → 记录战报。两阶段效果分开记录，同一效果不重复应用；技能不默认递归触发自身，新增连锁必须定义次数限制。

### 11.2 MVP 范围

| 内容 | 首版范围 |
| --- | --- |
| 培养 | 18 次行动，30 个事件，3 条事件链 |
| 球员 | 12 个原创原型，包含至少 2 个门将；固定 PA、单项天花板与初始熟练度 |
| 属性 | 18 项外场能力＋4 项门将能力；每项必须有实际结算用途 |
| 阵容 | 7 名首发，3 个替补，3 种阵型；每人一个职责 |
| 战术 | 进攻方向、传递、节奏、防线、压迫；不实现隐藏的阵型胜率加成 |
| 技能 | 12 个机制明确的技能，含低成本基础技能 |
| 比赛 | 传球、盘带、抢断、射门、争夺球、必要定位球 |
| 玩法 | 4 支 AI 队伍，短赛季与单场挑战 |
| 表现 | 俯视二维球场、关键事件提示、加速/跳过 |
| 复盘 | 动作概率、技能生效、球员贡献和失败原因 |

暂不做转会市场、复杂财政、真实球星授权、联网天梯、3D 碰撞、完整裁判系统及付费抽取。真实联赛/球员名称如后续使用，需要单独确认授权。

### 11.3 开发顺序

1. **先做比赛原型**：固定球队，只跑传球、射门与球权转换，能在无界面模式下批量比赛。
2. **补齐足球特征**：跑位、拦截、协防、体力、门将、定位球，确保不退化成轮流掷骰射门。
3. **再接培养**：18 次行动、少量事件、培养结果进入阵容；先确认不同培养方向会产生不同打法。
4. **最后扩充技能与内容**：用复盘验证每个技能确实存在适用场景，再增加事件数量和美术表现。

不要先做大量养成剧情，最后才发现比赛引擎无法体现传球、视野、决策、跑位与速度的差别。

## 12. 验证标准：怎样证明它不是“看似复杂”

### 12.1 必须通过的逻辑检查

- 同种子、同版本、同阵容、同指令的事件日志一致。
- 每个互斥结果集合概率总和为 1，概率均在 0～1 内。
- 球只能由一个人控制，或处于明确的在途/争夺/死球状态。
- 时钟持续推进，进球只记一次，比赛必然结束；下半场终场规则固定，不留无限补赛循环。
- 同一防守人不能同一时刻在两个远离的位置参与对抗。
- 技能和事件不能重复领取奖励，候选培养结果不能覆盖未确认的旧成品。
- 在固定环境和技能状态下，提高射门精度不能反而降低射正率；其他属性做同类局部单调性检查。
- 永久成长不超过 PA 或单项天花板，重养/换位置/切职责不能重复领取预算；更改成本表必须升级规则版本。
- 仅改变 PA、但保持所有比赛输入相同，不得改变比赛行为；CA 也不能成为额外对抗加成。
- 位置系数随熟练度连续递增且位于保底值与 1 之间；折扣只应用一次，不另加位置误差。切换到不支持的位置应被阵容校验拒绝。
- 换回原位置，在其余状态相同时恢复对应的有效属性；永久属性、CA/PA、当前体力与体力容量不因换位被改写或刷新。
- 球员错误与原因使用同一套日志字段：未识别、误判断、位置/时机、技术执行，不能用随机结果倒写理由。

### 12.2 批量平衡验证

- 镜像阵容交换主客场测试；对称条件下，含平局折半后的胜率应在统计误差内接近 50%。
- 对照只改变一个属性、技能或战术的阵容，在相同的一组种子上反复比较，不能用一场比赛定强弱。
- 原型可以先每组跑 1,000 场查明显问题，关键调整再用 10,000 场；同时报告置信区间，而不是宣称某个样本量保证准确。
- 监测传球成功率、每场射门、进球、球权转换、体力和各技能触发次数。
- 初期节奏假设：两队合计 18～30 次射门、总进球均值约 2～6 球；是待验证目标，不是每场强制区间，0:0 或大比分都应允许。
- 检查是否存在无脑远射、无限安全倒脚、全员高压、堆单属性或站门前等统治性策略。

### 12.3 试玩验证

让玩家在不知道隐藏公式的情况下回答：为什么选这个训练、为什么这次传球危险、这名球员适合什么角色、重养准备改变什么。如果回答始终只有“总评分高就好”，说明属性、事件和战术还没有形成真正的选择。

## 13. 最终设计原则

**潜力限制成长总量，培养塑造属性分配；位置与职责安排工作，阵型与战术组织空间，属性和技能改变机会，随机决定这次能否兑现。**

本方案不承诺仅靠更复杂的公式就能制造真实足球。先用少量可解释规则做出好玩的七人制，再依据批量数据与试玩逐步增加复杂度。
